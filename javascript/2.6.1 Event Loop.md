## 🔁 Event Loop (JavaScript)

> ⚠️ This is a **🟡 Core + High-importance concept**
> 👉 Interviewers expect: **execution order, queues, tricky outputs, real-world behavior**

---

# 🔹 Definition

👉 The **Event Loop** is a mechanism that allows JavaScript (single-threaded) to handle **asynchronous operations** without blocking the main thread.

👉 It continuously checks:

- Is the **Call Stack empty?**
- If yes → pick tasks from queues and execute them

💡 In simple words:

```text
Event Loop = traffic controller between Call Stack & Task Queues
```

---

# 🔹 Core Explanation

---

## 🧠 1. Why Event Loop is needed?

👉 JavaScript is **single-threaded**

- Can execute only **one task at a time**
- Long-running tasks would block UI

👉 Event Loop solves this by:

- Offloading async tasks (timers, APIs)
- Executing them later when stack is free

---

## 🔁 2. Main Components

---

### 🟦 1. Call Stack

👉 Where JS executes functions (LIFO)

```js
function a() {
  b();
}
function b() {
  console.log("Hello");
}
a();
```

👉 Stack:

```
a → b → console.log → (pop out)
```

---

### 🟨 2. Web APIs / Browser APIs

👉 Provided by browser (not JS engine)

Examples:

- setTimeout
- DOM events
- fetch

👉 Async tasks go here first

---

### 🟥 3. Task Queues

👉 Two types:

#### 🔹 Microtask Queue (High Priority)

- Promises (`.then`, `.catch`)
- queueMicrotask

#### 🔹 Macrotask Queue (Low Priority)

- setTimeout
- setInterval
- DOM events

---

### 🔄 4. Event Loop Itself

👉 Continuously runs this cycle:

```text
1. Execute Call Stack (sync code)
2. Run ALL Microtasks
3. Run ONE Macrotask
4. Repeat
```

---

# 🔹 How It Works (Step-by-Step)

---

### 📌 Flow:

```text
Call Stack → Microtask Queue → Macrotask Queue
```

---

### 💡 Key Rule:

```text
Microtasks ALWAYS execute before Macrotasks
```

---

# 🔹 Example(s) with Code

---

## ✅ Example 1: Basic Event Loop

```js
console.log("Start");

setTimeout(() => console.log("Timeout"), 0);

Promise.resolve().then(() => console.log("Promise"));

console.log("End");
```

---

### 🔍 Execution Steps:

1. `Start` → sync
2. `End` → sync
3. Promise → microtask
4. setTimeout → macrotask

---

### ✅ Output:

```text
Start
End
Promise
Timeout
```

---

## ❗ Example 2: Nested Async (Tricky ⭐)

```js
console.log("Start");

setTimeout(() => {
  console.log("Timeout 1");

  Promise.resolve().then(() => console.log("Promise inside Timeout"));
}, 0);

Promise.resolve().then(() => console.log("Promise 1"));

console.log("End");
```

---

### 🔍 Execution:

1. Sync → Start, End
2. Microtask → Promise 1
3. Macrotask → Timeout 1
4. Microtask → Promise inside Timeout

---

### ✅ Output:

```text
Start
End
Promise 1
Timeout 1
Promise inside Timeout
```

---

## ❗ Example 3: Microtask Starvation

```js
function loop() {
  Promise.resolve().then(loop);
}

loop();

setTimeout(() => console.log("Timeout"), 0);
```

---

### 💥 Result:

👉 `setTimeout` may never execute

---

### 💡 WHY:

```text
Microtasks keep executing → Event Loop never reaches macrotask
```

# 🔹 Real-world Use Cases

---

### ⚡ 1. API Calls

```js
fetch("/api")
  .then((res) => res.json())
  .then((data) => render(data));
```

👉 Uses microtasks → smooth async flow

---

### ⚡ 2. UI Responsiveness

👉 Long tasks are broken using:

```js
setTimeout(() => heavyTask(), 0);
```

👉 Prevents UI freezing

---

### ⚡ 3. Event Handling

👉 Click → macrotask
👉 Follow-up logic → microtask

---

# 🔹 When to Use / When NOT

---

### ✅ Use Event Loop concepts when:

- Debugging async behavior
- Handling Promises
- Optimizing performance

---

### ❌ Avoid ignoring it when:

- Predicting output
- Writing async-heavy logic

# ⚠️ Common Mistakes / Traps

---

### ❌ Mistake 1: setTimeout runs immediately

👉 Reality:

```text
Runs AFTER microtasks
```

---

### ❌ Mistake 2: JS is multi-threaded

👉 Reality:

```text
JS is single-threaded, async handled via Event Loop
```

---

### ❌ Mistake 3: Promise behaves like setTimeout

👉 Reality:

```text
Promise = Microtask (higher priority)
```

# 🔹 Advantages / Pitfalls

---

### ✅ Advantages

---

### ❌ Pitfalls

- Hard to debug

# 🔹 Best Practices

---

✔ Prefer Promises over callbacks
✔ Avoid long synchronous tasks

```js
// BAD
while (true) {}
```

✔ Break heavy tasks:

```js
setTimeout(() => processChunk(), 0);
```

✔ Keep microtasks minimal

---

# 🔹 Senior-Level Insights 🚀

---

## ⚡ 1. Rendering Behavior

👉 Browser renders **between macrotasks**, NOT during microtasks

```text
Heavy microtasks = UI freeze
```

---

## ⚡ 2. Performance Optimization

👉 Use macrotasks to yield control:

```js
setTimeout(() => heavyWork(), 0);
```

👉 Prevents blocking rendering

---

## ⚡ 3. Frameworks (React, Angular)

👉 Internally use:

- batching
- scheduling
- microtask-like prioritization

---

## ⚡ 4. Debugging Strategy

👉 Always ask:

```text
Is it sync / microtask / macrotask?
```

Event Loop ensures non-blocking execution by processing synchronous code first, then microtasks, and finally macrotasks in a continuous cycle
