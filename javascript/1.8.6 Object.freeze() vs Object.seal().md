## 🧠 `Object.freeze()` vs `Object.seal()` (JavaScript)

---

## 🔹 Definition

Both methods are used to **control how an object can be modified**, but they provide different levels of restriction.

👉 In simple terms:

- `Object.seal()` → “Lock structure, allow value changes”
- `Object.freeze()` → “Lock everything (no changes at all)”

💡 They are used for **immutability and data safety**

---

## 🔹 Core Explanation

---

## 🟡 1. `Object.seal()`

```js
Object.seal(obj);
```

🧠 What it does:

- ❌ Cannot add new properties
- ❌ Cannot delete existing properties
- ✅ Can modify existing property values

---

### ✅ Example

```js
const user = { name: "Dilip" };

Object.seal(user);

user.name = "JS"; // ✅ allowed
user.age = 25; // ❌ not added
delete user.name; // ❌ not deleted
```

👉 Final:

```js
{
  name: "JS";
}
```

---

### 🔥 Internal Behavior

- Sets `configurable: false` for all properties
- Keeps `writable: true`

👉 So values can still change

---

## 🔵 2. `Object.freeze()`

```js
Object.freeze(obj);
```

🧠 What it does:

- ❌ Cannot add properties
- ❌ Cannot delete properties
- ❌ Cannot modify existing values

👉 Fully immutable (shallow)

---

### ✅ Example

```js
const user = { name: "Dilip" };

Object.freeze(user);

user.name = "JS"; // ❌ no change
user.age = 25; // ❌ not added
delete user.name; // ❌ not deleted
```

👉 Final:

```js
{
  name: "Dilip";
}
```

---

### 🔥 Internal Behavior

- `configurable: false`
- `writable: false`

👉 Completely locked

---

## 🔁 Key Differences

| Feature            | Object.seal | Object.freeze |
| ------------------ | ----------- | ------------- |
| Add properties     | ❌          | ❌            |
| Delete properties  | ❌          | ❌            |
| Modify values      | ✅          | ❌            |
| Immutability level | Partial     | Full          |
| Writable           | ✅          | ❌            |

---

## 🔹 Example(s) with Code

---

### ✅ Example 1: Seal Behavior

```js
const obj = { a: 1 };

Object.seal(obj);

obj.a = 2; // ✅
obj.b = 3; // ❌
delete obj.a; // ❌

console.log(obj); // { a: 2 }
```

---

### ✅ Example 2: Freeze Behavior

```js
const obj = { a: 1 };

Object.freeze(obj);

obj.a = 2; // ❌
obj.b = 3; // ❌

console.log(obj); // { a: 1 }
```

---

### ⚠️ Example 3: Nested Object (Important 🔥)

```js
const obj = {
  user: { name: "Dilip" },
};

Object.freeze(obj);

obj.user.name = "JS"; // ✅ changes!
```

👉 WHY:

- Freeze is **shallow**, not deep

---

### ⚛️ 2. React/Redux State

- Enforce immutability

---

### 🔐 3. Security

- Protect critical data

---

### 📦 4. Constants

```js
const CONFIG = Object.freeze({
```

---

## 🔹 When to Use / When NOT to Use

---

### ✅ Use `Object.seal`

- When structure must stay fixed
- But values can change

---

### ✅ Use `Object.freeze`

- When full immutability required
- Constants, configs

---

### ❌ Avoid

- Assuming deep immutability
- Overusing freeze in performance-critical code

---

## 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Thinking freeze is deep

👉 Nested objects still mutable

---

### ❌ Mistake 2: Silent failure

```js
obj.a = 2; // no error (non-strict mode)
```

👉 Changes just fail silently

---

### ❌ Mistake 3: Forgetting strict mode

👉 In strict mode:

```js
"use strict";
obj.a = 2; // ❌ throws error
```

---

### ❌ Mistake 4: Using seal instead of freeze

👉 Leads to unintended mutations

---

## 🔹 Interview Q&A

---

### ❓1. What is Object.seal?

Prevents adding/removing properties but allows modification.

---

### ❓2. What is Object.freeze?

Makes object completely immutable (shallow).

---

### ❓3. Difference between seal and freeze?

- seal → allows modification
- freeze → no modification

---

### ❓4. Does freeze work deeply?

❌ No, shallow only

---

### ❓5. How to check if object is frozen?

```js
Object.isFrozen(obj);
```

---

### ❓6. How to check if sealed?

```js
Object.isSealed(obj);
```

---

### ❓7. Can sealed object properties be changed?

✅ Yes

---

### ❓8. What is writable vs configurable?

- writable → value change
- configurable → delete/modify descriptor

---

## 🔹 Advantages / Pitfalls

---

### ✅ Advantages

- Prevent accidental mutations
- Improve code reliability
- Useful for constants

---

### ❌ Pitfalls

- Shallow behavior
- Silent failures
- Performance overhead (minor)

---

## 🔹 Best Practices

---

✔ Use `freeze` for constants
✔ Use `seal` for controlled objects
✔ Use deep freeze if needed
✔ Use strict mode for safety
✔ Avoid mutating shared objects

---

## 🔹 Senior-Level Insights 🚀

---

### ⚡ Deep Freeze Utility

```js
function deepFreeze(obj) {
  Object.keys(obj).forEach((key) => {
    if (typeof obj[key] === "object") {
      deepFreeze(obj[key]);
    }
  });
  return Object.freeze(obj);
}
```

👉 Ensures full immutability

---

### 🧠 Performance Consideration

- Freeze prevents engine optimizations in some cases
- Use only where needed

---

### 🔄 Immutability in Frameworks

- Redux enforces immutability
- Helps detect state changes

---

### ⚖️ Trade-offs

| Method | Pros     | Cons           |
| ------ | -------- | -------------- |
| seal   | Flexible | Not fully safe |
| freeze | Safe     | Less flexible  |

## ✅ Final Takeaway

👉 `Object.seal` = **structure locked, values changeable**
👉 `Object.freeze` = **fully locked (immutable)**

💡 Interview expectations:

- Know shallow vs deep
- Understand writable/configurable
- Choose correct method based on use case
