## ⚡ Caching (JavaScript / Frontend)

> ⚠️ This is a **🔴 Advanced / Performance topic**
> 👉 Interviewers expect: **performance optimization + strategies + real-world trade-offs**

---

# 🔹 Definition

👉 **Caching is storing data temporarily so it can be reused instead of recomputing or refetching**

- Reduces **network calls, computation time, and latency**
- Improves **performance and user experience**
- Used across **browser, API, memory, and application layers**

---

# 🔹 Core Explanation

---

## 🧠 1. Why Caching is Important

👉 Without caching:

```text
Every request → fetch from server → slow
```

👉 With caching:

```text
First request → fetch → store → reuse
```

💡 Result:

- Faster response
- Reduced server load
- Better scalability

---

## 🧠 2. Types of Caching (Frontend Perspective)

---

### 🌐 1. Browser Cache (HTTP Cache)

👉 Controlled by headers:

```http
Cache-Control: max-age=3600
ETag / Last-Modified
```

👉 Browser stores:

- JS files
- CSS
- Images

💡 WHY:

- Avoid downloading same assets repeatedly

---

### 🧠 2. In-Memory Cache (JS level)

👉 Store data in variables / Map

```js
const cache = new Map();
```

💡 Fastest but:

- Lost on refresh

---

### 💾 3. Local Storage / Session Storage

👉 Persistent caching

```js
localStorage.setItem("data", JSON.stringify(data));
```

- Survives reload
- Slower than memory

---

### 📦 4. Service Worker Cache (Advanced ⭐)

👉 Acts as network proxy

- Cache API responses
- Enable offline support

---

### 📡 5. API / Server Cache

👉 Backend caching (Redis, CDN)

- Reduce DB calls
- Faster API response

---

## 🔹 Example(s) with Code

---

### ✅ Example 1: Simple In-Memory Cache

```js
const cache = new Map();

function fetchData(id) {
  if (cache.has(id)) {
    console.log("From cache");
    return Promise.resolve(cache.get(id));
  }

  console.log("Fetching...");
  return fetch(`/api/${id}`)
    .then((res) => res.json())
    .then((data) => {
      cache.set(id, data);
      return data;
    });
}
```

### 🧠 WHY:

- First call → API
- Next calls → cache

---

### ✅ Example 2: Memoization (Important ⭐)

```js
function memoize(fn) {
  const cache = {};

  return function (arg) {
    if (cache[arg]) return cache[arg];

    const result = fn(arg);
    cache[arg] = result;
    return result;
  };
}

const square = memoize((x) => x * x);

square(5); // compute
square(5); // cached
```

👉 Used for **expensive computations**

---

### ✅ Example 3: Fetch with Cache Strategy

```js
async function getUser(id) {
  const cached = localStorage.getItem(id);

  if (cached) {
    return JSON.parse(cached);
  }

  const res = await fetch(`/user/${id}`);
  const data = await res.json();

  localStorage.setItem(id, JSON.stringify(data));
  return data;
}
```

## 🔹 Caching Strategies (VERY IMPORTANT ⭐)

---

### 🧠 1. Cache First

```text
Check cache → if not → fetch
```

✔ Fastest
❌ May serve stale data

---

### 🌐 2. Network First

```text
Fetch → fallback to cache
```

✔ Fresh data
❌ Slower

---

### 🔄 3. Stale While Revalidate

```text
Return cache → update in background
```

✔ Best UX
✔ Common in modern apps

---

### 🚫 4. No Cache

```text
Always fetch fresh data
```

✔ Real-time apps

---

## 🔹 When to Use / When NOT to Use

---

### ✅ Use Caching

- Repeated API calls
- Static assets
- Expensive computations

---

### ❌ Avoid

- Sensitive data (security risk)
- Real-time data (stock prices, chat)
- Frequently changing data

---

## ⚠️ Common Mistakes / Traps

---

### ❌ Mistake 1: Serving stale data

👉 Cache without invalidation = outdated UI

---

### ❌ Mistake 2: Over-caching everything

👉 Memory waste + incorrect data

---

### ❌ Mistake 3: Ignoring cache invalidation

👉 Hardest problem in CS 😄

---

### ❌ Mistake 4: Not handling errors

👉 Cache fallback not implemented

## 🔹 Best Practices

---

✔ Use proper cache strategy (not random)
✔ Always handle cache invalidation
✔ Avoid caching sensitive data
✔ Use TTL (time-to-live)

```js
setTimeout(() => cache.delete(key), 60000);
```

✔ Combine with backend caching

### ⚡ Cache Invalidation (Critical)

👉 Two common approaches:

✔ Simple
❌ May be stale

```text

```

✔ Accurate
❌ Complex
