## 👉 Pipe & Compose Functions (JavaScript)

---

## 🔹 Definition

👉 **Pipe** and **Compose** are techniques used to **combine multiple functions into a single function**.

- **Pipe** → executes functions **left → right**
- **Compose** → executes functions **right → left**

📌 Simple:

> They help you build a **function pipeline** where output of one becomes input of next.

---

## 🔹 Core Explanation

### 🔗 1. Function Composition Concept

- Instead of nesting functions like `f(g(h(x)))`, we can make it cleaner using compose/pipe.
- Each function works on a **single responsibility**, improving readability and reuse.

💡 WHY:

- Encourages **modular + declarative code**

---

### 🔄 2. Compose (Right → Left Execution)

```js id="d6v1sq"
const compose = (f, g) => (x) => f(g(x));
```

👉 Execution:

```js id="u5a1tv"
compose(f, g)(x) = f(g(x))
```

💡 Flow:

- First `g(x)` runs
- Then `f(result)` runs

---

### 🔁 3. Pipe (Left → Right Execution)

```js id="c3r8yr"
const pipe = (f, g) => (x) => g(f(x));
```

👉 Execution:

```js id="2wq6v2"
pipe(f, g)(x) = g(f(x))
```

💡 Flow:

- First `f(x)`
- Then `g(result)`

---

### 🧠 4. Why Both Exist?

- **Compose** is mathematically traditional
- **Pipe** is more readable (matches natural reading order)

💡 In real-world JS → **pipe is more popular**

---

## 🔹 Example(s) with Code

### ✅ Example 1: Basic Compose

```js id="a9bzr7"
const add = (x) => x + 2;
const multiply = (x) => x * 3;

const composed = compose(multiply, add);

console.log(composed(5)); // (5+2)*3 = 21
```

🧩 Execution:

- `add(5)` → 7
- `multiply(7)` → 21

---

### ✅ Example 2: Pipe (More Readable)

```js id="6y1rbb"
const piped = pipe(add, multiply);

console.log(piped(5)); // (5+2)*3 = 21
```

🧩 Same result, but:

- Reads like: “first add, then multiply”

---

### ⚠️ Example 3: Multiple Functions

```js id="5r1f5v"
const pipe =
  (...fns) =>
  (x) =>
    fns.reduce((value, fn) => fn(value), x);

const result = pipe(
  (x) => x + 1,
  (x) => x * 2,
  (x) => x - 3,
)(5);

console.log(result); // ((5+1)*2)-3 = 9
```

💡 WHY:

- `reduce` applies functions sequentially
- Very scalable pattern

## 🔹 Real-world Use Cases

### ⚛️ 1. Data Transformation (Frontend APIs)

```js id="p7j0dr"
const processData = pipe(
  (data) => data.filter((u) => u.active),
  (data) => data.map((u) => u.name),
  (data) => data.sort(),
);
```

💡 Clean pipeline instead of nested logic

---

### 🔄 2. Form Validation

- Chain validation steps:

```js id="gnj5h7"
pipe(validateEmail, sanitizeInput, normalizeData);
```

---

### 🧩 3. Redux / Middleware

- Functions executed in sequence (middleware chain)

---

### ⚙️ 4. Functional Libraries

- Libraries like Lodash FP / Ramda use pipe/compose heavily

---

## 🔹 When to Use / When NOT to Use

### ✅ Use When:

- You have **multiple small transformations**
- Want **clean, readable pipelines**
- Following functional programming style

---

### ❌ Avoid When:

- Logic is simple (overkill)
- Too many chained functions reduce readability
- Debugging becomes difficult

---

## 🔹 Common Mistakes / Traps

### ❌ Mistake 1: Confusing order

```js id="8k1kt7"
compose(f, g) !== pipe(f, g);
```

👉 Order matters a lot

---

### ❌ Mistake 2: Functions with multiple arguments

```js id="9n7n9u"
pipe(add, multiply); // ❌ if add needs 2 args
```

👉 Pipe/compose works best with **unary functions (one argument)**

💡 Solution:

- Use currying

---

### ❌ Mistake 3: Debugging difficulty

- Hard to know which function failed in long chains

💡 Tip:

- Break pipeline into smaller parts

## 🔹 Interview Q&A

### ❓1. What is function composition?

👉 Combining multiple functions where output of one becomes input of next.

---

### ❓2. Difference between pipe and compose?

👉 Pipe: left → right
Compose: right → left

---

### ❓3. Which is more readable?

👉 Pipe, because it follows natural execution order.

---

### ❓4. Why use pipe/compose?

👉 To avoid nested function calls and improve readability.

---

### ❓5. Can we use functions with multiple arguments?

👉 Not directly — better to use curried functions.

---

### ❓6. How are they implemented?

👉 Using `reduce` to apply functions sequentially.

---

### ❓7. Are these built-in in JavaScript?

👉 No, but easy to implement or available via libraries.

---

### ❓8. Real-world benefit?

👉 Cleaner pipelines for data transformation and middleware.

## 🔹 Advantages / Pitfalls

### ✅ Advantages

- Clean and readable code
- Encourages small reusable functions
- Reduces nested function calls
- Improves maintainability

---

### ⚠️ Pitfalls

- Harder debugging
- Requires understanding of FP concepts
- Overuse can make code abstract

---

## 🔹 Best Practices

✔ Use with **pure functions**
✔ Prefer unary functions (use currying if needed)
✔ Keep pipeline short and readable
✔ Name functions clearly
✔ Avoid deep chains

---

## 🔹 Senior-Level Insights

### ⚡ 1. Pipe + Currying = Powerful Combo

- Currying ensures all functions are unary
- Makes pipelines flexible and reusable

---

### ⚡ 2. Performance Consideration

- Each step creates function calls → slight overhead
- Usually negligible unless in tight loops

---

### ⚡ 3. Debug Strategy

- Insert logs in pipeline:

```js id="4hxydl"
const tap = (fn) => (x) => (fn(x), x);
```

💡 Helps inspect intermediate values

---

### ⚡ 4. Architecture Usage

- Used in:
  - Middleware chains
  - Data processing layers
  - Functional utilities
