## 🧠 Custom Array Polyfills (JavaScript)

---

## 🔹 Definition

A **polyfill** is a custom implementation of a method that **mimics native JavaScript behavior**, usually for older browsers or for understanding internals.

👉 So, **Custom Array Polyfills** means:

- Writing your own version of built-in array methods like `map`, `filter`, `reduce`, etc.
- Implemented using core JS (loops, conditions) instead of relying on built-in methods.

💡 In interviews, this tests:

- Your understanding of **JS internals**
- How methods behave under the hood

---

## 🔹 Core Explanation

### ⚙️ How Polyfills Work

- You extend `Array.prototype`
- Add your own function (e.g., `myMap`)
- Inside, manually loop through array and apply logic

```js
Array.prototype.myMethod = function (callback) {
  // 'this' refers to the array
};
```

👉 Important:

- `this` → current array
- Should behave like native method
- Must handle edge cases (optional but impressive in interviews)

---

### 🧩 Why Use Polyfills

- Understand how JS methods internally work
- Support older browsers (rare today but still relevant conceptually)
- Demonstrates strong JS fundamentals

---

## 🔹 Example(s) with Code

---

### ✅ 1. `map()` Polyfill

### 👉 Native Behavior:

- Returns new array
- Applies function to each element

### 🔧 Custom Implementation:

```js
Array.prototype.myMap = function (callback) {
  let result = [];

  for (let i = 0; i < this.length; i++) {
    result.push(callback(this[i], i, this));
  }

  return result;
};
```

### ▶ Example:

```js
const arr = [1, 2, 3];

const output = arr.myMap((num) => num * 2);

console.log(output); // [2, 4, 6]
```

### 🧠 Why it works:

- Loop runs for each element
- Calls callback manually
- Stores result in new array

---

### ✅ 2. `filter()` Polyfill

### 👉 Native Behavior:

- Returns elements that satisfy condition

```js
Array.prototype.myFilter = function (callback) {
  let result = [];

  for (let i = 0; i < this.length; i++) {
    if (callback(this[i], i, this)) {
      result.push(this[i]);
    }
  }

  return result;
};
```

### ▶ Example:

```js
const arr = [1, 2, 3, 4];

const output = arr.myFilter((num) => num % 2 === 0);

console.log(output); // [2, 4]
```

---

### ✅ 3. `reduce()` Polyfill (Important 🔥)

### 👉 Native Behavior:

- Reduces array to single value

```js
Array.prototype.myReduce = function (callback, initialValue) {
  let accumulator = initialValue;

  for (let i = 0; i < this.length; i++) {
    if (accumulator !== undefined) {
      accumulator = callback(accumulator, this[i], i, this);
    } else {
      accumulator = this[i];
    }
  }

  return accumulator;
};
```

### ▶ Example:

```js
const arr = [1, 2, 3];

const sum = arr.myReduce((acc, curr) => acc + curr, 0);

console.log(sum); // 6
```

### 🧠 Tricky Point:

- If no `initialValue`, first element becomes accumulator
- Many candidates miss this edge case ❌

## 🔹 When to Use / When NOT to Use

### ✅ Use

- Learning internals
- Interview preparation
- Custom utility libraries (rare cases)

### ❌ Avoid

- Replacing native methods in production unnecessarily
- Reinventing stable built-ins (bad for performance & readability)

## 🔹 Common Mistakes / Traps

### ❌ Mistake 1: Forgetting `this`

```js
// Wrong
function myMap(arr) {}
```

✅ Correct:

```js
Array.prototype.myMap = function () {};
```

👉 `this` refers to array → crucial

---

### ❌ Mistake 2: Not returning new array

```js
// Wrong
return undefined;
```

👉 Native `map` always returns new array

---

### ❌ Mistake 3: Ignoring edge cases in reduce

- Missing `initialValue`
- Empty array handling

---

### ❌ Mistake 4: Not passing correct arguments

```js
callback(value, index, array);
```

👉 Interviewers expect this exact signature

## 🔹 Interview Q&A

### ❓1. What is a polyfill?

A polyfill is a custom implementation of a method that replicates native behavior, mainly used for compatibility or understanding internals.

---

### ❓2. Why do we use `Array.prototype`?

To make the method available to all arrays and use it like native methods (`arr.myMap()`).

---

### ❓3. What does `this` refer to in polyfills?

`this` refers to the array on which the method is called.

---

### ❓4. Difference between map and forEach polyfill?

- `map` returns new array
- `forEach` does not return anything

---

### ❓5. What happens if array is empty in reduce?

- With initial value → returns initial value
- Without initial value → throws error (native behavior)

---

### ❓6. Can polyfills affect performance?

Yes, custom implementations may be slower than optimized native methods.

---

### ❓7. Can we overwrite native methods?

Yes, but it’s risky and not recommended in production.

---

### ❓8. Why is reduce considered tricky?

Because of accumulator logic + handling initial value + edge cases.

---

## 🔹 Advantages / Pitfalls

### ✅ Advantages

- Deep understanding of JS internals
- Improves problem-solving skills
- Helpful in interviews

### ❌ Pitfalls

- Easy to miss edge cases
- Native methods are more optimized
- Overuse leads to messy code

---

## 🔹 Best Practices

✔ Always match native method signature
✔ Handle edge cases (especially in `reduce`)
✔ Avoid overriding native methods in production
✔ Use meaningful naming (`myMap`, not `map`)
✔ Keep implementation clean and readable

---

## 🔹 Senior-Level Insights 🚀

### ⚡ Performance

- Native methods are optimized in JS engines (V8, etc.)
- Polyfills using loops are slower but acceptable for learning

---

### 🧠 Memory

- `map` & `filter` create new arrays → more memory usage
- `reduce` is memory efficient (single value)

---

### ⚖️ Trade-offs

| Method | Memory | Performance | Use Case              |
| ------ | ------ | ----------- | --------------------- |
| map    | High   | Good        | Transform arrays      |
| filter | Medium | Good        | Conditional selection |
| reduce | Low    | Best        | Aggregation           |
