# 🧠 Custom Array Polyfills in JavaScript

---

## 🔹 Definition

👉 **Simple Definition (2–3 lines):**
A polyfill is a custom implementation of a built-in method (like `map`, `filter`) for environments where it doesn’t exist.
Custom array polyfills mimic native array methods using JavaScript logic.

👉 **Deeper Explanation (2–3 lines):**
Polyfills are usually added to `Array.prototype` so all arrays can use them.
They replicate the **behavior, edge cases, and contract** of native methods as closely as possible.

---

# 🔹 Deep Explanation (Core Section)

---

## 1️⃣ Why Polyfills Exist

- Older browsers (IE, legacy environments) may not support modern methods like `map`, `reduce`.
- Polyfills ensure **backward compatibility**.

💡 Internally:

- JS engines expose methods via prototypes
- Polyfills attach missing methods to prototype

⚠️ Modern Reality:

- Today, polyfills are mostly used for **learning + interviews**, not production

---

## 2️⃣ Where Polyfills are Attached

```js
Array.prototype.myMap = function () {};
```

- This makes `myMap` available on all arrays
- Because arrays inherit from `Array.prototype`

💡 Internals:

- JS checks property on object → then prototype → then chain

⚠️ Edge Case:

- Modifying prototype affects ALL arrays → risky in production

---

## 3️⃣ Understanding Native Behavior (Most Important)

Before writing polyfill, you must know:

- Callback signature: `(element, index, array)`
- `thisArg` support
- Return value behavior
- Handling empty slots (sparse arrays)

💡 Example:

- `map` does NOT modify original array
- `forEach` returns `undefined`

---

## 4️⃣ Handling `this` and `thisArg`

```js
arr.map(callback, thisArg);
```

- Native methods allow binding `this` inside callback

💡 Internally:

- `callback.call(thisArg, element, index, array)`

⚠️ Edge Case:

- If `thisArg` not provided → `undefined` (strict mode)

---

## 5️⃣ Sparse Arrays (Tricky Interview Topic)

```js
const arr = [1, , 3];
```

- Native methods **skip empty slots**

💡 Why:

- JS distinguishes between:
  - `undefined` value
  - missing index

⚠️ Polyfill must check:

```js
if (i in this)
```

---

## 6️⃣ Error Handling (Spec Behavior)

- If callback is not a function → throw `TypeError`
- If `this` is null/undefined → throw error

💡 Important:

```js
if (this == null) throw new TypeError();
```

---

## 7️⃣ Immutability vs Mutation

| Method  | Behavior          |
| ------- | ----------------- |
| map     | returns new array |
| filter  | returns new array |
| forEach | no return         |

💡 Polyfill must match behavior exactly

# 🔹 Example(s) with Code

---

## ✅ Example 1: `map` Polyfill

```js
Array.prototype.myMap = function (callback, thisArg) {
  if (this == null) throw new TypeError("this is null or undefined");
  if (typeof callback !== "function")
    throw new TypeError("callback must be function");

  const result = [];

  for (let i = 0; i < this.length; i++) {
    if (i in this) {
      result[i] = callback.call(thisArg, this[i], i, this);
    }
  }

  return result;
};

// usage
const arr = [1, 2, 3];
const res = arr.myMap((x) => x * 2);
console.log(res);
```

### 🔍 Execution:

1. Checks if `this` exists
2. Creates empty result array
3. Iterates over array
4. Calls callback with proper context
5. Stores result

💡 Output:

```js
[2, 4, 6];
```

💡 WHY:

- Each element transformed → new array returned

---

## ⚡ Example 2: Sparse Array Handling

```js
const arr = [1, , 3];

Array.prototype.myMap = function (cb) {
  const res = [];
  for (let i = 0; i < this.length; i++) {
    if (i in this) {
      res[i] = cb(this[i]);
    }
  }
  return res;
};

console.log(arr.myMap((x) => x * 2));
```

### 🔍 Execution:

- Index 1 is missing → skipped

💡 Output:

```js
[2, empty, 6];
```

💡 WHY:

- `i in this` ensures only existing elements processed

---

## ⚡ Example 3: `reduce` Polyfill (Interview-Level)

```js
Array.prototype.myReduce = function (callback, initialValue) {
  if (typeof callback !== "function") throw new TypeError();

  let acc = initialValue;
  let startIndex = 0;

  if (acc === undefined) {
    acc = this[0];
    startIndex = 1;
  }

  for (let i = startIndex; i < this.length; i++) {
    if (i in this) {
      acc = callback(acc, this[i], i, this);
    }
  }

  return acc;
};

console.log([1, 2, 3].myReduce((a, b) => a + b, 0));
```

### 🔍 Execution:

1. Initial accumulator = 0
2. Iterates and accumulates
3. Returns final result

💡 Output:

```js
6;
```

💡 WHY:

- Callback combines values step by step

⚠️ Edge Case:

- Empty array + no initial value → should throw error (native behavior)

# 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Ignoring sparse arrays

- ❌ Looping without check
- ✅ Use `i in this`
- 💡 Native methods skip holes

---

### ❌ Mistake 2: Not handling `thisArg`

- ❌ Ignoring context
- ✅ Use `callback.call(thisArg, ...)`
- 💡 Important for correctness

---

### ❌ Mistake 3: Modifying original array

- ❌ Changing input
- ✅ Return new array (for map/filter)
- 💡 Matches native behavior

---

### ❌ Mistake 4: Not throwing errors

- ❌ Silent failure
- ✅ Throw TypeError
- 💡 Spec compliance

# 🔹 10+ Interview Q&A

---

### 1. What is polyfill?

A custom implementation of a method that replicates native behavior in unsupported environments.

---

### 2. Where are polyfills added?

Usually on prototype like `Array.prototype`.

---

### 3. Why check `this == null`?

To prevent errors when method called on null/undefined.

---

### 4. What is sparse array?

Array with missing indexes, not just undefined values.

---

### 5. Why use `i in this`?

To skip non-existing elements.

---

### 6. Difference between map and forEach?

Map returns new array; forEach returns undefined.

---

### 7. Why use `call`?

To bind `thisArg` correctly.

---

### 8. Can polyfills override native methods?

Yes, but it’s dangerous.

---

### 9. Are polyfills used in modern apps?

Rarely; mostly handled by tools like Babel.

---

### 10. What happens if callback is not function?

TypeError should be thrown.

---

### 11. Why reduce is tricky?

Because of initial value handling and empty array edge cases.

---

✔️ Use polyfills only when necessary
