## 👉 Currying (JavaScript)

---

## 🔹 Definition

👉 **Currying** is a technique where a function with multiple arguments is transformed into a sequence of **functions each taking one argument**.

📌 Simple:

> Instead of `f(a, b, c)` → we write `f(a)(b)(c)`

---

## 🔹 Core Explanation

### 🧠 1. Breaking Down Function Arguments

- Normally, a function takes multiple arguments at once.
- Currying converts it into **nested functions**, each receiving one argument.

```js
// Normal function
function add(a, b, c) {
  return a + b + c;
}

// Curried version
function add(a) {
  return function (b) {
    return function (c) {
      return a + b + c;
    };
  };
}
```

💡 WHY:

- Allows **partial execution** and better reusability.

---

### 🔗 2. How Currying Works Internally

- Each function **remembers previous arguments** using closures.
- When the final argument is provided, computation happens.

```js
add(1)(2)(3); // 6
```

🧩 Execution:

- `add(1)` → returns function waiting for `b`
- then `(2)` → returns function waiting for `c`
- then `(3)` → computes result

---

### 🔄 3. Partial Application (Closely Related)

- Currying allows you to **fix some arguments early**.

```js
const add = (a) => (b) => (c) => a + b + c;

const add5 = add(5);
const add5and2 = add5(2);

console.log(add5and2(3)); // 10
```

💡 WHY useful:

- Create reusable specialized functions (like config-based logic)

---

### ⚠️ 4. Currying vs Normal Functions

| Normal Function  | Curried Function |
| ---------------- | ---------------- |
| `sum(1,2,3)`     | `sum(1)(2)(3)`   |
| All args at once | One-by-one       |
| Less flexible    | More reusable    |

---

## 🔹 Example(s) with Code

### ✅ Example 1: Simple Currying

```js
const multiply = (a) => (b) => a * b;

const double = multiply(2);
console.log(double(5)); // 10
```

🧩 Explanation:

- `multiply(2)` → returns function `(b)`
- That function multiplies with stored `a = 2`
- Closure keeps `a` alive

---

### ⚠️ Example 2: Generic Currying Function (Advanced)

```js
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn(...args);
    } else {
      return function (...next) {
        return curried(...args, ...next);
      };
    }
  };
}

function sum(a, b, c) {
  return a + b + c;
}

const curriedSum = curry(sum);

console.log(curriedSum(1)(2)(3)); // 6
console.log(curriedSum(1, 2)(3)); // 6
```

🧩 WHY this is powerful:

- Works with **any number of arguments**
- Supports flexible calling (`(1)(2)(3)` or `(1,2)(3)`)

## 🔹 Real-world Use Cases

### ⚛️ 1. React Event Handlers

```js
const handleClick = (id) => () => {
  console.log(id);
};

<button onClick={handleClick(10)} />;
```

💡 Pre-configure values (like `id`) before event happens

---

### 🔄 2. Reusable Utility Functions

```js
const filterBy = (key) => (value) => (arr) =>
  arr.filter((item) => item[key] === value);
```

💡 Create dynamic filters

---

### 🧩 3. Logging / Configuration

```js
const logger = (level) => (message) => {
  console.log(`[${level}] ${message}`);
};

const errorLog = logger("ERROR");
errorLog("Something failed");
```

## 🔹 When to Use / When NOT to Use

### ✅ Use When:

- You need **reusable and configurable functions**
- Want **partial application**
- Working with functional programming patterns

---

### ❌ Avoid When:

- Code becomes too nested and hard to read
- Simple logic doesn’t need abstraction
- Team is unfamiliar with FP concepts

---

## 🔹 Common Mistakes / Traps

### ❌ Mistake 1: Confusing Currying with Partial Application

👉 Currying:

```js
f(a)(b);
```

👉 Partial:

```js
f(a, b);
```

💡 Currying always returns unary functions

---

### ❌ Mistake 2: Forgetting function returns

```js
const add = (a) => {
  (b) => a + b; // ❌ missing return
};
```

---

### ❌ Mistake 3: Overcomplicating simple logic

👉 Not every function needs to be curried
👉 Overuse reduces readability

## 🔹 Interview Q&A

### ❓1. What is currying?

👉 Transforming a function with multiple arguments into a chain of functions each taking one argument.

---

### ❓2. Why use currying?

👉 For reusability, partial application, and cleaner functional composition.

---

### ❓3. Difference between currying and partial application?

👉 Currying breaks function into single-argument functions, while partial application fixes some arguments.

---

### ❓4. How does currying work internally?

👉 Using closures to store previously passed arguments until all are received.

---

### ❓5. Is currying native in JavaScript?

👉 Not automatically, but can be implemented manually or using libraries.

---

### ❓6. What is `fn.length` in currying?

👉 It tells how many parameters a function expects — used to decide when to execute.

---

### ❓7. Can currying accept multiple arguments at once?

👉 Yes (in advanced curry implementations), e.g., `fn(1,2)(3)`

---

### ❓8. Real-world benefit?

👉 Helps create reusable, configurable, and composable functions.

---

## 🔹 Advantages / Pitfalls

### ✅ Advantages

- High reusability
- Cleaner composition
- Supports functional programming
- Enables partial application

---

### ⚠️ Pitfalls

- Can reduce readability if overused
- Debugging nested functions can be tricky
- Slight performance overhead (more function calls)

---

## 🔹 Best Practices

✔ Use arrow functions for cleaner currying
✔ Keep functions small and readable
✔ Use currying where reusability matters
✔ Avoid deep nesting

---

## 🔹 Senior-Level Insights

### ⚡ 1. Composition + Currying

- Currying works best with **function composition**
- Helps build pipelines like:

```js
compose(filterFn, mapFn, reduceFn);
```

---

### ⚡ 2. Performance Consideration

- Each curried call creates a **new function instance**
- Not ideal in tight loops or performance-critical paths

---

### ⚡ 3. Real Architecture Usage

- Used in:
  - Middleware (Redux, Express)
  - Functional libraries (Ramda, Lodash FP)
  - React patterns (handlers, hooks)
