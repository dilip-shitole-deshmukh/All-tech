## 🧠 Array Methods: `map`, `filter`, `reduce`, `forEach`

---

## 🔹 Definition

These are **higher-order array methods** used to iterate and transform data.

👉 In simple terms:

- `map` → transform each element
- `filter` → select elements
- `reduce` → combine into single value
- `forEach` → just loop (no return)

💡 They follow **functional programming style** (clean & declarative)

---

## 🔹 Core Explanation

---

## 🟢 1. `map()` → Transform Data

```js
array.map(callback);
```

🧠 How it works:

- Runs callback for each element
- Returns a **new array**
- Does NOT modify original

---

### ✅ Example

```js
const nums = [1, 2, 3];

const doubled = nums.map((n) => n * 2);

console.log(doubled); // [2, 4, 6]
```

👉 WHY:

- Each element transformed → new array created

---

### 💡 Key Point

✔ Always returns array of **same length**

---

## 🔵 2. `filter()` → Select Data

```js
array.filter(callback);
```

🧠 How it works:

- Returns elements where condition is `true`
- Skips others

---

### ✅ Example

```js
const nums = [1, 2, 3, 4];

const evens = nums.filter((n) => n % 2 === 0);

console.log(evens); // [2, 4]
```

👉 WHY:

- Only elements passing condition included

---

### 💡 Key Point

✔ Output array size may be smaller

---

## 🟡 3. `reduce()` → Accumulate Value 🔥

```js
array.reduce((acc, curr) => {}, initialValue);
```

🧠 How it works:

- Combines all elements into **single value**
- Uses accumulator (`acc`)

---

### ✅ Example

```js
const nums = [1, 2, 3, 4];

const sum = nums.reduce((acc, curr) => acc + curr, 0);

console.log(sum); // 10
```

👉 Flow:

```text
0 → 1 → 3 → 6 → 10
```

---

### 💡 Key Point

✔ Most powerful but hardest to master

---

## 🔴 4. `forEach()` → Iterate Only

```js
array.forEach(callback);
```

🧠 How it works:

- Executes function for each element
- Returns **undefined**

---

### ✅ Example

```js
const nums = [1, 2, 3];

nums.forEach((n) => console.log(n));
```

👉 Output:

```text
1
2
3
```

---

### 💡 Key Point

❌ Cannot break/return
❌ No new array

---

## 🔁 Comparison Table

| Method  | Returns      | Purpose    | Mutable |
| ------- | ------------ | ---------- | ------- |
| map     | New array    | Transform  | ❌      |
| filter  | New array    | Select     | ❌      |
| reduce  | Single value | Accumulate | ❌      |
| forEach | undefined    | Iterate    | ❌      |

---

## 🔹 Example(s) with Code

---

### ✅ Example 1: Chaining (Real-world 🔥)

```js
const users = [
  { name: "A", age: 20 },
  { name: "B", age: 30 },
];

const result = users.filter((u) => u.age > 25).map((u) => u.name);

console.log(result); // ["B"]
```

👉 WHY:

- filter → select
- map → transform

---

### ✅ Example 2: Reduce for Object

```js
const arr = ["a", "b", "a"];

const count = arr.reduce((acc, curr) => {
  acc[curr] = (acc[curr] || 0) + 1;
  return acc;
}, {});

console.log(count); // { a: 2, b: 1 }
```

---

### ⚠️ Example 3: Common Mistake

```js
const result = [1, 2, 3].forEach((n) => n * 2);

console.log(result); // undefined ❌
```

👉 forEach does NOT return

## 🔹 When to Use / When NOT to Use

---

### ✅ Use `map`

- Transforming UI data

---

### ✅ Use `filter`

- Conditions (search, active users)

---

### ✅ Use `reduce`

- Totals, grouping, flattening

---

### ✅ Use `forEach`

- Side effects (logging, DOM updates)

---

### ❌ Avoid

- Using `forEach` when you need return
- Using `map` without using result

---

## 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Using map without return

```js
arr.map((n) => {
  n * 2;
}); // undefined ❌
```

---

### ❌ Mistake 2: Using forEach for transformation

👉 Should use map

---

### ❌ Mistake 3: Missing initial value in reduce

```js
reduce((acc, curr) => acc + curr);
```

👉 Can cause bugs

---

### ❌ Mistake 4: Mutating original array

👉 These methods are non-mutating

---

## 🔹 Interview Q&A

---

### ❓1. Difference between map and forEach?

- map → returns array
- forEach → undefined

---

### ❓2. When to use reduce?

When converting array into single value

---

### ❓3. Does filter modify original array?

❌ No

---

### ❓4. Can we chain methods?

✅ Yes

---

### ❓5. Why reduce is powerful?

Can implement map/filter logic

---

### ❓6. Can we break forEach?

❌ No

---

### ❓7. What does map return?

New array

---

### ❓8. What happens if reduce has no initial value?

First element becomes accumulator

---

## 🔹 Advantages / Pitfalls

---

### ✅ Advantages

- Cleaner code
- Declarative style
- Less bugs

---

### ❌ Pitfalls

- Overuse of reduce → hard to read
- Missing return → bugs
- Performance in large loops

---

## 🔹 Best Practices

---

✔ Use map/filter for transformations
✔ Always return in map
✔ Prefer reduce for aggregation only
✔ Avoid side effects in map/filter
✔ Keep functions pure

---

## 🔹 Senior-Level Insights 🚀

---

### ⚡ Performance Insight

- Multiple chaining:

```js
arr.filter().map();
```

👉 Iterates multiple times

👉 Alternative:

```js
arr.reduce(...)
```

---

### 🧠 Functional Programming Style

```js
const result = arr
  .filter(...)
  .map(...)
  .reduce(...)
```

👉 Clean and readable

---

### 🔄 Immutability

- These methods don’t mutate original array
- Important for React/Redux

---

### ⚖️ Trade-offs

| Method  | Pros     | Cons            |
| ------- | -------- | --------------- |
| map     | Simple   | Extra array     |
| filter  | Clean    | Extra iteration |
| reduce  | Powerful | Complex         |
| forEach | Simple   | Limited         |

---

👉 `map` → transform
