## 👉 Memoization (JavaScript)

---

## 🔹 Definition

👉 **Memoization** is an optimization technique where we **cache (store) the result of expensive function calls** and reuse it when the same inputs occur again.

📌 Simple:

> “Don’t recompute — reuse previous results.”

---

## 🔹 Core Explanation

### 🧠 1. Why Memoization is Needed

- Some functions (especially recursive ones) **repeat the same calculations** multiple times.
- This leads to **exponential time complexity** in worst cases (e.g., Fibonacci).

💡 Memoization avoids recomputation → improves performance drastically.

---

### ⚙️ 2. How Memoization Works

1. Create a **cache (object/map)**
2. Before computing:
   - Check if result already exists in cache

3. If yes → return cached result
4. If no → compute → store → return

```js id="d6y9sx"
const cache = {};

function square(n) {
  if (cache[n]) return cache[n];

  console.log("Computing...");
  const result = n * n;
  cache[n] = result;

  return result;
}
```

---

### 🔁 3. Memoization + Recursion (Most Important Use)

```js id="y13d70"
const memo = {};

function fib(n) {
  if (n <= 1) return n;
  if (memo[n]) return memo[n];

  memo[n] = fib(n - 1) + fib(n - 2);
  return memo[n];
}
```

💡 WHY this matters:

- Without memoization → **O(2ⁿ)**
- With memoization → **O(n)**

---

### 🧩 4. Closure-Based Memoization (Cleaner Pattern)

```js id="6v9fyx"
function memoize(fn) {
  const cache = {};

  return function (...args) {
    const key = JSON.stringify(args);

    if (cache[key]) {
      return cache[key];
    }

    const result = fn(...args);
    cache[key] = result;

    return result;
  };
}
```

💡 Uses:

- Wrap any function → make it memoized
- Closure keeps cache private

## 🔹 Example(s) with Code

### ✅ Example 1: Without Memoization

```js id="nqlj7x"
function fib(n) {
  if (n <= 1) return n;
  return fib(n - 1) + fib(n - 2);
}

console.log(fib(40)); // very slow
```

👉 Recomputes same values many times

---

### ✅ Example 2: With Memoization

```js id="zz44xq"
const memo = {};

function fib(n) {
  if (n <= 1) return n;
  if (memo[n]) return memo[n];

  memo[n] = fib(n - 1) + fib(n - 2);
  return memo[n];
}

console.log(fib(40)); // fast
```

🧩 WHY faster:

- Each value computed **only once**

---

### ⚠️ Tricky Example: Object as Key

```js id="l2v1j4"
const memo = {};

function sum(obj) {
  const key = JSON.stringify(obj);

  if (memo[key]) return memo[key];

  const result = obj.a + obj.b;
  memo[key] = result;

  return result;
}
```

👉 Objects need serialization → otherwise cache fails

## 🔹 Real-world Use Cases

### ⚛️ 1. React Performance Optimization

- `useMemo` hook caches expensive calculations
- Prevents unnecessary re-computation on re-render

---

### 🔄 2. API/Data Processing

- Expensive transformations (filter/sort/group)
- Cache results to avoid recomputation

---

### 🎯 3. Search / Autocomplete

- Cache previous queries → faster UX

---

### 🧩 4. Dynamic Programming Problems

- Fibonacci, factorial, path problems
- Memoization = core optimization technique

---

## 🔹 When to Use / When NOT to Use

### ✅ Use Memoization When:

- Function is **expensive (CPU heavy)**
- Same inputs occur repeatedly
- Pure function (same input → same output)

---

### ❌ Avoid When:

- Function is cheap (no need to cache)
- Inputs are always different
- Memory is limited

---

## 🔹 Common Mistakes / Traps

### ❌ Mistake 1: Memoizing impure functions

```js id="z9o6xk"
function getTime() {
  return new Date();
}
```

👉 ❌ Cannot memoize → output changes every time

---

### ❌ Mistake 2: Using objects as keys directly

```js id="3rz0km"
cache[obj] = result; // ❌ key becomes "[object Object]"
```

👉 Use `JSON.stringify`

---

### ❌ Mistake 3: Memory leaks

- Cache grows indefinitely
- No cleanup strategy

---

### ❌ Mistake 4: Overusing memoization

- Adds complexity + memory usage
- Not needed for simple functions

## 🔹 Interview Q&A

### ❓1. What is memoization?

👉 Caching function results to avoid recomputation.

---

### ❓2. Difference between memoization and caching?

👉 Memoization is specific to **function calls**, caching is more general (API, DB, etc.).

---

### ❓3. Why is memoization used in recursion?

👉 To avoid repeated calculations and reduce time complexity.

---

### ❓4. Can we memoize all functions?

👉 No, only **pure functions** with predictable outputs.

---

### ❓5. What is time complexity improvement?

👉 Example: Fibonacci → O(2ⁿ) → O(n)

---

### ❓6. What is the drawback of memoization?

👉 Increased memory usage.

---

### ❓7. What is `useMemo` in React?

👉 A hook to memoize expensive computations between renders.

---

### ❓8. Difference between memoization and tabulation?

👉 Memoization = top-down (recursion),
Tabulation = bottom-up (iteration).

---

## 🔹 Advantages / Pitfalls

### ✅ Advantages

- Significant performance improvement
- Avoids redundant calculations
- Simple optimization technique

---

### ⚠️ Pitfalls

- Memory overhead
- Cache invalidation complexity
- Not useful for all problems

---

## 🔹 Best Practices

✔ Use only for expensive computations
✔ Ensure function is pure
✔ Use proper cache keys
✔ Consider cache size limits (LRU cache if needed)
✔ Use built-in tools (`useMemo`, libraries)

---

## 🔹 Senior-Level Insights

### ⚡ 1. Time vs Space Trade-off

- Memoization trades **memory for speed**
- Faster execution but higher memory usage

---

### ⚡ 2. Cache Invalidation Problem

- Hardest problem in caching
- Need strategies:
  - TTL (time-based expiry)
  - LRU (least recently used)

---

### ⚡ 3. React Optimization Strategy

- Overusing `useMemo` can hurt performance
- Only memoize when:
  - Expensive calculation
  - Re-render frequency is high

---
