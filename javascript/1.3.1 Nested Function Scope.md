## 👉 Nested Function Scope — Deep-Dive (Interview Ready)

This is a **🟡 Conceptual / Intermediate Topic** → expect **lexical scope + closure understanding + tricky cases**.

---

# 🔹 Definition

- **Nested Function Scope** means a function defined inside another function can **access variables of its parent (outer) function**.
- This happens due to JavaScript’s **lexical scoping**.

👉 Simple interview line:
**“Inner functions can access outer function variables, but outer functions cannot access inner variables.”**

---

# 🔹 Core Explanation

---

## 🔸 1. Inner Function Access (Scope Chain)

### ✅ Explanation

- When a variable is used inside a function, JS first looks in **its own scope**.
- If not found, it looks in the **outer (parent) scope**, then global scope.

👉 WHY:

- This lookup mechanism is called the **scope chain**.

---

## 🔸 2. One-Way Access Rule

### ✅ Explanation

- Inner → can access outer variables
- Outer → ❌ cannot access inner variables

👉 WHY:

- Scope flows **outward only**, not inward.

---

## 🔸 3. Lexical Scope (Important)

### ✅ Explanation

- Scope is decided by **where functions are written**, not where they are called.
- Inner function “remembers” its parent environment.

👉 This is the base of **closures**.

---

# 🔹 Example 1 (Basic Nested Scope)

### 💻 Code

```js id="6c5u6h"
function outer() {
  let a = 10;

  function inner() {
    console.log(a);
  }

  inner();
}

outer(); // 10
```

### 🔍 Execution Explanation

- `inner` doesn’t find `a` in its own scope
- It checks outer (`outer`) → finds `a = 10`
- Prints 10

👉 This is **scope chain in action**

---

# 🔹 Example 2 (Multiple Nested Levels)

### 💻 Code

```js id="mfnh4s"
function a() {
  let x = 1;

  function b() {
    let y = 2;

    function c() {
      console.log(x, y);
    }

    c();
  }

  b();
}

a(); // 1 2
```

### 🔍 Explanation

- `c()` accesses:
  - `y` from `b`
  - `x` from `a`

- JS walks up the **scope chain step-by-step**

---

# 🔹 Example 3 (Closure Behavior)

### 💻 Code

```js id="r3ed4i"
function outer() {
  let count = 0;

  return function inner() {
    count++;
    console.log(count);
  };
}

const fn = outer();
fn(); // 1
fn(); // 2
```

### 🔍 WHY this works?

- `inner` **remembers outer scope even after outer finishes**
- This is called a **closure**

# 🔹 Tricky / Edge Cases

---

## ⚠️ Case 1: Variable Shadowing

```js id="b5t79c"
let a = 10;

function outer() {
  let a = 20;

  function inner() {
    console.log(a);
  }

  inner();
}

outer(); // 20
```

👉 Inner picks **nearest variable in scope chain**

---

## ⚠️ Case 2: Outer Cannot Access Inner

```js id="v7av4z"
function outer() {
  function inner() {
    let x = 10;
  }

  console.log(x); // ❌ ReferenceError
}
```

👉 Scope is not bidirectional.

---

## ⚠️ Case 3: Loop + Closure Problem

```js id="9d0kph"
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// 3 3 3 ❌
```

👉 All closures share same `i`

✅ Fix:

```js id="4m8l77"
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// 0 1 2 ✅
```

👉 It gets **reference**, not copy

---

### ❌ Mistake 2: Expecting outer to access inner

👉 Scope is one-directional

---

### ❌ Mistake 3: Ignoring closure memory impact

👉 Variables stay in memory if referenced

# 🔹 Interview Q&A

---

### 1. What is nested function scope?

- It allows inner functions to access outer function variables.
- Based on lexical scoping.

---

### 2. Can outer function access inner variables?

- ❌ No
- Scope flows from inner → outer only.

---

### 3. What is scope chain?

- Mechanism to resolve variables by searching outer scopes.
- Continues until global scope.

---

### 4. What is relation with closure?

- Nested functions create closures when returned.
- They retain access to outer scope variables.

---

### 5. What happens if variable not found?

- JS looks up through scope chain.
- If not found → ReferenceError.

---

### 6. What is shadowing?

- Inner variable overrides outer variable with same name.
- Closest scope is prioritized.

---

### 7. Why is lexical scope important?

- Makes behavior predictable.
- Helps in closures and modular code.

---

### 8. How does nested scope affect memory?

- Closures retain outer variables in memory.
- Can cause memory leaks if not handled.

# 🔹 Best Practices

- ✅ Keep nesting limited (avoid deep nesting)
- ✅ Use closures intentionally
- ✅ Prefer `let/const` for proper scoping
- ✅ Avoid unnecessary variable sharing

# 🔥 Senior-Level Insight

- Nested scopes → powerful but can lead to:
  - Memory leaks (closures holding large data)
  - Hard-to-debug deeply nested logic

👉 Best approach:

- Keep functions small
- Avoid deep nesting → use modular functions
