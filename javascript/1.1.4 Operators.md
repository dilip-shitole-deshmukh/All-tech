## 👉 Operators: Arithmetic, Comparison, Logical

---

## 🔹 Definition

Operators in JavaScript are symbols used to **perform operations on values (operands)** like calculations, comparisons, and logical decisions.

👉 In interviews, focus on:

- What they do
- How they behave with **type coercion**
- Common pitfalls

---

## 🔹 Core Explanation

### 🟢 1. Arithmetic Operators (`+ - * / % **`)

- Used for **mathematical calculations**.
- `+` is special → works for **both addition and string concatenation**.
- `%` returns remainder, `**` is exponentiation.

👉 Why important:
Operator behavior changes based on **data types**, especially with `+`.

---

### 🟢 2. Comparison Operators (`== === != !== > < >= <=`)

- Used to **compare two values** and return `true` or `false`.
- `==` → loose equality (does **type coercion**)
- `===` → strict equality (no type conversion)

👉 Why important:
Choosing `==` vs `===` can lead to unexpected bugs.

---

### 🟢 3. Logical Operators (`&& || !`)

- Used for **combining conditions**.
- They don’t always return boolean → they return **actual operand values**.
- Support **short-circuit evaluation**.

👉 Why important:
Heavily used in UI conditions, default values, and rendering logic.

---

## 🔹 Example(s) with Code

### ✅ Example 1: Arithmetic (`+` confusion)

```javascript id="7qopq3"
console.log(1 + 2); // 3
console.log("1" + 2); // "12"
console.log(1 + "2"); // "12"
console.log(1 + 2 + "3"); // "33"
console.log("1" + 2 + 3); // "123"
```

👉 Explanation:

- If **string is involved**, `+` becomes concatenation
- Evaluation is **left to right**

---

### ⚠️ Example 2: `==` vs `===`

```javascript id="e9h5tw"
console.log(5 == "5"); // true
console.log(5 === "5"); // false
```

👉 Why:

- `==` converts `"5"` → number
- `===` checks both **value + type**

---

### ⚠️ Example 3: Logical Operators Return Values

```javascript id="t45aqw"
console.log(true && "Hello"); // "Hello"
console.log(false && "Hello"); // false

console.log(true || "Hello"); // true
console.log(false || "Hello"); // "Hello"
```

👉 Explanation:

- `&&` → returns first falsy OR last truthy
- `||` → returns first truthy value

---

### ⚠️ Example 4: Short-Circuiting

```javascript id="g1w3c3"
let user = null;

let name = user || "Guest";
console.log(name); // "Guest"
```

👉 Why:

- `||` stops at first truthy → useful for defaults

---

## 🔹 Real-world Use Cases

- 🔹 Arithmetic → price calculation, counters, pagination
- 🔹 Comparison → form validation (`age >= 18`)
- 🔹 Logical → conditional rendering (`isLoggedIn && <Dashboard />`)
- 🔹 Default values → `value || "fallback"`

---

## 🔹 When to use / When NOT to use

### ✅ Use:

- `===` always for comparison (safe & predictable)
- `&&` for conditional execution
- `||` for fallback/default values

### ❌ Avoid:

- `==` unless you fully understand coercion
- Overusing `||` when `0`, `""` are valid values (use `??` instead)

---

## 🔹 Common Mistakes / Traps

### ❌ Mistake 1: `+` confusion

```javascript id="a50qsg"
"5" - 2; // 3
"5" + 2; // "52"
```

💡 Why:

- `-` forces number conversion
- `+` prefers string concatenation

---

### ❌ Mistake 2: Using `||` incorrectly

```javascript id="3fks2r"
let count = 0;
let value = count || 10;

console.log(value); // 10 ❌ unexpected
```

✅ Fix:

```javascript id="yvb36i"
let value = count ?? 10; // 0 ✅
```

💡 Why:

- `||` treats `0` as falsy
- `??` checks only `null` or `undefined`

---

### ❌ Mistake 3: Chained comparisons

```javascript id="lhr9v1"
console.log(1 < 2 < 3); // true
console.log(3 > 2 > 1); // false ❌ confusing
```

💡 Why:

- `1 < 2` → true → becomes `1`
- Then `1 < 3` → true

---

### ❌ Mistake 4: NaN comparison

```javascript id="49ld8n"
NaN === NaN; // false
```

💡 Why:

- NaN is **not equal to anything**, even itself
- Use `Number.isNaN()`

---

## 🔹 Interview Q&A

### ❓ 1. Difference between `==` and `===`?

- `==` → compares after type conversion
- `===` → compares value + type
- Always prefer `===` to avoid surprises

---

### ❓ 2. What is short-circuiting?

- Logical operators stop evaluation early
- `&&` stops at first falsy
- `||` stops at first truthy

---

### ❓ 3. Why `"5" + 2` gives `"52"`?

- `+` operator prefers string concatenation
- Number is converted to string

---

### ❓ 4. What does `&&` return?

- Returns first falsy value OR last truthy value
- Not necessarily boolean

---

### ❓ 5. Why `NaN !== NaN`?

- Special JS behavior
- Use `Number.isNaN()` to check

---

### ❓ 6. Difference between `||` and `??`?

- `||` → checks falsy values
- `??` → checks only `null` and `undefined`

---

### ❓ 7. What is operator precedence?

- Determines execution order
- Example: `2 + 3 * 4 = 14` (multiplication first)

---

## 🔹 Advantages / Pitfalls

### ✅ Advantages

- Powerful and expressive
- Simplifies conditional logic
- Enables concise code (especially logical ops)

### ❌ Pitfalls

- Type coercion confusion (`==`, `+`)
- Logical operators returning non-boolean
- Edge cases with falsy values

---

## 🔹 Best Practices

✔ Always use `===` instead of `==`
✔ Use `??` instead of `||` for safer defaults
✔ Be careful with `+` when mixing types
✔ Use parentheses to avoid precedence confusion
✔ Use `Number.isNaN()` for NaN checks

---

## 🔹 Final Summary (Interview Ready)

- **Arithmetic** → calculations (`+ - * / %`)
- **Comparison** → value checks (`===` preferred)
- **Logical** → combine conditions (`&& || !`)

💡 **Golden Insight:**
👉 “Operators are simple, but JS type coercion makes them tricky — always write predictable code using `===` and clear conditions.”
