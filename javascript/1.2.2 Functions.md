# 🔥 Functions in JavaScript

### (Declaration, Expression, Arrow Functions)

---

# 🔹 1️⃣ Definition

A **function** in JavaScript is a reusable block of code designed to perform a specific task.

Think of it as:

> 📦 A reusable logic container
> 🔁 Executable on demand
> 🧠 First-class citizen (can be passed, returned, stored)

JavaScript supports three major ways to define functions:

1. 🟢 **Function Declaration**
2. 🟡 **Function Expression**
3. 🔵 **Arrow Function (ES6)**

---

# 🔹 2️⃣ Deep Explanation (Everything You Must Know)

---

## 🟢 1. Function Declaration

### ✅ Syntax

```js
function greet(name) {
  return `Hello ${name}`;
}
```

### 🧠 Internal Mechanics

- Hoisted completely
- Can be called before definition
- Has its own `this`
- Has `arguments` object
- Can be used as constructor (with `new`)
- Named by default

### 📌 Hoisting Behavior

```js
sayHi(); // ✅ Works

function sayHi() {
  console.log("Hi");
}
```

The function is moved to memory during compilation phase.

---

## 🟡 2. Function Expression

### ✅ Syntax

```js
const greet = function (name) {
  return `Hello ${name}`;
};
```

### 🧠 Internal Mechanics

- Not fully hoisted
- Stored in variable
- Can be anonymous or named
- Useful for callbacks
- Has its own `this`
- Has `arguments`

### ❌ Hoisting Example

```js
sayHi(); // ❌ Error

const sayHi = function () {
  console.log("Hi");
};
```

Only the variable is hoisted (undefined), not the function.

---

## 🔵 3. Arrow Function (ES6)

### ✅ Syntax

```js
const greet = (name) => {
  return `Hello ${name}`;
};
```

### Short form

```js
const greet = (name) => `Hello ${name}`;
```

### 🧠 Internal Behavior

- ❌ No own `this`
- ❌ No `arguments`
- ❌ Cannot be used as constructor
- ❌ No `prototype`
- Lexically binds `this`
- Not hoisted like declarations

---

# 🔥 The Most Important Difference → `this`

---

## Regular Function (`this` dynamic)

```js
const user = {
  name: "Dilip",
  greet: function () {
    console.log(this.name);
  },
};

user.greet(); // Dilip
```

`this` refers to object calling it.

---

## Arrow Function (`this` lexical)

```js
const user = {
  name: "Dilip",
  greet: () => {
    console.log(this.name);
  },
};

user.greet(); // undefined
```

Arrow inherits `this` from surrounding scope.

---

### 🔥 Why Arrow Function Exists?

To fix this common issue:

```js
function Timer() {
  this.seconds = 0;

  setInterval(function () {
    this.seconds++; // ❌ Wrong this
  }, 1000);
}
```

Correct with arrow:

```js
function Timer() {
  this.seconds = 0;

  setInterval(() => {
    this.seconds++; // ✅ Correct
  }, 1000);
}
```

# 🔹 3️⃣ Example (Senior-Level Practical Code)

---

## 🟢 Function Declaration (Utility Function)

```js
function calculateDiscount(price, percentage) {
  return price - (price * percentage) / 100;
}
```

---

## 🟡 Function Expression (Callback Usage)

```js
const numbers = [1, 2, 3];

const doubled = numbers.map(function (num) {
  return num * 2;
});
```

---

## 🔵 Arrow Function (Modern React Usage)

```js
const doubled = numbers.map((num) => num * 2);
```

---

## 🔥 In React Component

```js
const Button = () => {
  const handleClick = () => {
    console.log("Clicked");
  };

  return <button onClick={handleClick}>Click</button>;
};
```

Arrow functions are preferred in React for predictable `this`.

# 🔹 5️⃣ When to Use? Why? Where? How?

---

## 🟢 Use Function Declaration When:

✔ Function is core reusable logic
✔ Needs hoisting
✔ Used globally

Example:

- Validation utilities
- Math helpers

---

## 🟡 Use Function Expression When:

✔ You want controlled scope
✔ Passing as argument
✔ Closures

Example:

- Event handlers
- Factory functions

---

## 🔵 Use Arrow Function When:

✔ Working with React
✔ Inside callbacks
✔ Need lexical `this`
✔ Short concise syntax

# 🔹 6️⃣ 10+ Interview Q&A

---

### 1️⃣ What is difference between function declaration and expression?

Declaration is hoisted fully. Expression is not.

---

### 2️⃣ Are arrow functions hoisted?

No.

---

### 3️⃣ Can arrow function be constructor?

No.

```js
const Person = () => {};
new Person(); // ❌ Error
```

---

### 4️⃣ Do arrow functions have arguments object?

No.

---

### 5️⃣ What is lexical this?

`this` from surrounding scope.

---

### 6️⃣ Which function type is best for React class methods?

Arrow (to avoid binding).

---

### 7️⃣ Why arrow functions cannot be used as constructors?

They don’t have `prototype`.

---

### 8️⃣ What happens if you return object in arrow function?

Need parentheses:

```js
const getUser = () => ({ name: "Dilip" });
```

---

### 9️⃣ Can function expression be named?

Yes.

```js
const greet = function sayHello() {};
```

---

### 🔟 Difference in memory?

Arrow functions inside objects can increase memory if recreated frequently.

---

### 1️⃣1️⃣ What about default parameters?

Works in all:

```js
function greet(name = "Guest") {}
```

---

### 1️⃣2️⃣ What about rest parameters?

```js
function sum(...nums) {}
```

# ⚡ Pitfalls

---

### ❌ Using arrow in object methods

```js
const obj = {
  value: 10,
  getValue: () => this.value,
};
```

Wrong.

---

### ❌ Overusing inline arrow in React

```jsx
<button onClick={() => doSomething()} />
```

Recreates function every render.

---

### ❌ Forgetting return in arrow block body

```js
const sum = (a, b) => {
  a + b;
}; // undefined
```

# 🔥 Senior-Level Perspective / Best Practices

---

## 🧠 1. Prefer arrow functions in:

- React functional components
- Array methods
- Async logic

---

## 🧠 2. Prefer function declaration for:

- Shared utilities
- Business logic
- Large reusable modules

---

## 🧠 3. Avoid:

- Arrow functions as object methods
- Over-nesting anonymous functions
- Creating functions inside loops unnecessarily

---

## 🧠 4. Performance Insight

Functions created inside render cycles (React) → performance cost.

Use:

```js
useCallback();
```

---

## 🧠 5. Clean Architecture Tip

✔ Keep functions pure
✔ Avoid side effects
✔ Prefer small composable functions
