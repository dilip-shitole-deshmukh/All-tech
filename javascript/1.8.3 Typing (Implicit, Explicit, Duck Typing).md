## 🧠 Typing in JavaScript (Implicit, Explicit, Duck Typing)

---

## 🔹 Definition

Typing refers to **how JavaScript handles and interprets data types at runtime**.

👉 JavaScript is:

> **Dynamically typed** → variables don’t have fixed types

💡 Types are determined **automatically at runtime**, not at compile time.

---

## 🔹 Core Explanation

---

## 🟢 1. Implicit Typing (Type Coercion)

👉 Also called **automatic type conversion**

```js
"5" + 2; // "52"
"5" - 2; // 3
```

🧠 How it works:

- JS automatically converts types to perform operations
- Uses internal rules (ToNumber, ToString, etc.)

---

### 🔥 WHY it behaves like this

👉 JS tries to be flexible:

```js
true + 1; // 2
```

- `true` → 1
- Then 1 + 1

---

### ⚠️ Tricky Cases

```js
[] + {}; // "[object Object]"
{
}
+[]; // 0 (in some contexts)
```

👉 Coercion rules can be confusing

---

## 🔵 2. Explicit Typing (Type Conversion)

👉 Developer manually converts types

```js
Number("5"); // 5
String(10); // "10"
Boolean(1); // true
```

🧠 Why use:

- Predictable behavior
- Avoid bugs from implicit coercion

---

### 💡 Common Methods

```js
parseInt("10");
parseFloat("10.5");
```

---

### ✅ Safer Example

```js
Number("5") + 2; // 7 (predictable)
```

👉 Better than:

```js
"5" + 2; // "52"
```

---

## 🟡 3. Duck Typing (Conceptual 🔥)

👉 Based on behavior, not type

> “If it looks like a duck and behaves like a duck → it is a duck”

---

### 🧠 Meaning in JS

- Objects are used based on **what they can do**, not their type

```js
function printLength(obj) {
  console.log(obj.length);
}

printLength("Hello"); // works
printLength([1, 2, 3]); // works
```

👉 No type checking → just behavior

---

### 💡 WHY JS supports Duck Typing

- JS is loosely typed
- No strict type enforcement

---

## 🔹 Example(s) with Code

---

### ✅ Example 1: Implicit Typing

```js
console.log("10" - 5); // 5
console.log("10" + 5); // "105"
```

🧠 WHY:

- `-` forces number conversion
- `+` prefers string concatenation

---

### ✅ Example 2: Explicit Typing

```js
let num = Number("10");
console.log(num + 5); // 15
```

👉 Controlled conversion

---

### ✅ Example 3: Duck Typing

```js
function logValue(obj) {
  if (obj.log) {
    obj.log();
  }
}

logValue({ log: () => console.log("Hello") });
```

👉 No class/type check → only behavior

## 🔹 When to Use / When NOT to Use

---

### ✅ Use Implicit Typing

- Simple operations
- Quick conversions

---

### ✅ Use Explicit Typing

- Critical logic
- Financial calculations
- API data

---

### ✅ Use Duck Typing

- Flexible functions
- Reusable utilities

---

### ❌ Avoid

- Relying heavily on implicit coercion
- Ignoring type validation in critical apps

---

## 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Confusing `+` behavior

```js
"5" + 1; // "51" ❌ unexpected
```

---

### ❌ Mistake 2: Using `==` instead of `===`

```js
"5" == 5; // true
"5" === 5; // false ✅
```

👉 `==` uses coercion

---

### ❌ Mistake 3: Assuming type safety

👉 JS does not enforce types

---

### ❌ Mistake 4: Duck typing without checks

👉 Can cause runtime errors

---

## 🔹 Interview Q&A

---

### ❓1. What is implicit typing?

Automatic type conversion by JS.

---

### ❓2. What is explicit typing?

Manual type conversion using functions.

---

### ❓3. What is duck typing?

Checking object behavior instead of type.

---

### ❓4. Why `"5" + 2` is "52"?

Because `+` triggers string concatenation.

---

### ❓5. Why `"5" - 2` is 3?

Because `-` converts to number.

---

### ❓6. Difference between `==` and `===`?

- `==` → coercion
- `===` → strict comparison

---

### ❓7. Is JS statically typed?

❌ No → dynamically typed

---

### ❓8. When to avoid implicit typing?

In critical logic or complex calculations

---
