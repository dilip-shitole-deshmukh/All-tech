## ⏱️ `setTimeout` & `setInterval` (JavaScript)

> ⚠️ This is a **🟡 Conceptual + Core Async topic**
> 👉 Frequently asked → tests **Event Loop + timing behavior + pitfalls**

---

## 🔹 Definition

👉 **`setTimeout`**

> Executes a function **once after a specified delay**

👉 **`setInterval`**

> Executes a function **repeatedly at fixed intervals**

💡 Both are **Web APIs (not pure JS)** and work via the **Event Loop**

---

## 🔹 Core Explanation

---

## 🟢 1. Basic Syntax

---

### 🔹 `setTimeout`

```js
setTimeout(callback, delay);
```

👉 Runs callback **after delay (ms)**

---

### 🔹 `setInterval`

```js
setInterval(callback, interval);
```

👉 Runs callback **every interval (ms)**

---

## 🔹 Example(s) with Code

---

### ✅ Example 1: setTimeout

```js
console.log("Start");

setTimeout(() => {
  console.log("Hello after 2s");
}, 2000);

console.log("End");
```

### 🧠 Output:

```text
Start
End
Hello after 2s
```

👉 WHY:

- `setTimeout` is async → pushed to Web API

---

### ✅ Example 2: setInterval

```js
let count = 0;

const id = setInterval(() => {
  console.log(count++);
}, 1000);

setTimeout(() => clearInterval(id), 5000);
```

👉 Prints every second, stops after 5 sec

---

## 🔥 2. How It Works (Event Loop)

👉 Flow:

```text
Call Stack → Web API → Callback Queue → Event Loop
```

### 🧠 Execution:

1. Timer registered in Web API
2. After delay → callback goes to queue
3. Event loop pushes it when stack is empty

💡 Even `setTimeout(0)` is NOT immediate

---

## ⚠️ 3. Minimum Delay & Timing Behavior

---

### 🔹 `setTimeout(fn, 0)`

```js
setTimeout(() => console.log("A"), 0);
console.log("B");
```

👉 Output:

```text
B
A
```

💡 WHY:

- Callback still waits for event loop

---

### 🔹 Browser delay clamping

👉 Nested timers may have **minimum delay (~4ms)**

---

## 🔥 4. Key Differences

| Feature   | setTimeout     | setInterval    |
| --------- | -------------- | -------------- |
| Execution | Once           | Repeated       |
| Control   | Manual re-call | Automatic      |
| Use case  | Delay task     | Repeating task |

---

## 🔥 5. Clearing Timers

---

### 🔹 clearTimeout

```js
const id = setTimeout(() => {}, 1000);
clearTimeout(id);
```

---

### 🔹 clearInterval

```js
const id = setInterval(() => {}, 1000);
clearInterval(id);
```

👉 Always clean timers to avoid leaks

---

## ⚠️ Tricky Concepts (Interview Favorites)

---

### ❗ 1. setInterval vs setTimeout loop

```js
setInterval(() => {
  console.log("Task");
}, 1000);
```

👉 Problem:

- If task takes longer → overlaps

---

### ✅ Better approach

```js
function run() {
  setTimeout(() => {
    console.log("Task");
    run();
  }, 1000);
}
run();
```

👉 Ensures no overlap

---

### ❗ 2. Closure Issue in Loops

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 1000);
}
```

👉 Output:

```text
3 3 3
```

💡 WHY:

- `var` is function-scoped

---

### ✅ Fix

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 1000);
}
```

👉 Output:

```text
0 1 2
```

## 🔹 When to Use / When NOT to Use

---

### ✅ Use setTimeout

- One-time delay
- Controlled execution

---

### ✅ Use setInterval

- Repeating tasks

---

### ❌ Avoid setInterval

- Long-running tasks (use recursive timeout)

---

## 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Assuming exact timing

👉 JS timers are **not precise**

---

### ❌ Mistake 2: Not clearing intervals

👉 Leads to memory leaks

---

### ❌ Mistake 3: Using setInterval for async tasks

👉 Causes overlapping executions

---

### ❌ Mistake 4: Blocking main thread

👉 Delays timer execution
