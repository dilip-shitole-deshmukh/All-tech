# 🧠 Object-Oriented Programming (OOP) Basics (JavaScript)

---

## 🔹 Definition

👉 **Simple Definition (2–3 lines):**
OOP is a programming paradigm where code is organized around **objects** instead of functions.
Objects contain **data (properties)** and **behavior (methods)**.

👉 **Deeper Explanation (2–3 lines):**
In JavaScript, OOP is implemented using **prototypes**, not true classical classes.
Concepts like **encapsulation, inheritance, polymorphism, and abstraction** are achieved using functions, objects, and `class` syntax.

---

# 🔹 Deep Explanation (Core Section)

---

## 1️⃣ Objects (Foundation of OOP)

- Objects are collections of key-value pairs where values can be data or functions.
- They act as **real-world entities** (User, Product, Cart).
- In JS, objects are dynamic → properties can be added/removed anytime.

💡 Internals:

- Objects are stored as **hash maps (hidden classes in V8)**
- Property access uses **prototype chain lookup** if not found directly

⚠️ Edge Case:

- Accessing non-existing property → returns `undefined` (not error)

---

## 2️⃣ Encapsulation (Data Hiding)

- Encapsulation means **bundling data + methods** and restricting direct access.
- Helps prevent accidental modification.

💡 How JS does it:

- Using closures OR private fields (`#`)
- Example:

```js
class Bank {
  #balance = 0;
  deposit(amount) {
    this.#balance += amount;
  }
}
```

💡 Why:

- Protects internal state → avoids bugs and misuse

⚠️ Edge Case:

- `_balance` is NOT private (just convention)

---

## 3️⃣ Inheritance (Code Reusability)

- One object/class can **reuse properties/methods** of another.
- Achieved using `extends` or prototype chaining.

💡 Internals:

- JS links objects via **[[Prototype]] chain**
- Lookup goes upward until property is found or null

⚠️ Edge Case:

- Deep inheritance → performance hit due to long prototype chain

---

## 4️⃣ Polymorphism (Same method, different behavior)

- Same method name behaves differently depending on context.

💡 Types in JS:

- Method overriding
- Dynamic typing allows flexible inputs

```js
class Animal {
  speak() {
    console.log("Sound");
  }
}
class Dog extends Animal {
  speak() {
    console.log("Bark");
  }
}
```

💡 Why:

- Enables flexible and extensible code

---

## 5️⃣ Abstraction (Hiding complexity)

- Show only **essential details**, hide implementation.

💡 Example:

```js
fetch("/api"); // we don’t know internal working
```

💡 Why:

- Reduces complexity
- Improves maintainability

---

## 6️⃣ Prototype-based OOP (Important for JS)

- Every object has a hidden `[[Prototype]]`
- Used for inheritance instead of copying

💡 Key Idea:

```js
obj.__proto__ === Constructor.prototype;
```

💡 Why:

- Memory efficient (methods shared)

---

## 7️⃣ `class` vs Prototype OOP

| Class           | Prototype       |
| --------------- | --------------- |
| Cleaner syntax  | Core mechanism  |
| Easier to read  | More flexible   |
| Syntactic sugar | Actual behavior |

💡 Interview Tip:
👉 “Classes are just syntactic sugar over prototypes”

# 🔹 Example(s) with Code

---

### ✅ Example 1: Encapsulation

```js
class User {
  #password;

  constructor(pwd) {
    this.#password = pwd;
  }

  checkPassword(pwd) {
    return this.#password === pwd;
  }
}

const u = new User("1234");
console.log(u.checkPassword("1234"));
```

### 🔍 Execution:

1. Object created via `new User()`
2. `#password` stored privately
3. Access only through method

💡 Output:

```js
true;
```

💡 WHY:

- Private fields are enforced by JS engine → not accessible outside

---

### ⚡ Example 2: Prototype Chain (Tricky)

```js
const parent = {
  greet() {
    console.log("Hello");
  },
};

const child = {};
child.__proto__ = parent;

child.greet();
```

### 🔍 Execution:

1. JS looks for `greet` in `child`
2. Not found → checks `parent`
3. Finds method → executes

💡 Output:

```js
Hello;
```

💡 WHY:

- Prototype chain lookup mechanism

---

### ⚡ Example 3: Polymorphism (Interview-level)

```js
class Shape {
  area() {
    return 0;
  }
}

class Circle extends Shape {
  constructor(r) {
    super();
    this.r = r;
  }

  area() {
    return Math.PI * this.r * this.r;
  }
}

const s = new Shape();
const c = new Circle(2);

console.log(s.area());
console.log(c.area());
```

### 🔍 Execution:

- `s.area()` → base class method
- `c.area()` → overridden method

💡 Output:

```js
0
12.56...
```

💡 WHY:

- Method resolution depends on object type

# 🔹 When to use? (Why, Where, How)

---

✔️ Use when:

- You have **complex data + behavior together**
- Need **modular and reusable structure**

✔️ Use when:

- Building **large applications**
- Multiple related entities (User, Order, Cart)

✔️ Use when:

- You need **inheritance or shared behavior**

---

# 🔹 When NOT to use

---

❌ Avoid when:

- Small utilities → functions better
- Over-engineering simple logic

❌ Avoid when:

- Functional programming fits better (React hooks, reducers)

# 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Thinking JS is class-based

- ❌ “JS works like Java”
- ✅ It is prototype-based
- 💡 Class is just abstraction

---

### ❌ Mistake 2: Overusing inheritance

- ❌ Deep class hierarchy
- ✅ Prefer composition
- 💡 Reduces coupling

---

### ❌ Mistake 3: Ignoring `this`

- ❌ `this` always refers to object
- ✅ Depends on call-site
- 💡 Leads to bugs in callbacks

---

### ❌ Mistake 4: Fake encapsulation

- ❌ Using `_var` as private
- ✅ Use `#` or closures
- 💡 `_` is just naming convention

# 🔹 10+ Interview Q&A

---

### 1. What is OOP?

OOP organizes code using objects containing data and methods. It improves structure and reusability.

---

### 2. Is JavaScript OOP?

Yes, but it uses prototype-based OOP, not classical OOP.

---

### 3. What are 4 pillars?

Encapsulation, Inheritance, Polymorphism, Abstraction.

---

### 4. What is encapsulation?

Hiding internal data and exposing controlled access methods.

---

### 5. What is inheritance?

Reusing properties/methods from parent objects.

---

### 6. What is polymorphism?

Same method behaves differently based on context.

---

### 7. What is abstraction?

Hiding implementation details and exposing only necessary parts.

---

### 8. Difference between class and prototype?

Class is syntax; prototype is actual mechanism.

---

### 9. Why use OOP?

Better organization, scalability, and maintainability.

---

### 10. Is OOP always better?

No, functional programming can be simpler and more predictable.

---

### 11. What is prototype chain?

A chain of objects used for property lookup.

# ⚡ Pitfalls

---

⚠️ Over-engineering
→ Adds complexity unnecessarily

⚠️ Tight coupling
→ Deep inheritance makes code rigid

⚠️ Debugging difficulty
→ Prototype chain can confuse

# 🔹 Best Practices

---

✔️ Prefer composition over inheritance
✔️ Keep classes small and focused
✔️ Use private fields for sensitive data
✔️ Avoid deep prototype chains
