## 👉 Variables (`var`, `let`, `const`)

---

## 🔹 Definition

Variables in JavaScript are used to **store data values** that can be reused and manipulated throughout the program.

JavaScript provides three ways to declare variables:

- `var` (old way, function-scoped)
- `let` (block-scoped, mutable)
- `const` (block-scoped, immutable reference)

---

## 🔹 Core Explanation

### 🟢 1. `var` (Function Scoped)

- `var` is **function-scoped**, meaning it is accessible throughout the entire function, not just inside blocks (`{}`).
- It also gets **hoisted and initialized with `undefined`**, which can lead to unexpected behavior.
- It allows **re-declaration and re-assignment**, making it error-prone in large applications.

👉 Why this matters:
Because of loose scoping + hoisting, `var` can cause bugs that are hard to track.

---

### 🟢 2. `let` (Block Scoped)

- `let` is **block-scoped**, meaning it's only accessible within `{}` where it is defined.
- It is **hoisted but NOT initialized**, which leads to the **Temporal Dead Zone (TDZ)**.
- It allows **re-assignment but NOT re-declaration** in the same scope.

👉 Why this matters:
Provides safer variable handling compared to `var`, especially in loops and conditions.

---

### 🟢 3. `const` (Block Scoped + Constant Reference)

- `const` is also **block-scoped**, similar to `let`.
- It **must be initialized at declaration** and cannot be reassigned.
- BUT for objects/arrays, the **reference is constant, not the value**.

👉 Why this matters:
Prevents accidental reassignment → improves code reliability.

---

## 🔹 Example(s) with Code

### ✅ Example 1: Scope Difference

```javascript
function test() {
  if (true) {
    var a = 10;
    let b = 20;
    const c = 30;
  }

  console.log(a); // ✅ 10
  console.log(b); // ❌ ReferenceError
  console.log(c); // ❌ ReferenceError
}
```

👉 Explanation:

- `var` ignores block scope → accessible outside `{}`
- `let` & `const` are block-scoped → not accessible outside

---

### ✅ Example 2: Hoisting Behavior

```javascript
console.log(a); // undefined
var a = 5;

console.log(b); // ❌ ReferenceError
let b = 10;
```

👉 Explanation:

- `var` is hoisted and initialized → `undefined`
- `let` is hoisted but in **TDZ** → cannot access before declaration

---

### ⚠️ Example 3: `const` with Objects

```javascript
const user = { name: "Dilip" };

user.name = "Rahul"; // ✅ Allowed
user = {}; // ❌ Error
```

👉 Explanation:

- Object content can change
- But reference cannot be reassigned

---

## 🔹 Real-world Use Cases

- 🔹 `let` → when value **changes over time** (loops, counters, state updates)
- 🔹 `const` → for **fixed references** (config, API URLs, constants, imported modules)
- 🔹 Avoid `var` → mostly legacy code or backward compatibility

---

## 🔹 When to use / When NOT to use

### ✅ Use:

- `const` → by default (safe + predictable)
- `let` → when reassignment is required

### ❌ Avoid:

- `var` → unless dealing with old codebases or specific edge cases

---

## 🔹 Common Mistakes / Traps

### ❌ Mistake 1: Thinking `const` is immutable

```javascript
const arr = [1, 2];
arr.push(3); // ✅ works
```

✅ Reality: Only reference is constant, not inner values

---

### ❌ Mistake 2: Using `var` in loops

```javascript
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// Output: 3 3 3
```

✅ Fix with `let`:

```javascript
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// Output: 0 1 2
```

💡 Why:

- `var` shares same reference
- `let` creates new binding per iteration

---

### ❌ Mistake 3: TDZ confusion

```javascript
console.log(x); // ❌ ReferenceError
let x = 5;
```

💡 Why:

- Variable exists but not initialized → TDZ

---

## 🔹 Interview Q&A

### ❓ 1. Difference between `var`, `let`, `const`?

- `var` → function-scoped, hoisted with `undefined`, can redeclare
- `let` → block-scoped, TDZ, cannot redeclare
- `const` → block-scoped, must initialize, no reassignment

---

### ❓ 2. What is Temporal Dead Zone (TDZ)?

- Time between variable hoisting and initialization
- Accessing variable in this phase throws error
- Applies to `let` and `const`

---

### ❓ 3. Why `var` is discouraged?

- No block scope → unexpected leaks
- Hoisting confusion
- Allows redeclaration → bugs in large codebases

---

### ❓ 4. Can `const` be changed?

- Cannot reassign variable
- But objects/arrays inside it can be modified

---

### ❓ 5. Are `let` and `const` hoisted?

- Yes, but not initialized
- They stay in TDZ until declaration

---

### ❓ 6. What happens if you redeclare `let`?

```javascript
let a = 10;
let a = 20; // ❌ Error
```

- Not allowed in same scope

---

### ❓ 7. Which should you use by default?

- Prefer `const` → safer, avoids accidental reassignment
- Use `let` only when necessary

---

## 🔹 Advantages / Pitfalls

### ✅ Advantages

- `let` & `const` provide **predictable scoping**
- Prevent accidental bugs (especially in async code)
- Improve readability and maintainability

### ❌ Pitfalls

- TDZ can confuse beginners
- `const` misconception (not deeply immutable)

---

## 🔹 Best Practices

✔ Use `const` by default
✔ Use `let` only when reassignment is needed
✔ Avoid `var` completely
✔ Keep variable scope as small as possible
✔ Prefer meaningful variable names

---

## 🔹 Final Summary (Interview Ready)

- `var` → ❌ function-scoped, hoisting issues, avoid
- `let` → ✅ block-scoped, reassignable, safe
- `const` → ✅ block-scoped, no reassignment, best default

💡 **Golden Rule:**
👉 Use `const` → fallback to `let` → never use `var` (in modern JS)
