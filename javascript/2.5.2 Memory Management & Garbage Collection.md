## 🧠 Memory Management & Garbage Collection (JavaScript)

> ⚠️ This is a **🔴 Advanced / Performance + System topic**
> 👉 Interviewers expect: **heap/stack, GC algorithms, leaks, optimization insights**

---

# 🔹 Definition

👉 **Memory Management = how JavaScript allocates, uses, and frees memory automatically**

- JS uses **automatic garbage collection (GC)**
- Developers don’t manually free memory (unlike C/C++)
- Engine (like V8) handles allocation & cleanup

---

# 🔹 Core Explanation

---

## 🧠 1. Memory Lifecycle (VERY IMPORTANT ⭐)

```text
Allocate → Use → Release
```

---

### 🔹 1. Allocation

👉 Happens when you create variables:

```js
let num = 10; // primitive
let obj = { a: 1 }; // object
```

👉 Engine decides:

- Stack or Heap

---

### 🔹 2. Usage

👉 Reading / writing values

```js
console.log(obj.a);
```

---

### 🔹 3. Release

👉 When memory is no longer needed → GC cleans it

---

## 🧠 2. Stack vs Heap (CORE CONCEPT)

---

### 📦 Stack

👉 Stores:

- Primitive values
- Function calls

```js
let x = 10;
```

✔ Fast
✔ Fixed size
❌ Limited

---

### 🧠 Heap

👉 Stores:

- Objects
- Arrays
- Functions

```js
let obj = { name: "JS" };
```

✔ Flexible
❌ Slower access

---

### 💡 Key Idea:

```text
Stack → simple data
Heap → complex data
```

---

## 🧠 3. Garbage Collection (HOW it works)

---

### 🔥 Main Algorithm: Mark & Sweep

---

### 🔹 Step 1: Mark

👉 GC marks all **reachable objects**

```text
Global → references → objects
```

---

### 🔹 Step 2: Sweep

👉 Removes **unreachable objects**

```text
Not reachable → deleted from memory
```

---

### 💡 Example:

```js
let obj = { name: "JS" };
obj = null;
```

👉 Old object becomes unreachable → GC removes it

---

## 🔹 Example(s) with Code

---

### ✅ Example 1: Basic GC

```js
function createUser() {
  let user = { name: "Dilip" };
  return user;
}

createUser();
```

👉 After function ends:

- `user` not referenced → GC removes it

---

### ❗ Example 2: Memory Leak (Tricky ⭐)

```js
let arr = [];

function add() {
  arr.push(new Array(1000000).fill("data"));
}

setInterval(add, 1000);
```

👉 WHY:

- References kept in `arr`
- GC cannot clean → memory grows

---

### ❗ Example 3: Closure Leak

```js
function outer() {
  let largeData = new Array(1000000).fill("data");

  return function inner() {
    console.log("Hello");
  };
}

const fn = outer();
```

👉 WHY:

- `inner` keeps reference to `largeData`
- Memory not freed

## ⚠️ Common Mistakes / Traps

---

### ❌ Mistake 1: Thinking GC frees everything automatically

👉 Reality:

```text
GC frees only unreachable memory
```

---

### ❌ Mistake 2: Unintentional global variables

```js
function test() {
  x = 10; // no var/let/const
}
```

👉 Becomes global → never cleaned

---

### ❌ Mistake 3: Forgotten event listeners

```js
element.addEventListener("click", handler);
```

👉 Not removed → memory leak

---

### ❌ Mistake 4: Closures holding large data

👉 Keeps memory alive unnecessarily

Handling allocation, usage, and cleanup of memory

Automatic cleanup of unused memory

Algorithm to remove unreachable objects

## 🔹 Advantages / Pitfalls

---

### ✅ Advantages

- Automatic memory handling
- Easier development
- Safer than manual memory

---

### ❌ Pitfalls

- Hidden memory leaks
- GC pauses (performance impact)
- Less control

---

## 🔹 Best Practices

---

✔ Avoid global variables
✔ Remove unused event listeners

```js
element.removeEventListener("click", handler);
```

✔ Use `null` to remove references

```js
obj = null;
```

✔ Be careful with closures
✔ Use WeakMap / WeakSet for temporary references

## 🔹 Senior-Level Insights 🚀

---

## ⚡ 1. Generational Garbage Collection

👉 Memory divided into:

```text
Young Generation → short-lived objects
Old Generation → long-lived objects
```

---

### 💡 WHY:

- Most objects die quickly
- Optimize GC performance

---

## ⚡ 2. Stop-the-world Problem

👉 GC pauses execution:

```text
JS execution stops → GC runs → resumes
```

👉 Causes UI lag if heavy

---

## ⚡ 3. Memory Leak Patterns

---

### 🔥 Common Patterns:

```text
• Detached DOM nodes
• Closures
• Timers (setInterval)
• Caches growing indefinitely
```

---

## ⚡ 4. Weak References (IMPORTANT ⭐)

```js
const wm = new WeakMap();
```

👉 GC can remove entries if no strong reference exists

---

## ⚡ 5. Profiling Tools

👉 Chrome DevTools:

- Memory tab
- Heap snapshot
- Allocation timeline

👉 JavaScript manages memory automatically, but **developers must avoid unnecessary references**

JavaScript uses automatic garbage collection (mark-and-sweep) to clean unused memory, but memory leaks can still occur when references to unused objects are retained
