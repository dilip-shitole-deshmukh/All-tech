## 🧠 Prototypes (JavaScript)

---

## 🔹 Definition

A Prototype is an object from which other objects **inherit properties and methods**.

👉 In simple terms:

> “Every JavaScript object has a hidden link to another object → its prototype”

💡 This is the foundation of **inheritance in JavaScript (Prototypal Inheritance)**.

---

## 🔹 Core Explanation

---

### ⚙️ 1. Prototype Chain (Most Important 🔥)

Every object has an internal link:

```text
[[Prototype]] → another object → ... → null
```

👉 When accessing a property:

1. JS looks in the object
2. If not found → looks in prototype
3. Continues up the chain

---

### 🧠 Example

```js id="6nlx3v"
const obj = { a: 1 };

console.log(obj.toString()); // works!
```

👉 WHY:

- `toString` is not in `obj`
- Found in `Object.prototype`

---

### 🔗 2. How Prototype is Set

#### ✅ Using Constructor Function

```js id="1dwn0h"
function Person(name) {
  this.name = name;
}

Person.prototype.greet = function () {
  console.log("Hello " + this.name);
};

const p1 = new Person("Dilip");
p1.greet();
```

🧠 Flow:

- `p1.__proto__ → Person.prototype`

---

### 🧩 3. `__proto__` vs `prototype`

| Property    | Meaning                          |
| ----------- | -------------------------------- |
| `__proto__` | Actual link to prototype         |
| `prototype` | Property of constructor function |

---

👉 Relationship:

```text
instance.__proto__ === Constructor.prototype
```

---

### 🔁 4. Prototype Lookup (How JS Finds Properties)

```js id="f0hq36"
const obj = { a: 1 };

obj.b; // not found
```

🧠 JS does:

```text
obj → prototype → prototype → null
```

👉 Stops when found or reaches null

---

### 🧪 5. Modifying Prototype

```js id="9jv23x"
Person.prototype.age = 25;
```

👉 All instances now have access to `age`

---

### ✅ Example 3: Shared Methods (Memory Efficient 🔥)

```js id="v9yo0p"
function User(name) {
  this.name = name;
}

User.prototype.sayHi = function () {
  console.log("Hi " + this.name);
};

const u1 = new User("A");
const u2 = new User("B");
```

👉 Only **one copy** of `sayHi` shared

## 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Confusing prototype vs **proto**

👉 One is function property, other is instance link

---

### ❌ Mistake 2: Adding methods inside constructor

```js id="q4sx36"
function User() {
  this.sayHi = function() {}; ❌
}
```

👉 Creates new function per instance

---

### ❌ Mistake 3: Overwriting prototype

```js id="dsu27m"
User.prototype = { sayHi() {} };
```

👉 Loses constructor reference

---

### ❌ Mistake 4: Modifying built-in prototype

```js id="a4z56p"
Array.prototype.myFunc = () => {}; ❌
```

👉 Can break code

## 🔹 Interview Q&A

---

### ❓1. What is prototype?

Object from which another object inherits properties.

---

### ❓2. What is prototype chain?

Chain of objects used for property lookup.

---

### ❓3. Difference between prototype and **proto**?

- prototype → constructor property
- **proto** → instance link

---

### ❓4. Why use prototypes?

To share methods across objects

---

### ❓5. What happens if property not found?

JS searches prototype chain

---

### ❓6. What is Object.prototype?

Top-level prototype for all objects

---

### ❓7. Are arrays and functions objects?

✅ Yes, they also have prototypes

---

### ❓8. What is prototypal inheritance?

Objects inherit from other objects

## 🔹 Senior-Level Insights 🚀

---

### ⚡ Prototype vs Class (Important)

```js id="96jodk"
class User {
  sayHi() {}
}
```

👉 Under the hood:

- Uses prototype

---

### 🧠 Memory Optimization

❌ Bad:

```js id="hqecpk"
this.method = function () {};
```

✅ Good:

```js id="w6z5x2"
User.prototype.method = function () {};
```

👉 Saves memory

---

### 🔄 Prototype Chain Depth

👉 Deep chains:

- Slower lookup
- Hard to debug

---

### ⚖️ Trade-offs

| Approach  | Pros      | Cons        |
| --------- | --------- | ----------- |
| Prototype | Efficient | Complex     |
| Classes   | Readable  | Abstraction |
