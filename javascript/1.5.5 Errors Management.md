## 🧠 Error Management (JavaScript / Frontend)

---

## 🔹 Definition

Error Management is the **strategy of detecting, handling, logging, and recovering from errors** in an application.

👉 In simple terms:

> “Not just catching errors → but managing them properly across the app”

💡 It includes:

- `try-catch`
- Custom errors
- Global handlers
- Logging & monitoring

---

## 🔹 Core Explanation

---

### ⚙️ 1. Layers of Error Management (Very Important 🔥)

Error handling is not just one thing — it's a **multi-layered system**:

#### 🟢 Layer 1: Local Handling (try-catch)

- Handles errors where they occur
- Best for **specific logic (API call, parsing)**
- Gives fine-grained control

---

#### 🟡 Layer 2: Custom Errors

- Classify errors (Validation, API, Auth)
- Helps in **structured handling**
- Improves readability & debugging

---

#### 🔴 Layer 3: Global Handlers

- Catch uncaught errors
- Acts as **fallback safety net**
- Used for logging & crash reporting

---

#### ⚫ Layer 4: Monitoring & Logging

- Send errors to tools (Sentry, etc.)
- Helps debug **real production issues**

---

### 🔁 Error Flow (Big Picture)

```text
User Action → Error Occurs →
try-catch? → handled → continue
        ↓
not handled → global handler →
log + fallback UI
```

## 🔹 Example(s) with Code

---

### ✅ Example 1: Layered Error Handling

```js id="6snm2f"
class ValidationError extends Error {}

async function fetchUser() {
  try {
    const res = await fetch("/api/user");

    if (!res.ok) {
      throw new Error("API failed");
    }

    return res.json();
  } catch (err) {
    if (err instanceof ValidationError) {
      console.log("Validation issue");
    } else {
      console.log("Generic error");
    }
    throw err; // rethrow for global handler
  }
}
```

🧠 Key Idea:

- Handle locally if possible
- Otherwise rethrow → global handler handles

---

### ✅ Example 2: Global + Logging

```js id="rrr2mq"
window.addEventListener("error", (e) => {
  sendToServer(e.message);
});

window.addEventListener("unhandledrejection", (e) => {
  sendToServer(e.reason);
});
```

---

### ✅ Example 3: User-friendly UI Handling

```js id="6qp58d"
try {
  await fetchData();
} catch (e) {
  showToast("Something went wrong. Please try again.");
}
```

💡 Never show raw error to users ❌

---

### ✅ Use

- Large applications
- API-heavy systems
- User-critical flows

---

### ❌ Avoid

- Ignoring errors
- Overusing try-catch everywhere
- Catching errors without handling

## 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Swallowing Errors

```js id="k14ajq"
catch (e) {}
```

👉 This hides bugs completely

---

### ❌ Mistake 2: Not rethrowing

```js id="ytq0m8"
catch (e) {
  console.log(e);
}
```

👉 Sometimes should:

```js id="r7w6bi"
throw e;
```

---

### ❌ Mistake 3: No global handler

👉 Unhandled errors → silent failures

---

### ❌ Mistake 4: Showing raw errors to users

```js id="l6gl6p"
alert(error.stack) ❌
```

## 🔹 Interview Q&A

---

### ❓1. What is error management?

A structured approach to handle, log, and recover from errors in an application.

---

### ❓2. What are layers of error handling?

- Local (try-catch)
- Custom errors
- Global handlers
- Monitoring

---

### ❓3. Why not rely only on try-catch?

Because async/global errors can escape local handling.

---

### ❓4. What is error propagation?

Passing error up the call stack using `throw`.

---

### ❓5. What is centralized error handling?

Handling errors in one place (global handler/logging system).

---

### ❓6. How to handle async errors?

- `try-catch` with `await`
- `.catch()` for promises
- `unhandledrejection` globally

---

### ❓7. Should we show errors to users?

❌ No → show friendly messages

---

### ❓8. What is best practice for logging?

Log errors with context (message, stack, user action)

---

## 🔹 Advantages / Pitfalls

---

### ✅ Advantages

- Prevents crashes
- Improves user experience
- Easier debugging
- Scalable architecture

---

### ❌ Pitfalls

- Over-engineering
- Performance overhead (if misused)
- Hidden bugs if poorly implemented

---

## 🔹 Best Practices

---

✔ Use layered approach (local + global)
✔ Always log errors
✔ Use custom error types
✔ Keep try blocks small
✔ Show user-friendly messages
✔ Re-throw when needed

Error → Local Handling →
If not handled → Global Handler →
