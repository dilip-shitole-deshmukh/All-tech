# 🧠 Error Management in JavaScript

---

## 🔹 Definition

👉 **Simple Definition (2–3 lines):**
Error management is the process of **detecting, handling, and responding to errors** in an application.
It ensures the app doesn’t crash and provides a smooth user experience.

👉 **Deeper Explanation (2–3 lines):**
It includes strategies like **try-catch, custom errors, global handlers, logging, and fallback UI**.
Good error management is not just catching errors—it’s about **handling them correctly at the right level**.

---

# 🔹 Deep Explanation (Core Section)

---

## 1️⃣ Types of Errors (Foundation)

### 🔸 Syntax Errors

- Occur during parsing (before execution)
- Example: missing bracket

💡 Cannot be caught by `try-catch`

---

### 🔸 Runtime Errors

- Occur during execution
- Example: accessing undefined property

💡 Can be handled using try-catch

---

### 🔸 Logical Errors

- Code runs but gives wrong output

💡 Hardest to detect → requires testing

---

## 2️⃣ Local Error Handling (try-catch)

- Used for **specific risky operations**
- Prevents local failures from crashing app

💡 Internals:

- JS engine stops execution of try block
- Jumps to catch

⚠️ Best practice:

- Keep try block small and focused

---

## 3️⃣ Asynchronous Error Handling

- Errors in async code behave differently

### ✅ Promises:

```js
fetch().catch((err) => {});
```

### ✅ async/await:

```js
try {
  await fetch();
} catch (e) {}
```

💡 Why:

- Async runs in event loop → separate execution

---

## 4️⃣ Custom Errors (Structured Handling)

- Create meaningful error types
- Helps categorize issues

💡 Example:

- `ValidationError`, `ApiError`

💡 Why:

- Enables targeted handling

---

## 5️⃣ Global Error Handling (Safety Net)

- Handles uncaught errors

```js
window.onerror;
window.addEventListener("unhandledrejection");
```

💡 Role:

- Last line of defense

⚠️ Not replacement for local handling

---

## 6️⃣ Error Propagation (Bubble Up)

- Errors move up the call stack

💡 Flow:

1. Error occurs
2. If not handled → goes up
3. Eventually reaches global

💡 Important:

- Decide where to handle error

---

## 7️⃣ Error Logging & Monitoring

- Send errors to tools:
  - Sentry
  - LogRocket

💡 Why:

- Track production issues

⚠️ Include:

- stack trace
- user context

---

## 8️⃣ Graceful Degradation (UX)

- Instead of crashing:
  - Show fallback UI
  - Retry option

💡 Example:

- “Something went wrong” screen

---

## 9️⃣ Retry & Recovery Strategies

- Retry failed operations

```js
retry(fetch, 3);
```

💡 Use cases:

- Network failures

⚠️ Avoid infinite retries

---

## 🔟 Centralized Error Handling

- Use middleware / wrapper

💡 Example:

```js
handleError(fn);
```

💡 Why:

- Avoid repetitive try-catch

---

# 🔹 Example(s) with Code

---

## ✅ Example 1: Combined Error Handling

```js
async function getData() {
  try {
    const res = await fetch("invalid-url");
    return await res.json();
  } catch (e) {
    console.error("API Error:", e);
    return null;
  }
}
```

### 🔍 Execution:

1. API call fails
2. Promise rejects
3. catch block executes

💡 WHY:

- await converts rejection to exception

---

## ⚡ Example 2: Custom + Propagation

```js
class ApiError extends Error {}

function fetchData() {
  throw new ApiError("Failed");
}

try {
  fetchData();
} catch (e) {
  if (e instanceof ApiError) {
    console.log("Handled API Error");
  }
}
```

### 🔍 Execution:

1. Error thrown
2. Propagates to catch
3. Handled based on type

💡 WHY:

- instanceof enables filtering

---

## ⚡ Example 3: Global Handler

```js
window.addEventListener("unhandledrejection", (e) => {
  console.log("Global:", e.reason);
});

Promise.reject("Error!");
```

### 🔍 Execution:

- Unhandled rejection triggers handler

💡 WHY:

- No local catch present

# 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Ignoring async errors

- ❌ try-catch handles all
- ✅ Not for promises
- 💡 Use .catch

---

### ❌ Mistake 2: Catching but not handling

- ❌ console.log only
- ✅ Provide fallback
- 💡 UX matters

---

### ❌ Mistake 3: Overusing global handlers

- ❌ Enough alone
- ✅ Needs local handling
- 💡 Layered approach

---

### ❌ Mistake 4: Throwing non-errors

- ❌ throw "error"
- ✅ throw Error
- 💡 Stack trace needed
