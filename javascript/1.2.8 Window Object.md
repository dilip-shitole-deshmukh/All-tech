## 👉 Window Object — Deep-Dive (Interview Ready)

This is a **🟢 Basic / Direct Topic**, but very important in interviews → focus on **core understanding + behavior + common traps**.

---

# 🔹 Definition

- The **Window Object** is the **global object in browsers**.
- It represents the **browser window/tab** and provides access to all global variables, functions, and browser APIs.

👉 Simple way to say in interview:
**“Window is the root object of the browser environment.”**

---

# 🔹 Core Explanation

---

## 🔸 1. Global Object in Browser

### ✅ Explanation

- In browsers, everything at global scope becomes a property of `window`.
- Variables declared with `var` are attached to `window`.

👉 WHY:
Because `window` is the **Global Execution Context object**.

### 💻 Example

```js
var a = 10;
console.log(window.a); // 10 ✅
```

---

## 🔸 2. `this === window` (in Global Scope)

### ✅ Explanation

- In global scope, `this` refers to `window`.
- So `this.a` and `window.a` behave the same.

### 💻 Example

```js
var a = 20;
console.log(this.a); // 20
```

---

## 🔸 3. Not All Variables Attach to Window

### ✅ Explanation

- Variables declared with `let` and `const` do **NOT become properties of window**.
- They are stored in a separate **Script scope**.

### 💻 Example

```js
let b = 30;
console.log(window.b); // undefined ❗
```

👉 Important interview point.

---

## 🔸 4. Window Provides Browser APIs

### ✅ Explanation

- `window` exposes built-in browser features:
  - `setTimeout`, `setInterval`
  - `alert`, `confirm`
  - `fetch`, `localStorage`
  - `document` (DOM access)

👉 WHY:

- It acts as a **bridge between JavaScript and browser features**.

---

## 🔸 5. Window Object is Implicit

### ✅ Explanation

- You don’t need to write `window.` explicitly.
- JS automatically assumes it in global scope.

### 💻 Example

```js
alert("Hello"); // same as window.alert("Hello")
setTimeout(() => {}, 1000); // window.setTimeout
```

---

# 🔹 Important Behavior (Must Know)

---

## 🔸 Global Variables vs Window Properties

```js
var x = 10;
let y = 20;

console.log(window.x); // 10 ✅
console.log(window.y); // undefined ❌
```

👉 WHY:

- `var` → attached to window
- `let/const` → not attached

---

## 🔸 Deleting Variables

```js
var a = 10;
delete window.a; // false ❌

window.b = 20;
delete window.b; // true ✅
```

👉 WHY:

- Variables declared with `var` are non-configurable
- Direct properties can be deleted

---

# 🔹 Real-world Use Cases

- 🔹 Access browser APIs (`localStorage`, `fetch`)
- 🔹 Debugging global variables in console (`window.varName`)
- 🔹 Cross-window communication (`window.open`, `window.postMessage`)
- 🔹 Managing timers (`setTimeout`, `setInterval`)

# 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Thinking all globals are on window

👉 Only `var` attaches, not `let/const`

---

### ❌ Mistake 2: Overusing global variables

👉 Pollutes `window` → hard to debug

---

### ❌ Mistake 3: Ignoring environment differences

👉 In Node.js → no `window`, use `global`

---

# 🔹 Interview Q&A

---

### 1. What is window object?

- It is the global object in browsers.
- Represents browser window and provides APIs.

---

### 2. Is `window` same as global object?

- Yes, in browsers `window` is the global object.
- In Node.js, global object is different (`global`).

---

### 3. What is relation between `this` and window?

- In global scope, `this === window`.
- Inside functions, depends on how function is called.

---

### 4. Do `let` and `const` attach to window?

- ❌ No
- Only `var` attaches to window object.

---

### 5. Why is `window` important?

- It gives access to browser APIs like DOM, timers, storage.
- Acts as root of JavaScript execution in browser.

---

### 6. Can we access `window` explicitly?

- Yes, but usually not needed.
- JS assumes it implicitly.

---

### 7. Difference between `window` and `document`?

- `window` → global object
- `document` → represents HTML DOM

---

### 8. What happens in strict mode?

```js
"use strict";
function test() {
  console.log(this);
}
test(); // undefined ❗
```

👉 `this` is NOT window in strict mode.

# 🔹 Advantages

- ✔ Central access point for browser APIs
- ✔ Simplifies global scope handling
- ✔ Enables interaction with browser environment

---

# 🔹 Best Practices

- ✅ Avoid polluting `window` (minimize global variables)
- ✅ Use modules instead of globals
- ✅ Prefer `let/const` over `var`
- ✅ Use `window` explicitly only when needed

---

# 🔥 Senior-Level Insight

- Excessive use of `window` leads to:
  - Global namespace pollution
  - Hard-to-maintain code
  - Conflicts in large apps

- Modern frameworks (React, Angular):
  - Avoid direct `window` usage
  - Use abstraction layers (services, hooks)
