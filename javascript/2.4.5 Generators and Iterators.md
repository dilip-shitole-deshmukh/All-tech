## 🔄 Generators & Iterators (JavaScript)

> ⚠️ This is a **🟡 Conceptual / Intermediate topic**
> 👉 Interviewers expect: **protocol understanding + how iteration works internally**

---

# 🔹 Definition

### 👉 Iterator

> An **object that defines how to traverse a sequence of values**

- It follows a standard **protocol (`next()` method)**
- Each call returns `{ value, done }`

---

### 👉 Generator

> A **special function (`function*`) that produces an iterator automatically**

- Uses `yield` to pause/resume execution
- Makes writing iterators **easy and readable**

---

# 🔹 Core Explanation

---

## 🧠 1. Iterator Protocol (HOW it works)

👉 An object is an iterator if it has:

```js
{
  next: () => ({ value: any, done: boolean });
}
```

### 💡 Behavior:

- `value` → current item
- `done: true` → iteration finished

---

## 🧠 2. Iterable Protocol

👉 An object is iterable if it has:

```js
obj[Symbol.iterator]();
```

👉 This method returns an **iterator**

---

### 🔥 Example: Built-in iterable

```js
const arr = [1, 2, 3];

const iterator = arr[Symbol.iterator]();

console.log(iterator.next()); // { value: 1, done: false }
```

👉 Arrays, strings, maps → already iterable

---

## 🧠 3. Generators (HOW they simplify things)

---

### 🔹 Syntax

```js
function* gen() {
  yield 1;
  yield 2;
  yield 3;
}
```

👉 Calling `gen()` returns an iterator

---

## 🔹 Example(s) with Code

---

### ✅ Example 1: Basic Generator

```js
function* numbers() {
  yield 1;
  yield 2;
  yield 3;
}

const gen = numbers();

console.log(gen.next());
console.log(gen.next());
console.log(gen.next());
console.log(gen.next());
```

### 🧠 Output:

```text
{ value: 1, done: false }
{ value: 2, done: false }
{ value: 3, done: false }
{ value: undefined, done: true }
```

👉 WHY:

- `yield` pauses function execution
- Resumes from same point on next call

---

### ✅ Example 2: for...of with Generator

```js
function* numbers() {
  yield 10;
  yield 20;
}

for (let num of numbers()) {
  console.log(num);
}
```

👉 Output:

```text
10
20
```

👉 WHY:

- `for...of` uses iterator internally

---

### ✅ Example 3: Passing values to generator (Tricky ⭐)

```js
function* gen() {
  const x = yield 10;
  console.log(x);
}

const g = gen();

g.next(); // starts, pauses at yield
g.next(100); // sends value back
```

👉 Output:

```text
100
```

👉 WHY:

- `next(value)` sends value back to previous `yield`

---

## 🔥 4. Custom Iterator (Manual Implementation)

```js
const myIterable = {
  data: [1, 2, 3],
  [Symbol.iterator]() {
    let index = 0;

    return {
      next: () => {
        if (index < this.data.length) {
          return { value: this.data[index++], done: false };
        }
        return { done: true };
      },
    };
  },
};

for (let val of myIterable) {
  console.log(val);
}
```

👉 Shows how JS iteration works internally

## 🔹 Real-world Use Cases

---

- Load items on demand instead of all at once

### 📡 2. Data Streams

- Handle large datasets efficiently

### 🔁 3. Custom Iteration Logic

## 🔹 When to Use / When NOT to Use

---

### ✅ Use Generators

- When you need lazy execution
- When dealing with large/streaming data
- When building custom iterables

---

### ❌ Avoid

- Simple loops (overkill)
- When async/await is cleaner

---

## ⚠️ Common Mistakes / Traps

---

### ❌ Mistake 1: Thinking generator executes immediately

👉 Reality:

- It executes only when `next()` is called

---

### ❌ Mistake 2: Forgetting `done`

👉 Iterator must return `{ done: true }` at end

---

### ❌ Mistake 3: Confusing `yield` with `return`

```js
function* gen() {
  yield 1;
  return 2;
}
```

👉 Output:

- `2` is NOT iterated in `for...of`

---

### ❌ Mistake 4: Not understanding `next(value)`

👉 Value goes **backward**, not forward

## 🔹 Interview Q&A

---

### ❓1. What is an iterator?

An object with `next()` method returning `{value, done}`

---

### ❓2. What is a generator?

A function that returns an iterator using `yield`

---

### ❓3. Difference between iterable and iterator?

Iterable → has `[Symbol.iterator]`
Iterator → has `next()`

---

### ❓4. How does for...of work?

Uses `[Symbol.iterator]()` internally

---

### ❓5. What does yield do?

Pauses execution and returns value

---

### ❓6. Can generator receive values?

Yes, via `next(value)`

---

### ❓7. Why use generators?

Lazy execution + memory efficient

---

### ❓8. Are generators async?

No (but async generators exist)

---

## 🔹 Advantages / Pitfalls

---

### ✅ Advantages

- Lazy evaluation (memory efficient)
- Cleaner iterator implementation
- Control over execution flow

---

### ❌ Pitfalls

- Harder to understand initially
- Debugging can be tricky
- Overkill for simple tasks

---

## 🔹 Best Practices

---

✔ Use generators for large data processing
✔ Prefer `for...of` for readability
✔ Avoid manual iterator unless needed
✔ Keep generator logic simple
✔ Document behavior clearly

## 🔹 Senior-Level Insights 🚀

---

### ⚡ Performance

👉 Generators are **lazy**

```text
Only compute when needed → saves memory
```

👉 Useful in:

- Pagination
- Infinite scroll

---

### 🧠 Internal Mechanism

👉 Generator maintains:

```text
Execution context + state (paused/resumed)
```

👉 Unlike normal functions → don’t run completely

---

### 🔁 Generator vs Async/Await

| Feature | Generator | Async/Await |
| ------- | --------- | ----------- |
| Control | Manual    | Automatic   |
| Use     | Iteration | Async code  |

---

### 🔥 Advanced: Async Generators

```js
async function* gen() {
  yield await fetchData();
}
```

👉 Used with:

```js
for await (const val of gen()) {
}
```
