## 👉 Pure and Impure Functions

---

## 🔹 Definition

### ✅ Pure Function

👉 A **pure function** is a function that:

1. Always returns the **same output for the same input**
2. Has **no side effects** (does not modify external state)

📌 Simple:

> Input fixed → Output fixed → No external impact

---

### ❌ Impure Function

👉 An **impure function**:

- May return **different outputs for same input**, OR
- Causes **side effects** (modifies outside state, DOM, API calls, etc.)

📌 Simple:

> Depends on or changes something outside itself

---

## 🔹 Core Explanation

### 🧠 1. Deterministic Nature (Pure Functions)

- Pure functions are **predictable** — same input → same result every time.
- This makes them easy to test and debug because no hidden dependencies exist.

💡 Example idea:
`add(2, 3)` will **always** return `5`, no matter when or where it's called.

---

### ⚠️ 2. Side Effects (Impure Functions)

- Side effects = any interaction with the outside world:
  - Modifying global variables
  - DOM manipulation
  - API calls
  - Console logs (technically)

💡 These make functions **harder to predict and test**.

---

### 🔄 3. Hidden Dependencies

- Impure functions often depend on **external variables or state**.
- If that external state changes, output changes — even with same inputs.

```js
let count = 0;

function increment() {
  count++;
  return count;
}
```

👉 Output depends on external `count` → impure

---

### 🧩 4. Immutability Connection

- Pure functions usually **do not mutate data**.
- Instead of modifying existing objects, they return **new ones**.

```js
// ❌ Impure
function addItem(arr, item) {
  arr.push(item);
  return arr;
}

// ✅ Pure
function addItem(arr, item) {
  return [...arr, item];
}
```

💡 This is heavily used in React & Redux.

---

## 🔹 Example(s) with Code

### ✅ Example 1: Pure Function

```js
function multiply(a, b) {
  return a * b;
}

console.log(multiply(2, 3)); // 6
```

🧩 **Why pure?**

- No external dependency
- Same inputs → same output
- No side effects

---

### ❌ Example 2: Impure Function

```js
let tax = 0.2;

function calculatePrice(price) {
  return price + price * tax;
}
```

🧩 **Why impure?**

- Depends on external variable `tax`
- If `tax` changes → output changes

---

### ⚠️ Tricky Example

```js
function getRandomNumber() {
  return Math.random();
}
```

👉 Looks simple but **impure**

🧩 **Why?**

- Same input (none) → different output each time
- Not deterministic

---

## 🔹 Real-world Use Cases

### 🌐 1. React State Updates

- React prefers **pure functions** for predictable UI updates
- Reducers in Redux must be pure

```js
function reducer(state, action) {
  return { ...state, count: state.count + 1 };
}
```

---

### 🔄 2. Data Transformation

- Functions like `map`, `filter`, `reduce` rely on pure callbacks
- Ensures consistent transformation

---

### ⚙️ 3. Business Logic

- Calculations, validations → should be pure
- Easy to test and reuse

---

## 🔹 When to Use / When NOT to Use

### ✅ Use Pure Functions When:

- Writing **business logic**
- Working with **state management (React/Redux)**
- You need **predictable, testable code**

---

### ❌ Impure Functions Are Necessary When:

- Interacting with:
  - APIs
  - Database
  - DOM
  - Timers

💡 You cannot avoid impurity completely — just **control it**

---

## 🔹 Common Mistakes / Traps

### ❌ Mistake 1: Thinking console.log is harmless

```js
function logValue(x) {
  console.log(x);
  return x;
}
```

👉 This is **impure** (side effect: logging)

---

### ❌ Mistake 2: Mutating objects

```js
function updateUser(user) {
  user.name = "New";
  return user;
}
```

👉 Mutates original object → impure

---

### ❌ Mistake 3: Using Date/Random unknowingly

```js
function getTime() {
  return new Date();
}
```

👉 Different result each time → impure

## 🔹 Interview Q&A

### ❓1. What is a pure function?

👉 A function with no side effects and deterministic output — same input always produces same output.

---

### ❓2. Why are pure functions important?

👉 They are predictable, easy to test, and reduce bugs because they don’t depend on external state.

---

### ❓3. Is `Math.random()` pure?

👉 No, because it produces different output for the same input (non-deterministic).

---

### ❓4. Are all impure functions bad?

👉 No. Side effects are necessary (API calls, DOM updates), but should be isolated.

---

### ❓5. What is a side effect?

👉 Any operation that affects or depends on external state (e.g., modifying variables, API calls).

---

### ❓6. Why Redux reducers must be pure?

👉 To ensure predictable state updates and enable features like time-travel debugging.

---

### ❓7. Is modifying input parameter allowed in pure functions?

👉 No. Pure functions should not mutate inputs; they should return new values.

---

### ❓8. Can a function be partially pure?

👉 Not really — if it has even one side effect, it's considered impure.

---

## 🔹 Advantages / Pitfalls

### ✅ Advantages of Pure Functions

- Easy to test (no mocks needed)
- Predictable behavior
- Easier debugging
- Better for parallel execution

---

### ⚠️ Pitfalls

- Sometimes require **extra memory** (due to immutability)
- Can feel verbose when copying objects/arrays

---

## 🔹 Best Practices

✔ Keep business logic pure
✔ Isolate side effects (API, DOM)
✔ Avoid mutating inputs
✔ Use immutability (`...spread`, `Object.assign`)
✔ Combine with HOFs (`map`, `filter`)

---

## 🔹 Senior-Level Insights

### ⚡ 1. Separation of Concerns

- Good architecture separates:
  - **Pure logic layer** (calculations)
  - **Impure layer** (API/DOM)

💡 Example: React → UI triggers → service layer handles API

---

### ⚡ 2. Performance Trade-off

- Immutability creates **new objects**, which may impact performance
- But enables optimizations like:
  - React’s shallow comparison
  - Memoization (`useMemo`)

---

### ⚡ 3. Testability & Scalability

- Pure functions scale better in large codebases
- Easier to write unit tests without mocking external dependencies

---

## ✅ Final Summary

👉 **Pure Function** = predictable + no side effects
👉 **Impure Function** = depends on or changes external state

💡 Rule of thumb:

> “Keep your logic pure, isolate your side effects.”
