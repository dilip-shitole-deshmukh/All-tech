## 🧠 `Promise.all()` (JavaScript)

> ⚠️ This is a **🟡 Conceptual + Practical async topic** → focus on **parallel execution + failure behavior**

---

## 🔹 Definition

`Promise.all()` is a method that takes an **array of promises** and returns a **single promise**.

👉 In simple terms:

> “Run multiple async tasks in parallel and wait for all of them to complete”

💡 If all succeed → returns results
💡 If any fails → fails immediately

---

## 🔹 Core Explanation

---

## 🟢 1. Basic Working

```js
Promise.all([promise1, promise2, promise3]);
```

🧠 Behavior:

- Runs all promises **in parallel**
- Waits until **all are resolved**
- Returns an array of results

👉 Order of results = order of input (not completion order)

---

## 🔵 2. Success Case

```js
const p1 = Promise.resolve(1);
const p2 = Promise.resolve(2);
const p3 = Promise.resolve(3);

Promise.all([p1, p2, p3]).then((results) => console.log(results));
```

🧠 Output:

```text
[1, 2, 3]
```

👉 WHY:

- All promises resolved successfully
- Results collected in array

---

## 🔴 3. Failure Behavior (Important 🔥)

```js
const p1 = Promise.resolve(1);
const p2 = Promise.reject("Error!");
const p3 = Promise.resolve(3);

Promise.all([p1, p2, p3])
  .then(console.log)
  .catch((err) => console.log(err));
```

🧠 Output:

```text
Error!
```

👉 WHY:

- As soon as one promise rejects → `Promise.all` rejects
- Remaining promises are ignored

💡 This is called **fail-fast behavior**

---

## 🟡 4. Parallel Execution (Performance Key 🔥)

```js
// ❌ Sequential (slow)
const a = await fetchA();
const b = await fetchB();
```

```js
// ✅ Parallel (fast)
const [a, b] = await Promise.all([fetchA(), fetchB()]);
```

🧠 WHY:

- Both requests start at same time
- Total time = max(duration), not sum

---

## 🔹 Example(s) with Code

---

### ✅ Example 1: API Calls

```js
async function loadData() {
  const [users, posts] = await Promise.all([
    fetch("/users").then((res) => res.json()),
    fetch("/posts").then((res) => res.json()),
  ]);

  console.log(users, posts);
}
```

👉 Faster than sequential fetching

---

### ⚠️ Example 2: Order Guarantee

```js
const p1 = new Promise((res) => setTimeout(() => res("A"), 2000));
const p2 = new Promise((res) => setTimeout(() => res("B"), 1000));

Promise.all([p1, p2]).then(console.log);
```

🧠 Output:

```text
["A", "B"]
```

👉 Even though `p2` finishes first → order is preserved

---

### ⚠️ Example 3: Non-Promise Values

```js
Promise.all([1, Promise.resolve(2), 3]).then(console.log);
```

🧠 Output:

```text
[1, 2, 3]
```

👉 Non-promises are wrapped as resolved promises

## 🔹 When to Use / When NOT to Use

---

### ✅ Use `Promise.all`

- Tasks are **independent**
- Need **all results**
- Want **performance optimization**

---

### ❌ Avoid

- When one failure should NOT stop others
  👉 Use:

```js
Promise.allSettled();
```

---

## 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Sequential awaits

👉 Missing performance optimization

---

### ❌ Mistake 2: Not handling rejection

👉 Entire chain fails

---

### ❌ Mistake 3: Dependent tasks

```js
await Promise.all([step1(), step2()]); // ❌ if step2 depends on step1
```

---

### ❌ Mistake 4: Assuming execution order

👉 Execution is parallel, not sequential

## 🔹 Interview Q&A

---

### ❓1. What is `Promise.all()`?

Runs multiple promises in parallel

---

### ❓2. What does it return?

A single Promise

---

### ❓3. What happens if one fails?

Whole Promise rejects immediately

---

### ❓4. Does order change?

No, result order is preserved

---

### ❓5. When to use it?

Parallel async operations

---

### ❓6. Difference from `Promise.allSettled()`?

`all` → fails fast
`allSettled` → waits for all

---

### ❓7. Can it take non-promises?

Yes, auto-wrapped

---

### ❓8. Performance benefit?

Reduces total execution time

---

## 🔹 Advantages / Pitfalls

---

### ✅ Advantages

- Faster execution
- Cleaner async handling
- Parallel processing

---

### ❌ Pitfalls

- Fail-fast behavior
- Hard to debug multiple failures
- Not suitable for dependent tasks

---

## 🔹 Best Practices

---

✔ Use for independent tasks
✔ Combine with async/await
✔ Handle errors properly
✔ Use `allSettled` if needed
✔ Avoid mixing with sequential logic

## 🔹 Senior-Level Insights 🚀

---

### ⚡ Fail-Fast Trade-off

👉 Good for:

- Critical operations

👉 Bad for:

- Partial success scenarios

---

### 🧠 Microtask Behavior

- `.then()` runs in **microtask queue**
- Faster than macrotasks

---

### 🔄 Comparison

| Method               | Behavior      |
| -------------------- | ------------- |
| `Promise.all`        | Fail fast     |
| `Promise.allSettled` | Wait all      |
| `Promise.race`       | First settled |
| `Promise.any`        | First success |

---

### 🚀 Performance Thinking

❌ Bad:

```js
await api1();
await api2();
await api3();
```

✅ Good:

```js
await Promise.all([api1(), api2(), api3()]);
```
