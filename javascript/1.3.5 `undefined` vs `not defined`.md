# 🧠 `undefined` vs `not defined` (JavaScript)

---

## 🔹 Definition

👉 **Simple Definition:**

- **`undefined`** means a variable **exists but has no value assigned**.
- **`not defined`** means the variable **does not exist at all in the current scope**.

👉 **Slightly Deeper:**

- `undefined` is a **type + value** provided by JavaScript during memory allocation (hoisting phase).
- `not defined` is actually a **ReferenceError**, thrown when JS cannot find a variable in the **scope chain**.

---

# 🔹 Deep Explanation (Core Section)

---

## 1️⃣ `undefined` (Value exists, but not assigned)

### 🧠 What it is

- A special primitive value automatically assigned by JS.
- Happens when a variable is declared but not initialized.

### ⚙️ Internal working

- During **creation phase (hoisting)**:
  - JS allocates memory
  - Assigns `undefined` as default value

```js
var a;
console.log(a); // undefined
```

---

### 💡 Why it behaves this way

- Ensures variables exist in memory before execution
- Prevents runtime crashes due to missing declarations

---

### ⚠️ Edge cases

- Function with no return → returns `undefined`
- Missing object property → `undefined`

---

## 2️⃣ `not defined` (Variable doesn’t exist ❌)

### 🧠 What it is

- Occurs when JS cannot find variable in:

  ```
  Local → Parent → Global scope
  ```

### ⚙️ Internal behavior

- JS searches scope chain
- If not found → throws **ReferenceError**

```js
console.log(a); // ReferenceError: a is not defined
```

---

### 💡 Why it behaves this way

- Prevents accidental use of undeclared variables
- Helps catch bugs early

---

### ⚠️ Edge case

- Happens even if variable exists in another file/module (scope isolation)

---

## 3️⃣ Key Difference (VERY IMPORTANT 🔥)

| Feature          | undefined            | not defined        |
| ---------------- | -------------------- | ------------------ |
| Exists in memory | ✅ Yes               | ❌ No              |
| Type             | Primitive value      | ReferenceError     |
| Created by       | JS engine (hoisting) | Runtime error      |
| Safe to access   | ✅ Yes               | ❌ Crashes program |

---

## 4️⃣ Hoisting Connection 🔥

### 🧠 Why `undefined` appears

```js
console.log(a);
var a = 10;
```

### 🔍 Execution:

1. Creation phase:
   - `a = undefined`

2. Execution:
   - `console.log(a)` → undefined

👉 NOT "not defined"

💡 WHY:
Variable exists due to hoisting

---

## 5️⃣ Scope Chain Role

### 🧠 Example:

```js
function test() {
  console.log(a);
}
test();
```

👉 Output: ReferenceError

### 💡 WHY:

- `a` not in local
- not in parent
- not in global

→ not defined

---

## 6️⃣ `typeof` Trick (INTERVIEW FAVORITE 🔥)

```js
console.log(typeof a);
```

👉 Output: `"undefined"` (NOT error)

### 💡 WHY:

- `typeof` safely checks variable existence
- Special behavior → avoids ReferenceError

---

# 🔹 Example(s) with Code

---

## ✅ Example 1: undefined (Declared but not assigned)

```js
var a;
console.log(a);
```

👉 Output:

```js
undefined;
```

### 🔍 WHY:

- `a` exists in memory
- No value assigned → default `undefined`

---

## ⚡ Example 2: not defined (Variable doesn’t exist)

```js
console.log(b);
```

👉 Output:

```js
ReferenceError: b is not defined
```

### 🔍 WHY:

- JS cannot find `b` anywhere in scope chain

---

## 🔥 Example 3: Hoisting Confusion

```js
console.log(a);
var a = 5;
```

👉 Output:

```js
undefined;
```

### 🔍 WHY:

- Hoisting makes `a` exist
- Value assigned later

---

## 🔥 Example 4: let/const (TDZ trap)

```js
console.log(x);
let x = 10;
```

👉 Output:

```js
ReferenceError;
```

### 💡 WHY:

- `let` is hoisted BUT in TDZ
- Access before initialization → error (similar to not defined behavior)

---

✅ Use `let/const` instead of `var`
→ avoid hoisting confusion

→ precise checks

✅ Use `typeof` for undeclared variables
→ safe checks

✅ Avoid assigning undefined manually
→ use null instead

# 🔹 Senior-Level Insights

---

### 🧠 Performance

- Accessing undefined is cheap
- Errors (not defined) break execution → costly

---

### 🧠 Memory Behavior

- undefined variables still occupy memory
- not defined → no allocation

---

### 🧠 Scalability

- Poor handling → bugs in large apps
- Use optional chaining & defaults

---

### 🧠 Trade-offs

- undefined (safe but ambiguous)
- explicit null (clear intent)
