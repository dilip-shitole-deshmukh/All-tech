## 👉 `undefined` vs `not defined` — Deep-Dive (Interview Ready)

This is a **🟡 Conceptual / Intermediate Topic** → interviewers expect **clear difference + hoisting relation + error behavior**.

---

# 🔹 Definition

### ✅ `undefined`

- A variable is **declared but not assigned a value**.
- JavaScript **knows the variable exists**, but it has no value yet.

---

### ❌ `not defined`

- A variable is **never declared in the current scope**.
- Accessing it results in a **ReferenceError**.

👉 Simple interview line:
**“`undefined` means declared but no value, while `not defined` means the variable doesn’t exist at all.”**

---

# 🔹 Core Difference (Must Remember)

| Feature           | `undefined` | `not defined`     |
| ----------------- | ----------- | ----------------- |
| Declaration       | ✅ Declared | ❌ Not declared   |
| Memory Allocation | ✅ Yes      | ❌ No             |
| Value             | `undefined` | ❌ No value       |
| Error             | ❌ No error | ✅ ReferenceError |
| Hoisting          | ✅ Yes      | ❌ No             |

---

# 🔹 Core Explanation (HOW + WHY)

---

## 🔸 1. Why `undefined` Happens

### ✅ Explanation

- During **creation phase (hoisting)**, JS allocates memory for variables.
- Variables declared with `var` are initialized with `undefined`.

👉 WHY:

- JS needs placeholder before actual assignment.

---

## 🔸 2. Why `not defined` Happens

### ✅ Explanation

- When JS tries to access a variable that was **never declared**, it throws an error.
- No memory is allocated → JS cannot resolve it in scope chain.

---

# 🔹 Example 1 (Basic Difference)

### 💻 Code

```js id="x8yq0d"
var a;
console.log(a); // undefined ✅
```

👉 `a` is declared → exists in memory → value is undefined

---

```js id="2mdm3m"
console.log(b); // ❌ ReferenceError: b is not defined
```

👉 `b` does not exist → JS throws error

---

# 🔹 Example 2 (Hoisting Behavior)

### 💻 Code

```js id="7gdvzg"
console.log(x);
var x = 10;
```

### 🔍 Output

```
undefined
```

### 🔍 WHY?

- During creation phase:

```js id="e8pq9c"
x → undefined
```

- Then execution assigns `x = 10`

---

# 🔹 Example 3 (`let` and `const` Case)

```js id="7r9l9h"
console.log(a);
let a = 10;
```

👉 ❌ ReferenceError (NOT undefined)

### 🔍 WHY?

- `let/const` are in **Temporal Dead Zone (TDZ)**
- They are hoisted but **not initialized**

👉 Important:

- This is **different from "not defined"**, but behavior looks similar

---

# 🔹 Tricky / Edge Cases

---

## ⚠️ Case 1: typeof Behavior

```js id="ek4qcc"
console.log(typeof a); // "undefined"
console.log(typeof b); // "undefined" ❗
```

👉 Even if `b` is not defined → no error

👉 WHY:

- `typeof` is safe operator

---

## ⚠️ Case 2: Function Parameters

```js id="dzj3ox"
function test(a) {
  console.log(a);
}

test(); // undefined
```

👉 Parameter exists but no value passed

---

## ⚠️ Case 3: Missing Object Property

```js id="mxwxq7"
const obj = {};
console.log(obj.name); // undefined
```

👉 Property doesn’t exist → returns undefined (NOT error)

# 🔹 Interview Q&A

---

### 1. What is `undefined`?

- A variable declared but not assigned value.
- JS sets it automatically during hoisting.

---

### 2. What is `not defined`?

- Variable not declared anywhere.
- Accessing it throws ReferenceError.

---

### 3. Why does `var` show undefined?

- Due to hoisting → initialized with undefined.
- Memory is allocated before execution.

---

### 4. What happens with `let/const`?

- They are hoisted but not initialized.
- Accessing before declaration → ReferenceError (TDZ).

---

### 5. Is `typeof` safe for undefined variables?

- Yes, it doesn’t throw error.
- Always returns `"undefined"`.

---

### 6. Is missing object property undefined?

- Yes, accessing non-existing property returns undefined.
- No error occurs.

---

### 7. Difference between undefined and null?

- `undefined` → default by JS
- `null` → explicitly assigned

---

### 8. Can we assign undefined manually?

- Yes, but not recommended.
- Better use `null` intentionally.
