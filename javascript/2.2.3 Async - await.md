## 🧠 Async / Await (JavaScript)

> ⚠️ This is a **🟡 Conceptual + Practical Async topic** → focus on **how it simplifies Promises + execution behavior**

---

## 🔹 Definition

`async/await` is a **syntactic sugar over Promises** that allows writing asynchronous code in a **synchronous-looking way**.

👉 In simple terms:

> “It makes async code look like normal step-by-step code”

💡 It improves:

- Readability
- Error handling
- Maintainability

---

## 🔹 Core Explanation

---

## 🟢 1. `async` Function

```js
async function getData() {
  return "Hello";
}
```

🧠 Key Points:

- Always returns a **Promise**
- Even if you return a normal value → it becomes `Promise.resolve(value)`

👉 Equivalent:

```js
Promise.resolve("Hello");
```

---

## 🔵 2. `await` Keyword

```js
const data = await fetchData();
```

🧠 How it works:

- Pauses execution of async function
- Waits until Promise resolves/rejects
- Then continues execution

👉 Only works inside `async` functions

---

## 🟡 3. Execution Flow (Important 🔥)

```js
console.log("Start");

async function test() {
  console.log("Inside");
  await Promise.resolve();
  console.log("After await");
}

test();

console.log("End");
```

🧠 Output:

```text
Start
Inside
End
After await
```

👉 WHY:

- `await` pauses function
- Rest goes to **microtask queue**

---

## 🔁 4. Sequential vs Parallel Execution

---

### ❌ Sequential (Slow)

```js
const a = await fetchA();
const b = await fetchB();
```

👉 Executes one after another

---

### ✅ Parallel (Optimized)

```js
const [a, b] = await Promise.all([fetchA(), fetchB()]);
```

👉 Runs both simultaneously

💡 Important for performance

---

## 🔥 5. Error Handling with try/catch

```js
async function getData() {
  try {
    const res = await fetch("/api");
    const data = await res.json();
    console.log(data);
  } catch (err) {
    console.log("Error:", err);
  }
}
```

🧠 WHY:

- Cleaner than `.catch()` chaining
- Works like synchronous error handling

## 🔹 Example(s) with Code

---

### ✅ Example 1: Basic Usage

```js
function fetchData() {
  return new Promise((resolve) => {
    setTimeout(() => resolve("Data"), 1000);
  });
}

async function main() {
  const result = await fetchData();
  console.log(result);
}

main();
```

---

### ⚠️ Example 2: Missing await

```js
async function test() {
  const data = fetchData(); // ❌ missing await
  console.log(data);
}
```

👉 Output:

```text
Promise { <pending> }
```

💡 Because promise not resolved yet

---

### ⚠️ Example 3: Multiple awaits issue

```js
await fetchA();
await fetchB();
await fetchC();
```

👉 Slow execution

💡 Better:

```js
await Promise.all([fetchA(), fetchB(), fetchC()]);
```

## 🔹 When to Use / When NOT to Use

---

### ✅ Use async/await

- Complex async flows
- Readability required
- Error handling needed

---

### ❌ Avoid

- Simple one-liner promises
- Blocking multiple independent calls

---

## 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Forgetting `await`

👉 Leads to unresolved Promise

---

### ❌ Mistake 2: Using await outside async

```js
await fetch(); // ❌ error
```

---

### ❌ Mistake 3: Sequential awaits

👉 Performance issue

---

### ❌ Mistake 4: Not handling errors

👉 Causes unhandled rejection

---

### ❌ Mistake 5: Thinking it blocks JS thread

👉 It **does NOT block thread**

```text
Call Stack → Microtask Queue → Macrotask Queue
```
