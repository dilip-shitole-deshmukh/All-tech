# 🔹 Definition

# 🔹 Core Weird Behaviors (Must Know)

---

## ⚡ 1. `[] + []` → `""`

```js
[] + [];
```

👉 Output:

```js
"";
```

---

### 🧠 WHY:

- `[]` → converted to `""` (string)
- So:

```js
"" + "" → ""
```

---

💡 Key concept:

> Arrays convert to string using `.toString()`

---

---

## ⚡ 2. `[] + {}` vs `{}` + []

```js
[] + {}; // "[object Object]"
{
}
+[]; // 0
```

---

### 🧠 WHY:

👉 Case 1:

```js
[] → ""
{} → "[object Object]"
```

👉 Result:

```js
"" + "[object Object]";
```

---

👉 Case 2:

- `{}` treated as block
- `+[] → 0`

---

💡 Key concept:

> JS parsing rules + type coercion

---

---

## ⚡ 3. `null == undefined` → true

```js
null == undefined; // true
null === undefined; // false
```

---

### 🧠 WHY:

- Loose equality (`==`) → special rule
- Strict equality (`===`) → no conversion

---

💡 Rule:

> Only `null` and `undefined` are loosely equal

---

---

## ⚡ 4. `NaN !== NaN`

```js
NaN === NaN; // false
```

---

### 🧠 WHY:

- `NaN` means “not a number”
- It’s not equal to anything (even itself)

---

👉 Correct way:

```js
Number.isNaN(NaN); // true
```

---

---

## ⚡ 5. `typeof null === "object"`

```js
typeof null; // "object"
```

---

### 🧠 WHY:

- Historical bug in JS
- Never fixed for backward compatibility

---

---

## ⚡ 6. `0.1 + 0.2 !== 0.3`

```js
0.1 + 0.2; // 0.30000000000000004
```

---

### 🧠 WHY:

- Floating-point precision issue (binary representation)

---

💡 Fix:

```js
(0.1 + 0.2).toFixed(2); // "0.30"
```

---

---

## ⚡ 7. Truthy & Falsy Values

```js
Boolean([]); // true
Boolean({}); // true
Boolean(""); // false
Boolean(0); // false
```

---

### 🧠 WHY:

👉 Only 6 falsy values:

- false
- 0
- ""
- null
- undefined
- NaN

---

---

## ⚡ 8. `==` vs `===`

```js
"5" == 5; // true
"5" === 5; // false
```

---

### 🧠 WHY:

- `==` → type coercion
- `===` → strict comparison

---

💡 Rule:

> Always prefer `===`

---

---

## ⚡ 9. Hoisting Weirdness

```js
console.log(a);
var a = 10;
```

👉 Output:

```js
undefined;
```

---

### 🧠 WHY:

- `var` is hoisted
- Initialized as `undefined`

---

---

## ⚡ 10. `this` Behavior

```js
const obj = {
  name: "Dilip",
  getName: function () {
    return this.name;
  },
};
```

👉 Works as expected

---

```js
const fn = obj.getName;
fn(); // undefined
```

---

### 🧠 WHY:

- `this` depends on call context

# 🔹 Best Practices

✔ Always use `===`
✔ Use `Number.isNaN()`
✔ Avoid implicit coercion
✔ Be careful with `this`
✔ Use strict mode (`"use strict"`)
