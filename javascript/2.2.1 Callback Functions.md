## 🧠 Callback Functions (JavaScript)

> ⚠️ This is a **🟡 Conceptual / Core JS topic** → focus on **WHAT + WHY + HOW + async behavior**

---

## 🔹 Definition

A **callback function** is a function that is **passed as an argument to another function** and is executed later.

👉 In simple terms:

> “A function you give to someone else to call when needed”

💡 JavaScript uses callbacks heavily because it is **asynchronous and event-driven**

---

## 🔹 Core Explanation

---

## 🟢 1. Basic Concept (Synchronous Callback)

```js
function greet(name, callback) {
  console.log("Hello " + name);
  callback();
}

function sayBye() {
  console.log("Bye!");
}

greet("Dilip", sayBye);
```

🧠 Execution Flow:

1. `greet` is called
2. Prints `"Hello Dilip"`
3. Calls `callback()` → `sayBye()`
4. Prints `"Bye!"`

👉 WHY:

- Functions are **first-class citizens** (can be passed like variables)

---

## 🔵 2. Asynchronous Callback (Important 🔥)

```js
console.log("Start");

setTimeout(() => {
  console.log("Callback executed");
}, 1000);

console.log("End");
```

🧠 Output:

```text
Start
End
Callback executed
```

👉 WHY:

- `setTimeout` is async → callback goes to **Web API → Callback Queue**
- Event loop executes it later

💡 This is where callbacks become powerful

---

## 🟡 3. Why Callbacks Exist

👉 JavaScript is:

- Single-threaded
- Non-blocking

👉 So callbacks help:

- Handle async operations
- Avoid blocking main thread

---

## 🔁 4. Callback in Array Methods

```js
[1, 2, 3].map((num) => num * 2);
```

🧠 WHY:

- `map` internally calls your callback for each element

👉 Same with:

- `forEach`
- `filter`
- `reduce`

---

## 🔥 5. Callback Hell (Major Problem)

```js
getData(function (a) {
  getMoreData(a, function (b) {
    getMoreData(b, function (c) {
      console.log(c);
    });
  });
});
```

😵 Problem:

- Deep nesting
- Hard to read & maintain

👉 Known as **"Pyramid of Doom"**

---

## 🔹 Example(s) with Code

---

### ✅ Example 1: Simple Callback

```js
function process(num, callback) {
  return callback(num);
}

const result = process(5, (x) => x * 2);

console.log(result); // 10
```

---

### ✅ Example 2: Event Callback

```js
button.addEventListener("click", () => {
  console.log("Clicked!");
});
```

👉 Browser calls your callback when event happens

---

### ⚠️ Example 3: Async Issue

```js
let data;

setTimeout(() => {
  data = "Loaded";
}, 1000);

console.log(data); // undefined ❌
```

👉 WHY:

- Callback runs later
- JS doesn't wait

## 🔹 Senior-Level Insights 🚀

---

### ⚡ Event Loop Connection

👉 Callback execution depends on:

- Call Stack
- Callback Queue
- Event Loop

---

### 🧠 Inversion of Control Problem

```js
apiCall(callback);
```

👉 You don’t control:

- When callback runs
- How many times it runs

---

### 🔄 Evolution Path

```text
Callbacks → Promises → Async/Await
```

👉 Modern JS prefers async/await

---

### ⚖️ Trade-offs

| Feature     | Pros        | Cons                            |
| ----------- | ----------- | ------------------------------- |
| Callback    | Simple      | Hard to scale                   |
| Promise     | Better flow | Slight complexity               |
| Async/Await | Clean       | Requires understanding promises |
