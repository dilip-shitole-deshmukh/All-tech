# 🧠 Conditionals in JavaScript

---

## 🔹 Definition

👉 **Simple Definition (2–3 lines):**
Conditionals are control flow statements used to execute different blocks of code based on conditions.
They help programs make decisions dynamically.

👉 **Deeper Explanation (2–3 lines):**
JavaScript evaluates expressions to **truthy/falsy values** and decides which branch to execute.
Main constructs include `if`, `else if`, `else`, and `switch`.

---

# 🔹 Deep Explanation (Core Section)

---

## 1️⃣ `if` Statement (Basic Decision Making)

- Executes a block if condition evaluates to **true**.
- If condition is false → block is skipped.

💡 Internals:

- JS converts condition using **ToBoolean conversion**
- Non-boolean values → coerced into truthy/falsy

```js
if ("hello") {
} // truthy
```

⚠️ Edge Case:

- `if (0)` → false
- `if ([])` → true

---

## 2️⃣ `else if` and `else` (Multiple Branching)

- `else if` allows multiple conditions
- `else` acts as fallback

💡 How it works:

- Conditions evaluated **top → bottom**
- First true condition executes → rest ignored

⚠️ Edge Case:

```js
if (true) {
} else if (true) {
} // never runs
```

---

## 3️⃣ Truthy & Falsy (VERY IMPORTANT)

Falsy values:

```js
(false, 0, -0, "", null, undefined, NaN);
```

Everything else → truthy

💡 Why important:

- Many bugs come from implicit coercion

⚠️ Example:

```js
if ("0") // true
if (0)   // false
```

---

## 4️⃣ `switch` Statement (Structured Matching)

- Used for multiple fixed-value comparisons
- Cleaner than multiple `if-else`

```js
switch (value) {
  case 1:
    break;
}
```

💡 Internals:

- Uses **strict equality (`===`)**
- Compares case values sequentially

---

## 5️⃣ Fallthrough in `switch` (Tricky)

```js
switch (x) {
  case 1:
    console.log("one");
  case 2:
    console.log("two");
}
```

💡 Output (if x=1):

```
one
two
```

💡 Why:

- No `break` → execution continues

---

## 6️⃣ Block Scope with Conditionals

```js
if (true) {
  let a = 10;
}
```

- `let` and `const` are block-scoped
- `var` is function-scoped

⚠️ Edge Case:

```js
if (true) {
  var x = 10;
}
console.log(x); // 10
```

---

## 7️⃣ Ternary Operator (Shortcut)

```js
condition ? value1 : value2;
```

- Compact alternative to `if-else`

💡 Use when:

- Simple conditions

⚠️ Avoid:

- Nested ternary → hard to read

---

## 8️⃣ Short-Circuiting (`&&`, `||`)

```js
isLoggedIn && showDashboard();
```

- `&&` → executes if left is truthy
- `||` → returns first truthy value

💡 Internals:

- Doesn’t return boolean → returns actual value

# 🔹 Example(s) with Code

---

## ✅ Example 1: Truthy/Falsy

```js
if ("0") {
  console.log("Yes");
}
```

### 🔍 Execution:

1. `"0"` is string → truthy
2. Condition becomes true

💡 Output:

```js
Yes;
```

💡 WHY:

- Non-empty string is truthy

---

## ⚡ Example 2: `switch` Fallthrough

```js
const x = 1;

switch (x) {
  case 1:
    console.log("One");
  case 2:
    console.log("Two");
    break;
}
```

### 🔍 Execution:

1. Matches case 1
2. No break → continues
3. Executes case 2

💡 Output:

```js
One;
Two;
```

💡 WHY:

- Switch doesn’t auto-break

---

## ⚡ Example 3: Tricky Coercion

```js
if ([] == false) {
  console.log("True");
}
```

### 🔍 Execution:

1. `[] == false` → true
2. Due to type coercion

💡 Output:

```js
True;
```

💡 WHY:

- `[] → "" → 0`, so `0 == 0`

# 🔹 When to use? (Why, Where, How)

---

✔️ Use `if-else`:

- Complex conditions
- Multiple logical checks

✔️ Use `switch`:

- Multiple fixed values
- Better readability

✔️ Use ternary:

- Simple conditions

---

# 🔹 When NOT to use

---

❌ Avoid nested `if`:

- Hard to read and maintain

❌ Avoid complex ternary:

- Reduces readability

❌ Avoid switch without break:

- Leads to bugs

---

# 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Confusing truthy/falsy

- ❌ `"0"` is false
- ✅ It’s true
- 💡 Only empty string is false

---

### ❌ Mistake 2: Missing break in switch

- ❌ Only one case runs
- ✅ Fallthrough happens
- 💡 Default behavior

---

### ❌ Mistake 3: Using `==`

- ❌ Loose equality safe
- ✅ Causes coercion bugs
- 💡 Prefer `===`

---

### ❌ Mistake 4: Assignment in condition

```js
if (x = 10)
```

- ❌ Comparison
- ✅ Assignment
- 💡 Always true

# 🔹 10+ Interview Q&A

---

### 1. What are conditionals?

Statements used to control execution based on conditions.

---

### 2. What is truthy/falsy?

Values converted to boolean in conditions.

---

### 3. Difference between `==` and `===`?

`==` allows coercion; `===` checks type + value.

---

### 4. When to use switch?

When comparing a variable against multiple values.

---

### 5. What is fallthrough?

Execution continues to next case without break.

---

### 6. Is switch faster than if?

Not significantly; readability matters more.

---

### 7. What is ternary operator?

Shortcut for simple if-else.

---

### 8. What is short-circuiting?

Logical operators returning values without evaluating full expression.

---

### 9. Are empty arrays falsy?

No, they are truthy.

---

### 10. Can conditionals return values?

Yes, especially with ternary and logical operators.

---

### 11. Why avoid nested conditions?

Reduces readability and increases bugs.
