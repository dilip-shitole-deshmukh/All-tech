## 🧠 Conditionals (`if`, `else if`, `else`, `switch`)

---

## 🔹 Definition

Conditionals are used to **execute different blocks of code based on conditions** (true/false).

👉 In simple terms:

> “If something is true → do this, otherwise → do something else”

💡 They are the **foundation of decision-making** in JavaScript programs.

---

## 🔹 Core Explanation

---

### ✅ 1. `if` Statement

```js
if (condition) {
  // runs if condition is true
}
```

🧠 How it works:

- Condition is evaluated → converted to **boolean**
- If `true` → block executes
- If `false` → skipped

💡 JS uses **truthy/falsy values**, not just true/false.

---

### ✅ 2. `if...else`

```js
if (condition) {
  // true case
} else {
  // false case
}
```

🧠 Why use:

- Ensures **one of the blocks always runs**
- Helps avoid writing two separate `if` checks

---

### ✅ 3. `else if` (Multiple Conditions)

```js
if (condition1) {
} else if (condition2) {
} else {
}
```

🧠 Important behavior:

- Conditions are checked **top → down**
- First `true` condition executes → rest are skipped

💡 Order matters a lot here!

---

### ✅ 4. `switch` Statement

```js
switch (value) {
  case 1:
    // code
    break;
  case 2:
    // code
    break;
  default:
  // fallback
}
```

🧠 How it works:

- Compares using **strict equality (`===`)**
- Matches value with `case`
- `break` prevents **fall-through**

---

## 🔹 Example(s) with Code

---

### ✅ Example 1: Basic `if-else`

```js
const age = 20;

if (age >= 18) {
  console.log("Adult");
} else {
  console.log("Minor");
}
```

🧠 Output:

- Condition true → prints `"Adult"`

---

### ✅ Example 2: `else if` Order Trap ⚠️

```js
const num = 10;

if (num > 5) {
  console.log("Greater than 5");
} else if (num > 8) {
  console.log("Greater than 8");
}
```

🧠 Output:

```
Greater than 5
```

💡 WHY:

- First condition already true → second never checked
- Always put **more specific conditions first**

---

### ✅ Example 3: `switch` Fall-through ⚠️

```js
const day = 1;

switch (day) {
  case 1:
    console.log("Monday");
  case 2:
    console.log("Tuesday");
    break;
}
```

🧠 Output:

```
Monday
Tuesday
```

💡 WHY:

- No `break` after case 1 → execution continues

---

### ✅ Example 4: Truthy/Falsy Concept 🔥

```js
if ("") {
  console.log("True");
} else {
  console.log("False");
}
```

🧠 Output:

```
False
```

💡 Falsy values:

- `false`, `0`, `""`, `null`, `undefined`, `NaN`

## 🔹 When to Use / When NOT to Use

---

### ✅ Use `if-else`

- Complex conditions (`&&`, `||`)
- Range checks (e.g., `age > 18`)

---

### ✅ Use `switch`

- Multiple fixed values
- Cleaner alternative to many `else if`

---

### ❌ Avoid

- Deep nested `if` (hard to read)
- Using `switch` for complex logic (bad readability)

---

## 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Assignment instead of comparison

```js
if (a = 5) ❌
```

👉 This assigns value → always truthy

✅ Correct:

```js
if (a === 5)
```

---

### ❌ Mistake 2: Not understanding truthy/falsy

```js
if ("0") // true ❗
```

👉 String `"0"` is truthy, not false

---

### ❌ Mistake 3: Missing `break` in switch

👉 Causes unexpected multiple executions

---

### ❌ Mistake 4: Wrong condition order

```js
if (score > 50) ...
else if (score > 80) ...
```

👉 Second condition never reached

---

## 🔹 Interview Q&A

---

### ❓1. Difference between `if-else` and `switch`?

- `if-else` → flexible, supports complex conditions
- `switch` → cleaner for fixed values

---

### ❓2. Does `switch` use `==` or `===`?

👉 Uses **strict equality (`===`)**

---

### ❓3. What is fall-through in switch?

When `break` is missing, execution continues to next case.

---

### ❓4. What are falsy values in JS?

`false`, `0`, `""`, `null`, `undefined`, `NaN`

---

### ❓5. Can we use expressions in switch case?

Yes, but comparison is strict → must match exactly.

---

### ❓6. Which is faster: if-else or switch?

Difference is negligible; readability matters more.

---

### ❓7. Can switch handle ranges?

❌ No directly → use `if-else`

---

### ❓8. What is ternary operator?

Short form of `if-else`:

```js
condition ? value1 : value2;
```

---

## 🔹 Advantages / Pitfalls

---

### ✅ Advantages

- Enables decision-making logic
- Improves control flow
- Makes code dynamic

---

### ❌ Pitfalls

- Nested conditions → hard to read
- Wrong order → logical bugs
- Misuse of truthy/falsy → unexpected behavior

---

## 🔹 Best Practices

---

✔ Keep conditions simple and readable
✔ Use `===` instead of `==`
✔ Avoid deep nesting (use early returns)
✔ Use `switch` for fixed value checks
✔ Order conditions carefully

---

## 🔹 Senior-Level Insights 🚀

---

### ⚡ Readability > Performance

- Modern JS engines optimize both `if` and `switch`
- Focus on **clean and maintainable logic**

---

### 🧠 Avoid Nested Hell (Important)

❌ Bad:

```js
if (a) {
  if (b) {
    if (c) {
    }
  }
}
```

✅ Better:

```js
if (!a || !b || !c) return;
```

---

### ⚖️ Trade-offs

| Approach | Pros                   | Cons                |
| -------- | ---------------------- | ------------------- |
| if-else  | Flexible               | Can get messy       |
| switch   | Clean for fixed values | Limited flexibility |
