## 🧠 `Promise.race()` (JavaScript)

> ⚠️ This is a **🟡 Conceptual async topic** → focus on **“first settled wins” behavior + real-world use (timeouts, fallback APIs)**

---

## 🔹 Definition

`Promise.race()` takes an **array of promises** and returns a **single promise** that settles as soon as **the first promise settles** (either resolve OR reject).

👉 In simple terms:

> “Whichever finishes first (success or failure) wins the race”

---

## 🔹 Core Explanation

---

## 🟢 1. How It Works

```js
Promise.race([promise1, promise2, promise3]);
```

🧠 Behavior:

- Starts all promises **in parallel**
- Returns result of **first settled promise**
- Ignores all others afterward

👉 Important:

- "First settled" ≠ "First resolved"
- Could be success OR failure

---

## 🔵 2. Success Case

```js
const p1 = new Promise((res) => setTimeout(() => res("A"), 2000));
const p2 = new Promise((res) => setTimeout(() => res("B"), 1000));

Promise.race([p1, p2]).then(console.log);
```

🧠 Output:

```text
B
```

👉 WHY:

- `p2` finishes faster → wins race

---

## 🔴 3. Failure Case (Important 🔥)

```js
const p1 = new Promise((_, rej) => setTimeout(() => rej("Error!"), 1000));
const p2 = new Promise((res) => setTimeout(() => res("Success"), 2000));

Promise.race([p1, p2]).then(console.log).catch(console.log);
```

🧠 Output:

```text
Error!
```

👉 WHY:

- First settled promise is rejection → race fails

💡 No waiting for others

---

## 🟡 4. Key Behavior Difference

| Method               | Behavior                 |
| -------------------- | ------------------------ |
| `Promise.all`        | Waits all                |
| `Promise.race`       | First settles            |
| `Promise.any`        | First success            |
| `Promise.allSettled` | Waits all (no fail-fast) |

## 🔹 Example(s) with Code

---

### ✅ Example 1: Timeout Implementation (Real Interview Favorite 🔥)

```js
function fetchWithTimeout(url, timeout) {
  const fetchPromise = fetch(url);

  const timeoutPromise = new Promise((_, reject) =>
    setTimeout(() => reject("Timeout!"), timeout),
  );

  return Promise.race([fetchPromise, timeoutPromise]);
}
```

👉 WHY:

- If API is slow → timeout triggers first
- Prevents hanging requests

---

### ✅ Example 2: Fastest Server Response

```js
Promise.race([fetch("server1"), fetch("server2"), fetch("server3")]).then(
  (res) => console.log("Fastest response"),
);
```

👉 Used in **CDN / multi-endpoint systems**

---

### ⚠️ Example 3: Non-Promise Values

```js
Promise.race([1, Promise.resolve(2)]).then(console.log);
```

🧠 Output:

```text
1
```

👉 WHY:

- Non-promise values are treated as already resolved

## 🔹 When to Use / When NOT to Use

---

### ✅ Use `Promise.race`

- When only **first result matters**
- Timeout handling
- Performance optimization

---

### ❌ Avoid

- When you need **all results**
  👉 Use `Promise.all`

---

## 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Assuming success only

👉 Race can reject first

---

### ❌ Mistake 2: Ignoring remaining promises

👉 They still run in background

---

### ❌ Mistake 3: Using for dependent tasks

👉 Not suitable

---

### ❌ Mistake 4: No error handling

👉 Can cause unexpected failures

---

## 🔹 Interview Q&A

---

### ❓1. What is `Promise.race()`?

Returns first settled promise

---

### ❓2. What does “first settled” mean?

Resolved OR rejected

---

### ❓3. Does it wait for all promises?

No

---

### ❓4. What if first promise rejects?

Whole race rejects

---

### ❓5. Use case?

Timeout implementation

---

### ❓6. Difference from `Promise.any()`?

`race` → first settle
`any` → first success

---

### ❓7. Does it cancel other promises?

No, they continue

---

### ❓8. Can it take non-promises?

Yes

---

## 🔹 Advantages / Pitfalls

---

### ✅ Advantages

- Fast response handling
- Useful for timeouts
- Simple API

---

### ❌ Pitfalls

- Other promises still execute
- Can fail unexpectedly
- Not useful for collecting results

---

## 🔹 Best Practices

---

✔ Always handle errors (`catch`)
✔ Use for independent tasks
✔ Combine with timeout logic
✔ Avoid for critical multi-step workflows
✔ Be aware of background execution

---

## 🔹 Senior-Level Insights 🚀

---

### ⚡ No Cancellation

```js
Promise.race([...]);
```

👉 Losing promises are NOT cancelled

💡 For cancellation → use:

- `AbortController`

---

### 🧠 Performance Thinking

👉 Great for:

- Reducing latency
- Handling unreliable APIs

---

### ⚖️ Trade-offs

| Feature | Pros           | Cons                   |
| ------- | -------------- | ---------------------- |
| race    | Fastest result | No control over others |
| all     | Complete data  | Slower                 |

---

### 🔄 Real-world Pattern

```text
Primary API vs Backup API
→ Race both → Use fastest
```
