## 🧠 Microtasks vs Macrotasks (JavaScript Event Loop)

> ⚠️ This is a **🟡 Conceptual + ⚡ Performance-critical topic**
> 👉 Interviewers expect: **event loop order, execution priority, tricky outputs**

---

# 🔹 Definition

👉 **Microtasks and Macrotasks are queues used by the Event Loop to manage async operations**

- **Macrotasks (Task Queue)** → setTimeout, setInterval, DOM events
- **Microtasks (Job Queue)** → Promises (`.then`, `.catch`, `.finally`), `queueMicrotask`

💡 Key idea:

```text
Microtasks always run BEFORE the next macrotask
```

---

# 🔹 Core Explanation

---

## 🔁 1. Where they fit (Event Loop Flow)

```text
Call Stack → Microtask Queue → Macrotask Queue
```

---

### 🔄 Execution Order:

1. Run synchronous code (call stack)
2. Execute ALL microtasks
3. Execute ONE macrotask
4. Repeat

---

### 💡 WHY this design?

👉 Microtasks are for **high-priority, immediate follow-ups**
👉 Macrotasks are for **scheduled or delayed work**

---

## ⚡ 2. Macrotasks (Task Queue)

---

### 📌 Examples:

```js
setTimeout(() => {}, 0);
setInterval(() => {});
document.addEventListener("click", handler);
```

---

### 💡 Behavior:

- Executed **after microtasks**
- Only **one macrotask per loop cycle**
- Can be delayed by microtasks

---

## ⚡ 3. Microtasks (Job Queue)

---

### 📌 Examples:

```js
Promise.resolve().then(() => {});
queueMicrotask(() => {});
```

---

### 💡 Behavior:

- Executed **immediately after current stack**
- Runs **ALL microtasks before moving on**
- Higher priority than macrotasks

---

## 🔥 Golden Rule (VERY IMPORTANT ⭐)

```text
Microtasks → always run before Macrotasks
```

---

# 🔹 Example(s) with Code

---

## ✅ Example 1: Basic Order

```js
console.log("Start");

setTimeout(() => console.log("Timeout"), 0);

Promise.resolve().then(() => console.log("Promise"));

console.log("End");
```

---

### 🔍 Execution Steps:

1. `Start` → sync
2. `End` → sync
3. Promise → microtask
4. setTimeout → macrotask

---

### ✅ Output:

```text
Start
End
Promise
Timeout
```

---

## ❗ Example 2: Multiple Microtasks

```js
console.log("Start");

Promise.resolve().then(() => console.log("Microtask 1"));
Promise.resolve().then(() => console.log("Microtask 2"));

setTimeout(() => console.log("Macrotask"), 0);
```

---

### ✅ Output:

```text
Start
Microtask 1
Microtask 2
Macrotask
```

---

### 💡 WHY:

👉 All microtasks run before macrotask

---

## ❗ Example 3: Nested Microtasks (Tricky ⭐)

```js
Promise.resolve().then(() => {
  console.log("Microtask 1");

  Promise.resolve().then(() => {
    console.log("Microtask 2");
  });
});

setTimeout(() => console.log("Macrotask"), 0);
```

---

### ✅ Output:

```text
Microtask 1
Microtask 2
Macrotask
```

---

### 💡 WHY:

👉 Newly added microtasks are also executed **before moving to macrotask**

---

## ❗ Example 4: Starvation Problem

```js
function loop() {
  Promise.resolve().then(loop);
}

loop();

setTimeout(() => console.log("Timeout"), 0);
```

---

### 💥 Result:

👉 `setTimeout` may NEVER run

---

### 💡 WHY:

```text
Microtasks keep adding themselves → macrotask never gets chance
```

---

# 🔹 Real-world Use Cases

---

### ⚡ 1. Promise Chains

```js
fetchData().then(process).then(render);
```

👉 Uses microtasks → fast execution

---

### ⚡ 2. UI Updates

👉 Microtasks help ensure:

- DOM updates happen before next render cycle

---

### ⚡ 3. Event Handling

👉 User clicks → macrotask
👉 Follow-up logic → microtask

---

# 🔹 When to Use / When NOT

---

### ✅ Use Microtasks when:

- Immediate follow-up logic needed
- Promise chaining
- State updates

---

### ❌ Avoid overusing Microtasks:

- Can block UI (starvation)
- Infinite loops possible

---

### ✅ Use Macrotasks when:

- Delayed execution needed
- Non-critical tasks
- Animations / timers

---

# ⚠️ Common Mistakes / Traps

---

### ❌ Mistake 1: setTimeout runs immediately

👉 Reality:

```text
It runs AFTER all microtasks
```

---

### ❌ Mistake 2: Promise is async like setTimeout

👉 Reality:

```text
Promise = microtask (higher priority)
setTimeout = macrotask (lower priority)
```

---

### ❌ Mistake 3: Ignoring microtask queue

👉 Leads to wrong output prediction

---

# 🔹 Interview Q&A

---

### ❓1. What is microtask queue?

Queue for high-priority async tasks like Promises

---

### ❓2. What is macrotask queue?

Queue for scheduled tasks like setTimeout

---

### ❓3. Which runs first?

👉 Microtasks always

---

### ❓4. Is Promise synchronous?

👉 No, but executed before macrotasks

---

### ❓5. What is queueMicrotask?

API to add task to microtask queue

---

### ❓6. Can microtasks delay macrotasks?

👉 Yes, completely

---

### ❓7. What is starvation?

Microtasks preventing macrotasks from running

---

### ❓8. Event loop order?

```text
Sync → Microtasks → Macrotask
```

---

# 🔹 Advantages / Pitfalls

---

### ✅ Advantages

- Fast execution
- Predictable ordering
- Efficient async chaining

---

### ❌ Pitfalls

- Starvation issues
- Hard debugging
- Confusing execution order

---

# 🔹 Best Practices

---

✔ Use Promises for async flows
✔ Avoid infinite microtask loops

```js
// BAD
Promise.resolve().then(loop);
```

✔ Use setTimeout to yield control

```js
setTimeout(() => heavyTask(), 0);
```

✔ Keep microtasks small

---

# 🔹 Senior-Level Insights 🚀

---

## ⚡ 1. Rendering & Event Loop

👉 Browser renders **between macrotasks**, not during microtasks

```text
Microtasks block rendering
```

👉 Heavy microtasks = UI freeze

---

## ⚡ 2. React & Microtasks

👉 React batching often relies on:

- microtask-like scheduling
- prioritizing updates

---

## ⚡ 3. Performance Trade-off

| Type      | Speed     | Risk          |
| --------- | --------- | ------------- |
| Microtask | ⚡ Fast   | 🚨 Starvation |
| Macrotask | 🐢 Slower | ✅ Safer      |

---

## ⚡ 4. Debugging Tip

👉 If order is confusing:

```text
Check → Is it Promise or setTimeout?
```

---

# ✅ Final Takeaway

```text
JavaScript processes microtasks immediately after the current execution, before moving to macrotasks, making Promises execute before setTimeout
```
