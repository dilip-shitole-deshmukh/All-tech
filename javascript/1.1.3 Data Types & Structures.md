## 👉 Data Types & Structures: Numbers, Strings, Booleans, Arrays, Objects

---

## 🔹 Definition

JavaScript provides **data types** to represent different kinds of values.
They are broadly divided into:

- **Primitive types** → Number, String, Boolean
- **Reference types** → Array, Object

👉 Key idea:

- Primitives store **actual values**
- Reference types store **memory references (addresses)**

---

## 🔹 Core Explanation

### 🟢 1. Number

- Used to represent **numeric values** (both integers & floating-point).
- JavaScript has only **one number type** (no separate int/float).
- Special values: `NaN`, `Infinity`, `-Infinity`.

👉 Why important:
JS internally uses **IEEE 754 (floating-point)** → can cause precision issues.

---

### 🟢 2. String

- Represents **textual data**, enclosed in `' '`, `" "`, or `` ` ` ``.
- Strings are **immutable**, meaning you cannot change characters directly.
- Template literals (`` `Hello ${name}` ``) allow dynamic string creation.

👉 Why important:
Immutability ensures predictable behavior but creates new strings on modification.

---

### 🟢 3. Boolean

- Represents **true / false values**.
- Commonly used in **conditions, comparisons, and control flow**.
- JS also has **truthy & falsy values**.

👉 Falsy values:

```js
(false, 0, "", null, undefined, NaN);
```

👉 Why important:
Understanding truthy/falsy avoids logical bugs.

---

### 🟢 4. Array (Reference Type)

- Ordered collection of values → can store **mixed data types**.
- Arrays are **dynamic and resizable**.
- Internally, arrays are just **special objects with numeric keys**.

👉 Why important:
Used heavily in UI rendering, loops, API responses.

---

### 🟢 5. Object (Reference Type)

- Collection of **key-value pairs**.
- Keys are strings (or symbols), values can be anything.
- Objects are **mutable and reference-based**.

👉 Why important:
Core building block for almost everything in JS (DOM, JSON, APIs).

---

## 🔹 Example(s) with Code

### ✅ Example 1: Primitive vs Reference

```javascript
let a = 10;
let b = a;

b = 20;
console.log(a); // 10
```

👉 Explanation:

- `a` and `b` store **separate values**
- Changing `b` does NOT affect `a`

---

```javascript
let obj1 = { name: "Dilip" };
let obj2 = obj1;

obj2.name = "Rahul";
console.log(obj1.name); // Rahul
```

👉 Explanation:

- Both variables point to **same memory reference**
- Changing one affects the other

---

### ⚠️ Example 2: Floating Point Issue

```javascript
console.log(0.1 + 0.2); // 0.30000000000000004
```

👉 Why:

- Due to **binary floating-point representation**
- Not all decimals can be represented exactly

---

### ⚠️ Example 3: Array is Object

```javascript
let arr = [1, 2, 3];

console.log(typeof arr); // "object"
```

👉 Why:

- Arrays are special objects with indexed keys (`0,1,2...`)

---

## 🔹 Real-world Use Cases

- 🔹 Number → calculations (price, totals, counters)
- 🔹 String → UI text, API data, form inputs
- 🔹 Boolean → toggles (isLoggedIn, isLoading)
- 🔹 Array → lists (products, users, table data)
- 🔹 Object → structured data (user profile, API response)

---

## 🔹 When to use / When NOT to use

- Use **primitive types** when you need **simple values & immutability**
- Use **arrays** when order matters and multiple values are needed
- Use **objects** for structured, key-based data

❌ Avoid:

- Using objects when array fits better (ordering issues)
- Mutating shared objects unintentionally (bugs in React state)

---

## 🔹 Common Mistakes / Traps

### ❌ Mistake 1: Comparing Objects

```javascript
{} === {} // false
```

✅ Reality:

- Objects are compared by **reference**, not value

---

### ❌ Mistake 2: `typeof null`

```javascript
typeof null; // "object"
```

💡 Why:

- Historical JS bug (still exists for backward compatibility)

---

### ❌ Mistake 3: Array mutation confusion

```javascript
const arr = [1, 2];
arr.push(3); // ✅ works
```

💡 Why:

- Array reference is constant, but content is mutable

---

### ❌ Mistake 4: Truthy/Falsy confusion

```javascript
if ("0") console.log("runs"); // ✅ runs
```

💡 Why:

- Non-empty string is truthy

## 🔹 Interview Q&A

### ❓ 1. Difference between primitive and reference types?

- Primitive → stored directly in stack, copied by value
- Reference → stored in heap, variables hold reference
- Changes in reference types affect all references

---

### ❓ 2. Why `0.1 + 0.2 !== 0.3`?

- Due to floating-point precision issues
- JS uses binary representation → rounding errors

---

### ❓ 3. Are arrays objects in JS?

- Yes, arrays are specialized objects
- Indexed access is just numeric keys

---

### ❓ 4. Why `typeof null === "object"`?

- Historical bug in JS
- Still maintained for backward compatibility

---

### ❓ 5. What are truthy and falsy values?

- Falsy: `false, 0, "", null, undefined, NaN`
- Everything else is truthy

---

### ❓ 6. How are objects stored internally?

- Stored in heap memory
- Variables store reference (memory address)

---

### ❓ 7. Difference between `==` and `===`?

- `==` → type coercion
- `===` → strict comparison (preferred)

---

## 🔹 Advantages / Pitfalls

### ✅ Advantages

- Flexible data handling (dynamic typing)
- Easy to work with complex structures (objects, arrays)
- Powerful for frontend state management

### ❌ Pitfalls

- Type coercion confusion
- Reference mutation bugs
- Floating-point precision issues

---

## 🔹 Best Practices

✔ Use `===` instead of `==`
✔ Avoid mutating objects/arrays directly (especially in React)
✔ Use `const` for arrays/objects unless reassignment needed
✔ Clone objects when necessary (`{...obj}`, `[...arr]`)
✔ Be aware of truthy/falsy behavior

---

## 🔹 Final Summary (Interview Ready)

- **Primitive types** → Number, String, Boolean (immutable, value-based)
- **Reference types** → Array, Object (mutable, reference-based)
- Arrays & Objects are stored in **heap memory**
- Key pitfalls → reference comparison, floating precision, truthy/falsy

💡 **Golden Insight:**
👉 “Primitives behave like values, Objects/Arrays behave like references”
