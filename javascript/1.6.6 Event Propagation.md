## 🧠 Event Propagation (JavaScript)

---

## 🔹 Definition

Event Propagation is the process by which an event **travels through the DOM tree when triggered**.

👉 In simple terms:

> “When you click an element → the event doesn’t stay there, it moves through parent elements”

💡 This movement defines **which event handlers execute and in what order**.

---

## 🔹 Core Explanation

---

### ⚙️ Event Flow (3 Phases) 🔥

Every event goes through **3 phases**:

```text
1. Capturing Phase (Top → Down)
2. Target Phase (Actual Element)
3. Bubbling Phase (Bottom → Up)
```

👉 Example DOM:

```html
<div id="parent">
  <button id="child">Click</button>
</div>
```

---

### 🔵 1. Capturing Phase

- Event starts from **root (`document`)**
- Travels **down to the target element**
- Handlers run only if `{ capture: true }`

```js
parent.addEventListener("click", handler, true);
```

🧠 WHY:

- Gives parent a chance to intercept event **before child**

---

### 🟢 2. Target Phase

- Event reaches the **actual clicked element**
- Both capturing & bubbling handlers can execute here

---

### 🔴 3. Bubbling Phase (Default)

- Event travels **back up from target to root**
- This is the **default behavior in JS**

```js
parent.addEventListener("click", handler);
```

---

## 🔹 Example(s) with Code

---

### ✅ Example 1: Basic Propagation

```js
parent.addEventListener("click", () => {
  console.log("Parent");
});

child.addEventListener("click", () => {
  console.log("Child");
});
```

### 🧠 Output:

```text
Child
Parent
```

👉 WHY:

- Child runs first (target)
- Then event bubbles to parent

---

### ✅ Example 2: Capturing vs Bubbling

```js
parent.addEventListener(
  "click",
  () => {
    console.log("Parent Capture");
  },
  true,
);

parent.addEventListener("click", () => {
  console.log("Parent Bubble");
});

child.addEventListener("click", () => {
  console.log("Child");
});
```

### 🧠 Output:

```text
Parent Capture
Child
Parent Bubble
```

👉 Order:

1. Capturing
2. Target
3. Bubbling

---

### ✅ Example 3: stopPropagation() 🔥

```js
child.addEventListener("click", (e) => {
  e.stopPropagation();
  console.log("Child only");
});

parent.addEventListener("click", () => {
  console.log("Parent");
});
```

### 🧠 Output:

```text
Child only
```

👉 WHY:

- Stops event from moving upward

---

### ✅ Example 4: stopImmediatePropagation()

```js
btn.addEventListener("click", (e) => {
  e.stopImmediatePropagation();
  console.log("First");
});

btn.addEventListener("click", () => {
  console.log("Second");
});
```

👉 Only `"First"` runs

## 🔹 Real-world Use Cases

---

### 🌐 1. Event Delegation

- Use bubbling to handle child events at parent level
- Improves performance

---

### 🧾 2. Preventing Parent Actions

- Stop modal from closing when clicking inside

---

### 🎯 3. Nested UI Components

- Dropdowns, menus, modals

---

## 🔹 When to Use / When NOT to Use

---

### ✅ Use Bubbling

- Default choice
- Required for event delegation

---

### ✅ Use Capturing

- When parent must handle event first
- Rare use cases

---

### ❌ Avoid

- Excessive `stopPropagation`
- Mixing phases without clarity

---

## 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Thinking parent runs first

👉 Reality:

- Default = bubbling → child first

---

### ❌ Mistake 2: Confusing target vs currentTarget

```js
e.target; // actual clicked element
e.currentTarget; // listener element
```

---

### ❌ Mistake 3: Overusing stopPropagation

👉 Breaks event delegation

---

### ❌ Mistake 4: Ignoring event phases

👉 Leads to unexpected execution order

## 🔹 Interview Q&A

---

### ❓1. What is event propagation?

Process of event traveling through DOM elements.

---

### ❓2. What are phases of propagation?

Capturing → Target → Bubbling

---

### ❓3. Which phase is default?

👉 Bubbling

---

### ❓4. How to stop propagation?

👉 `event.stopPropagation()`

---

### ❓5. What is stopImmediatePropagation?

Stops all handlers on same element

---

### ❓6. What is event.target?

Actual element that triggered event

---

### ❓7. What is event.currentTarget?

Element where listener is attached

---

### ❓8. Why is propagation important?

Helps in delegation and efficient event handling

## 🔹 Advantages / Pitfalls

---

### ✅ Advantages

- Enables event delegation
- Efficient event handling
- Flexible control over event flow

---

### ❌ Pitfalls

- Hard to debug
- Unexpected behavior if misunderstood
- Overuse of stopping methods

---

## 🔹 Best Practices

---

✔ Use bubbling by default
✔ Understand event flow clearly
✔ Use `stopPropagation` only when necessary
✔ Prefer delegation for performance
✔ Use `currentTarget` when needed

## 🔹 Senior-Level Insights 🚀

---

### ⚡ Performance Optimization

- Reduce number of listeners

---

### 🧠 Debugging Trick

```js
console.log(event.eventPhase);
```

| Value | Phase     |
| ----- | --------- |
| 1     | Capturing |
| 2     | Target    |
| 3     | Bubbling  |

---

### 🔄 Real-world Flow

```text
Click →
Capturing (document → parent) →
Target (element) →
Bubbling (element → parent → document)
```

---

### ⚖️ Trade-offs

| Phase     | Pros           | Cons                          |
| --------- | -------------- | ----------------------------- |
| Capturing | Control early  | Rare use                      |
| Bubbling  | Simple, common | Can trigger unwanted handlers |
