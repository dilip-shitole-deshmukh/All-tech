## 👉 Lazy Evaluation (JavaScript)

---

## 🔹 Definition

👉 **Lazy Evaluation** is a technique where **computation is delayed until the result is actually needed**.

📌 Simple:

> “Don’t calculate now — calculate only when required.”

---

## 🔹 Core Explanation

### 🧠 1. Eager vs Lazy Evaluation

```js
// Eager (default JS behavior)
const result = expensiveFunction(); // runs immediately

// Lazy
const result = () => expensiveFunction(); // runs only when called
```

💡 Difference:

- **Eager** → computes immediately
- **Lazy** → defers execution

---

### ⚙️ 2. How Lazy Evaluation Works

- Instead of storing a value, we store a **function (thunk)**.
- Execution happens **only when we invoke it**.

```js
const lazyValue = () => {
  console.log("Computing...");
  return 10;
};

// nothing happens yet
lazyValue(); // now computation happens
```

---

### 🔁 3. Lazy Evaluation with Generators

```js
function* generateNumbers() {
  let i = 1;
  while (true) {
    yield i++;
  }
}

const gen = generateNumbers();

console.log(gen.next().value); // 1
console.log(gen.next().value); // 2
```

💡 WHY this is lazy:

- Values are generated **on demand**, not all at once

---

### 🔄 4. Lazy vs Memoization (Important Difference)

| Lazy Evaluation        | Memoization          |
| ---------------------- | -------------------- |
| Delays execution       | Caches result        |
| Computes when needed   | Avoids recomputation |
| May run multiple times | Runs once per input  |

💡 They can be combined for powerful optimizations

---

### 🧩 5. Short-Circuiting (Built-in Lazy Behavior)

```js
false && expensiveFunction(); // function never runs
true || expensiveFunction(); // function never runs
```

💡 JS evaluates only what’s needed → lazy behavior

---

## 🔹 Example(s) with Code

### ✅ Example 1: Basic Lazy Function

```js
function getData() {
  console.log("Fetching...");
  return 100;
}

const lazyData = () => getData();

console.log("Before call");
console.log(lazyData());
```

🧩 Execution:

- Nothing happens until `lazyData()` is called
- Then function executes

---

### ⚠️ Example 2: Lazy Array Processing (Optimization)

```js
const arr = [1, 2, 3, 4, 5];

// Eager
const result = arr.map((x) => x * 2).filter((x) => x > 5);

// Lazy (conceptual)
function* lazyMap(arr) {
  for (let x of arr) yield x * 2;
}
```

💡 Lazy approach:

- Processes elements **one by one**, not full array
- Saves memory and time for large data

---

### 🧩 Example 3: Infinite Data Handling

```js
function* infiniteNumbers() {
  let i = 0;
  while (true) yield i++;
}

const gen = infiniteNumbers();

console.log(gen.next().value); // 0
console.log(gen.next().value); // 1
```

👉 Impossible with eager evaluation

## 🔹 Real-world Use Cases

### 🌐 1. Infinite Scroll / Pagination

- Load data **only when user scrolls**
- Avoid loading entire dataset at once

---

### ⚛️ 2. React Lazy Loading

```js
const Component = React.lazy(() => import("./Component"));
```

💡 Loads component **only when needed**

---

### 📦 3. Code Splitting

- Load JS bundles dynamically
- Improves initial load performance

---

### 🔄 4. Large Data Processing

- Process streams/logs without loading everything into memory

---

## 🔹 When to Use / When NOT to Use

### ✅ Use When:

- Expensive computation
- Large datasets
- Data may not always be needed
- Performance optimization required

---

### ❌ Avoid When:

- Computation is cheap
- Simplicity is more important
- Over-engineering small logic

---

## 🔹 Common Mistakes / Traps

### ❌ Mistake 1: Thinking lazy = faster always

👉 Lazy saves work **only if computation is avoided**

---

### ❌ Mistake 2: Forgetting execution

```js
const fn = () => compute();
// forgot to call fn()
```

👉 Nothing happens

---

### ❌ Mistake 3: Confusing with async

👉 Lazy ≠ asynchronous
👉 Lazy = delayed execution
👉 Async = non-blocking execution

---

### ❌ Mistake 4: Multiple executions

```js
const lazy = () => expensive();

lazy();
lazy(); // runs again
```

👉 Not cached → runs every time

## 🔹 Interview Q&A

### ❓1. What is lazy evaluation?

👉 Delaying computation until the result is needed.

---

### ❓2. How is lazy evaluation implemented in JS?

👉 Using functions (thunks), generators, or short-circuit evaluation.

---

### ❓3. Lazy vs eager evaluation?

👉 Eager computes immediately; lazy delays execution.

---

### ❓4. Is lazy evaluation default in JavaScript?

👉 No, JS is eager by default.

---

### ❓5. Difference between lazy and memoization?

👉 Lazy delays execution; memoization caches results.

---

### ❓6. What are generators used for?

👉 Implement lazy sequences and handle large/infinite data.

---

### ❓7. Real-world example?

👉 React lazy loading and infinite scroll.

---

### ❓8. Is lazy evaluation asynchronous?

👉 No, it just delays execution; async handles concurrency.

---

## 🔹 Advantages / Pitfalls

### ✅ Advantages

- Improves performance
- Reduces memory usage
- Enables infinite data structures
- Avoids unnecessary computation

---

### ⚠️ Pitfalls

- Can make code harder to understand
- Debugging becomes tricky
- May execute multiple times if not cached

---

## 🔹 Best Practices

✔ Use for expensive computations
✔ Combine with memoization when needed
✔ Prefer generators for large data
✔ Keep logic readable
✔ Avoid overuse

---

## 🔹 Senior-Level Insights

### ⚡ 1. Lazy + Memoization Combo

```js
const lazyMemo = (() => {
  let cache;
  return () => {
    if (!cache) cache = expensive();
    return cache;
  };
})();
```

💡 Executes once, then reuses → best of both worlds
