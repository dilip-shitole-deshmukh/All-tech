## 🧠 Callbacks vs Promises vs Async/Await

> ⚠️ This is a **🟡 Conceptual + Comparison topic (VERY IMPORTANT in interviews)**
> 👉 Focus on **evolution + differences + when to use**

---

## 🔹 Definition

All three are ways to handle **asynchronous operations in JavaScript**:

- 📞 **Callbacks** → Old approach (function passed to execute later)
- 🤝 **Promises** → Structured async handling
- ⚡ **Async/Await** → Clean, synchronous-looking syntax

💡 Evolution:

```text
Callbacks → Promises → Async/Await
```

---

## 🔹 Core Explanation

---

## 🟢 1. Callbacks

### 👉 What it is:

A function passed as an argument and executed later

```js
setTimeout(() => {
  console.log("Done");
}, 1000);
```

### 🧠 How it works:

- Function is passed
- Executed after async operation completes

### ❌ Problem:

- Nested callbacks → **Callback Hell**
- Hard to maintain

---

## 🔵 2. Promises

### 👉 What it is:

Object representing **future value (success/failure)**

```js
fetch("/api")
  .then((res) => res.json())
  .then((data) => console.log(data))
  .catch((err) => console.log(err));
```

### 🧠 How it works:

- `.then()` → success
- `.catch()` → error
- Supports chaining

### ✅ Improvement over callbacks:

- Avoids nesting
- Better error handling

---

## 🟡 3. Async / Await

### 👉 What it is:

Syntax over promises to write async code like synchronous

```js
async function getData() {
  try {
    const res = await fetch("/api");
    const data = await res.json();
    console.log(data);
  } catch (err) {
    console.log(err);
  }
}
```

### 🧠 How it works:

- `await` pauses execution
- Works only inside `async`

### ✅ Improvement over promises:

- Cleaner code
- Easier debugging

---

## 🔁 Same Example in All Three (Important 🔥)

---

### 📞 Callback

```js
getData(function (data) {
  processData(data, function (result) {
    console.log(result);
  });
});
```

😵 Problem → Pyramid structure

---

### 🤝 Promise

```js
getData()
  .then((data) => processData(data))
  .then((result) => console.log(result))
  .catch((err) => console.log(err));
```

🙂 Better → Flat chain

---

### ⚡ Async/Await

```js
async function main() {
  try {
    const data = await getData();
    const result = await processData(data);
    console.log(result);
  } catch (err) {
    console.log(err);
  }
}
```

🔥 Best → Clean & readable

---

## 🔹 Key Differences (Interview Gold Table ⭐)

| Feature        | Callback     | Promise     | Async/Await  |
| -------------- | ------------ | ----------- | ------------ |
| Readability    | ❌ Poor      | 👍 Good     | 🔥 Excellent |
| Error Handling | ❌ Difficult | 👍 Better   | 🔥 Best      |
| Chaining       | ❌ Nested    | 👍 Yes      | 👍 Yes       |
| Debugging      | ❌ Hard      | 👍 Moderate | 🔥 Easy      |
| Syntax         | Verbose      | Structured  | Clean        |
| Control        | Low          | Medium      | High         |

## 🔹 Real-world Use Cases

---

### 📞 Callbacks

- Event handling (`addEventListener`)
- Simple async tasks

---

### 🤝 Promises

- API calls
- Parallel execution (`Promise.all`)

---

### ⚡ Async/Await

- Complex workflows
- Production apps (React, Node.js)

---

## 🔹 When to Use / When NOT to Use

---

### ✅ Use Callbacks

- Simple operations
- Event-based code

---

### ✅ Use Promises

- Parallel tasks
- Chaining operations

---

### ✅ Use Async/Await

- Complex logic
- Readability important

---

### ❌ Avoid

- Nested callbacks
- Mixing patterns unnecessarily

---

## 🔹 Common Mistakes / Traps

---

### ❌ Mixing all three

```js
await fetch().then(...) // ❌ confusing
```

👉 Stick to one pattern

---

### ❌ Callback Hell

👉 Leads to unreadable code

---

### ❌ Forgetting error handling

👉 Causes crashes

---

### ❌ Sequential awaits

```js
await a();
await b();
```

👉 Use `Promise.all` if independent

## 🔹 Interview Q&A

---

### ❓1. Why callbacks replaced?

Because of callback hell

---

### ❓2. Why promises introduced?

To handle async cleanly

---

### ❓3. Why async/await introduced?

To simplify promise syntax

---

### ❓4. Is async/await different from promises?

No, it's syntactic sugar

---

### ❓5. Which is best?

Async/await for readability

---

### ❓6. Can async/await replace promises?

Internally still uses promises

---

### ❓7. When to use Promise.all?

Parallel execution

---

### ❓8. What is callback hell?

Nested callbacks

## 🔹 Advantages / Pitfalls

---

### ✅ Callbacks

- Simple
  ❌ Hard to scale

---

### ✅ Promises

- Structured
  ❌ Chain complexity

---

### ✅ Async/Await

- Clean & readable
  ❌ Sequential pitfalls

---

## 🔹 Best Practices

---

✔ Prefer async/await
✔ Use Promise.all for parallel calls
✔ Always handle errors
✔ Avoid nested callbacks
✔ Keep async code readable

## 🔹 Senior-Level Insights 🚀

---

### ⚡ Event Loop Understanding

```text
Call Stack → Microtask Queue (Promises) → Macrotask Queue
```

👉 All three rely on this

---

### 🧠 Performance Thinking

❌ Bad:

```js
await api1();
await api2();
```

✅ Good:

```js
await Promise.all([api1(), api2()]);
```

| ----------- | -------------- |
| Callback    | Events         |
| Promise     | Parallel async |
