# 🧠 Closures (JavaScript)

---

## 🔹 Definition

👉 **Simple Definition:**
A **closure** is when a function remembers and can access variables from its **outer scope even after that outer function has finished executing**.

👉 **Slightly Deeper:**
Closures are created because of **lexical scoping + execution context**.
When a function is returned or passed around, it **retains a reference to its original scope**, not a copy of values.

---

# 🔹 Deep Explanation (Core Section)

---

## 1️⃣ What Exactly is a Closure?

### 🧠 Concept

- Closure = **function + its lexical environment**
- Inner function “closes over” variables of outer function

### ⚙️ Internal working

- When function is created:
  - It stores a hidden reference → `[[Environment]]`

- This points to its **outer lexical scope**

### 💡 Why it behaves this way

- JS uses lexical scoping → scope decided at definition time
- Enables functions to **carry their environment**

---

## 2️⃣ Closure Lifecycle (Very Important 🔥)

### 🧠 Normal case (no closure)

- Function finishes → execution context destroyed → memory freed

### 🧠 With closure

- If inner function references outer variables:
  - Outer scope is **NOT garbage collected**

### ⚙️ Internal behavior

- JS engine keeps outer variables alive in memory
- Stored in **heap (not stack)**

### ⚠️ Edge case

- Too many closures → memory leaks

---

## 3️⃣ Closures Store Reference, NOT Value ⚠️

### 🧠 What developers think

- Closure stores value snapshot ❌

### ✅ Reality

- It stores **reference to variable**

### 💡 Example:

```js id="8v7u2g"
function outer() {
  let x = 10;

  return function inner() {
    console.log(x);
  };
}

const fn = outer();
x = 20; // global (different variable)
fn();
```

👉 Output: **10**

But:

```js id="2ndqk7"
function outer() {
  let x = 10;

  return function inner() {
    console.log(x);
  };
}

const fn = outer();
fn(); // 10
```

If we update inside same scope → closure sees updated value.

---

## 4️⃣ Closures + Scope Chain 🔗

### 🧠 How lookup works

```
Inner → Outer → Global
```

### ⚙️ Internal detail

- Each function keeps pointer to parent scope
- This forms a **scope chain**

### 💡 Key insight

- Closure works because of this chain

---

## 5️⃣ Closures Enable Private Variables 🔐

### 🧠 Concept

- Outer function variables are hidden
- Only accessible via inner functions

### 💡 Example:

```js id="u8m3d7"
function counter() {
  let count = 0;

  return {
    increment() {
      count++;
      return count;
    },
  };
}

const c = counter();
console.log(c.increment()); // 1
```

👉 `count` is private

---

## 6️⃣ Closures in Loops (FAMOUS INTERVIEW TRAP 🔥)

### 🧠 Problem:

```js id="y2pnr1"
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 1000);
}
```

👉 Output:

```
3 3 3
```

### 💡 WHY:

- `var` → single shared variable
- Closure references same `i`

---

### ✅ Fix:

```js id="y6brj2"
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 1000);
}
```

👉 Output:

```
0 1 2
```

# 🔹 Example(s) with Code

---

## ✅ Example 1: Basic Closure

```js id="6nxh5d"
function outer() {
  let a = 10;

  function inner() {
    console.log(a);
  }

  return inner;
}

const fn = outer();
fn();
```

### 🔍 Execution:

1. `outer()` runs → `a = 10`
2. `inner` returned → closure created
3. `outer` execution ends BUT `a` stays
4. `fn()` → logs `10`

💡 WHY:
Closure preserves `a`

---

## ⚡ Example 2: Counter (Real-world)

```js id="8q1yxb"
function counter() {
  let count = 0;

  return function () {
    count++;
    return count;
  };
}

const c = counter();
console.log(c());
console.log(c());
```

👉 Output:

```
1
2
```

💡 WHY:
Same closure instance retains state

---

## 🔥 Example 3: Tricky Reference Case

```js id="2gq2jz"
function outer() {
  let x = 10;

  return function inner() {
    x++;
    console.log(x);
  };
}

const fn = outer();
fn();
fn();
```

👉 Output:

```
11
12
```

💡 WHY:
Closure keeps reference → updates persist

---

## 🔥 Example 4: Loop Trap (Interview)

```js id="8s5k2k"
for (var i = 0; i < 3; i++) {
  (function (j) {
    setTimeout(() => console.log(j), 1000);
  })(i);
}
```

👉 Output:

```
0 1 2
```

💡 WHY:
IIFE creates new closure per iteration
