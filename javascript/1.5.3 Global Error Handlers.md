# 🧠 Global Error Handlers

---

## 🔹 Definition

👉 **Simple Definition (2–3 lines):**
Global error handlers are mechanisms that catch **unhandled errors at the application level**.
They act as a safety net when errors are not caught by local `try-catch`.

👉 **Deeper Explanation (2–3 lines):**
In browsers, global handlers listen for runtime errors and unhandled promise rejections.
They help in **logging, monitoring, and preventing app crashes**.

---

# 🔹 Deep Explanation (Core Section)

---

## 1️⃣ Types of Global Error Handlers

### ✅ 1. `window.onerror`

```js
window.onerror = function (message, source, lineno, colno, error) {};
```

- Captures **uncaught synchronous errors**
- Works for script-level failures

💡 Internals:

- Browser triggers this when error bubbles to global scope

⚠️ Limitations:

- Doesn’t catch async errors (like promises)

---

### ✅ 2. `window.addEventListener("error")`

```js
window.addEventListener("error", (event) => {});
```

- More flexible than `onerror`
- Can capture **resource loading errors** (images, scripts)

💡 Example:

- Image failed to load → triggers event

---

### ✅ 3. `unhandledrejection` (VERY IMPORTANT)

```js
window.addEventListener("unhandledrejection", (event) => {});
```

- Handles **unhandled promise rejections**

💡 Internals:

- When a promise rejects without `.catch()`
- Event loop detects it → triggers handler

⚠️ Edge Case:

- If `.catch()` added later → may not trigger

---

## 2️⃣ Error Flow (How it Works Internally)

1. Error occurs
2. JS engine tries local handling (`try-catch`)
3. If not handled → bubbles to global scope
4. Global handler captures it

💡 Think like:
👉 “Last line of defense before crash”

---

## 3️⃣ Difference: Sync vs Async Errors

| Type             | Handler              |
| ---------------- | -------------------- |
| Sync errors      | `window.onerror`     |
| Async (Promises) | `unhandledrejection` |

💡 Why:

- Async runs in event loop → separate execution context

---

## 4️⃣ Error Object Details

```js
event.error;
event.message;
event.filename;
```

💡 Useful for:

- Debugging
- Logging to monitoring tools

---

## 5️⃣ Preventing Default Behavior

```js
window.onerror = function () {
  return true;
};
```

- Returning `true` prevents default logging

⚠️ Use carefully:

- Can hide errors from console

---

## 6️⃣ Integration with Monitoring Tools

- Global handlers send errors to:
  - Sentry
  - LogRocket
  - Datadog

💡 Why:

- Track production issues

---

## 7️⃣ Limitations of Global Handlers

- Cannot catch:
  - Syntax errors during parsing
  - Errors inside Web Workers (separate context)

⚠️ Important:

- Not replacement for proper error handling

---

# 🔹 Example(s) with Code

---

## ✅ Example 1: Basic Global Error Handler

```js
window.onerror = function (message, source, lineno, colno, error) {
  console.log("Global Error:", message);
};
```

### 🔍 Execution:

1. Any uncaught error occurs
2. Browser calls handler
3. Logs error

💡 WHY:

- Error reached global scope

---

## ⚡ Example 2: Promise Rejection

```js
window.addEventListener("unhandledrejection", (event) => {
  console.log("Unhandled Promise:", event.reason);
});

Promise.reject("Failed!");
```

### 🔍 Execution:

1. Promise rejects
2. No `.catch()`
3. Event triggered

💡 Output:

```js
Unhandled Promise: Failed!
```

💡 WHY:

- Event loop detects unhandled rejection

---

## ⚡ Example 3: Tricky (Handled Later)

```js
const p = Promise.reject("Error");

setTimeout(() => {
  p.catch(() => {});
}, 100);
```

### 🔍 Execution:

1. Promise rejected
2. No immediate catch
3. Global handler may trigger

💡 WHY:

- Timing matters → event loop

# 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Thinking it catches all errors

- ❌ All errors handled
- ✅ Only uncaught errors
- 💡 Local try-catch takes priority

---

### ❌ Mistake 2: Ignoring async errors

- ❌ window.onerror handles promises
- ✅ Need unhandledrejection
- 💡 Separate systems

---

### ❌ Mistake 3: Returning true blindly

- ❌ Prevent errors
- ✅ Hides debugging info
- 💡 Dangerous

---

### ❌ Mistake 4: Overusing global handler

- ❌ Centralized handling enough
- ✅ Still need local handling
- 💡 Separation of concerns

# 🔹 10+ Interview Q&A

---

### 1. What is global error handler?

A mechanism to catch uncaught errors at application level.

---

### 2. What is `window.onerror`?

Handles uncaught synchronous errors.

---

### 3. What is `unhandledrejection`?

Handles unhandled promise rejections.

---

### 4. Does it replace try-catch?

No, it complements it.

---

### 5. Can it catch syntax errors?

No, syntax errors occur before execution.

---

### 6. Why needed?

To log production errors.

---

### 7. What is event.reason?

The rejected value of promise.

---

### 8. Can we stop error logging?

Yes, by returning true (not recommended).

---

### 9. Does it work for async/await?

Yes, via unhandledrejection if not caught.

---

### 10. Is it used in production?

Yes, for monitoring tools.

---

### 11. What is limitation?

Cannot catch all error types.
