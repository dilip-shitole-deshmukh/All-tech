## ⚙️ JavaScript Engines & V8 Engine

> ⚠️ This is a **🔴 Advanced / System-level topic**
> 👉 Interviewers expect: **execution pipeline + optimization + memory + performance**

---

# 🔹 Definition

👉 **JavaScript Engine = software that executes JavaScript code**

- Converts JS → machine code → runs it on CPU
- Every browser/runtime has its own engine
- Examples:
  - V8 (Chrome, Node.js)
  - SpiderMonkey (Firefox)
  - JavaScriptCore (Safari)

---

# 🔹 Core Explanation

---

## 🧠 1. High-Level Working of JS Engine

```text
JS Code → Parsing → AST → Bytecode → Execution → Optimization
```

👉 Engine doesn’t run raw JS directly
👉 It transforms it step-by-step into efficient machine instructions

---

## 🧠 2. Parsing Phase (Code Understanding)

👉 JS code is converted into **AST (Abstract Syntax Tree)**

```js
let x = 10;
```

👉 Internally becomes structured tree (not plain text)

💡 WHY:

- Easier for engine to analyze and optimize

---

## 🧠 3. Interpreter vs Compiler (KEY CONCEPT ⭐)

---

### ⚡ Interpreter

- Executes code line-by-line
- Fast startup
- Used for initial execution

---

### 🚀 Compiler (JIT - Just In Time)

- Converts code into optimized machine code
- Runs faster after optimization

---

### 🔥 Key Idea:

```text
First → interpreted
Repeated → compiled & optimized
```

---

## 🧠 4. Inside V8

---

### 🔹 Main Components

---

### ⚡ 1. Ignition (Interpreter)

- Converts JS → bytecode
- Executes immediately

---

### 🚀 2. TurboFan (Optimizing Compiler)

- Optimizes frequently executed code
- Produces highly efficient machine code

---

### 🧠 3. Memory (Heap)

- Stores objects and variables
- Managed by garbage collector

---

### 📚 4. Call Stack

- Tracks function execution

---

## 🧠 5. Execution Flow in V8

---

```text
JS → AST → Bytecode (Ignition) → Optimized Code (TurboFan)
```

---

### 💡 Real Flow Example

```js
function add(a, b) {
  return a + b;
}

add(2, 3);
add(4, 5);
add(6, 7);
```

👉 Steps:

1. First calls → interpreted
2. Engine detects repeated usage
3. Marks function as **hot**
4. TurboFan optimizes it

---

## 🔹 Example(s) with Code

---

### ✅ Example 1: Hot Code Optimization

```js
function multiply(a, b) {
  return a * b;
}

for (let i = 0; i < 100000; i++) {
  multiply(2, 3);
}
```

👉 WHY:

- Frequent calls → optimized by V8

---

### ❗ Example 2: De-optimization (Tricky ⭐)

```js
function add(a, b) {
  return a + b;
}

add(2, 3); // number
add("2", "3"); // string
```

👉 Problem:

- Engine expects consistent types
- Mixed types → de-optimization

## 🔹 Senior-Level Insights 🚀

---

## ⚡ 1. Hidden Classes (VERY IMPORTANT)

👉 V8 creates internal structure for objects

```js
const obj = { a: 1, b: 2 };
```

👉 Changing structure dynamically:

```js
obj.c = 3;
```

👉 Causes:

```text
New hidden class → slower access
```

---

## ⚡ 2. Inline Caching

👉 V8 caches property access

```js
obj.name;
```

👉 Faster if structure stays same

---

## ⚡ 3. Garbage Collection

👉 Automatic memory cleanup

- Mark-and-sweep algorithm
- Removes unused objects

💡 Issue:

- Memory leaks if references remain

---

## ⚡ 4. De-optimization Triggers

```text
• Changing types
• Deleting properties
• Using try/catch heavily
```

---

## ⚡ 5. Engine vs Event Loop

```text
Engine → executes code
Event Loop → handles async
```

👉 Both are separate concepts
