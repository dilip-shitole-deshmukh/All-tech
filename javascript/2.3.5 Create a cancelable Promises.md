## 🧠 Cancelable Promises in JavaScript

> ⚠️ This is a **🟡 Conceptual + Practical Async topic (very common in real-world apps)**
> 👉 Tests your understanding of **Promises limitations + Abort patterns**

---

## 🔹 Definition

👉 A **cancelable promise** is a way to **stop or ignore an ongoing async operation** before it completes.

💡 Important truth:

> ❗ Native JavaScript **Promises are NOT cancelable**

👉 You cannot “stop” a promise once started —
You can only:

- Ignore its result
- Or cancel the underlying operation (like fetch)

---

## 🔹 Core Explanation

---

## 🟢 1. Why Promises Are Not Cancelable

👉 Once a promise starts:

- It runs to completion
- JS has no built-in `.cancel()`

```js
new Promise((resolve) => {
  setTimeout(() => resolve("Done"), 5000);
});
```

❌ You cannot stop this timer

💡 Reason:

- Promises are designed to represent **future value**, not control execution

---

## 🔥 2. How We Achieve “Cancelable Behavior”

👉 3 practical approaches:

---

### ✅ Approach 1: Ignore Result (Flag-based cancellation)

```js
function cancelablePromise() {
  let isCanceled = false;

  const promise = new Promise((resolve) => {
    setTimeout(() => {
      if (!isCanceled) {
        resolve("Completed");
      }
    }, 2000);
  });

  return {
    promise,
    cancel() {
      isCanceled = true;
    },
  };
}

const { promise, cancel } = cancelablePromise();

cancel(); // cancel before completion

promise.then(console.log); // nothing logs
```

### 🧠 How it works:

- We don’t stop execution
- We just **ignore the result**

---

## ⚡ Approach 2: Reject on Cancel

```js
function cancelablePromise() {
  let rejectFn;

  const promise = new Promise((resolve, reject) => {
    rejectFn = reject;

    setTimeout(() => {
      resolve("Success");
    }, 2000);
  });

  return {
    promise,
    cancel() {
      rejectFn("Canceled");
    },
  };
}

const { promise, cancel } = cancelablePromise();

cancel();

promise.catch((err) => console.log(err)); // "Canceled"
```

### 🧠 Why useful:

- Caller knows operation was canceled
- Easier error handling

---

## 🚀 Approach 3: Using `AbortController` (BEST PRACTICE ⭐)

👉 Used with APIs like `fetch`

```js
const controller = new AbortController();
const signal = controller.signal;

fetch("/api/data", { signal })
  .then((res) => res.json())
  .then((data) => console.log(data))
  .catch((err) => console.log(err.name)); // AbortError

// Cancel request
controller.abort();
```

### 🧠 How it works:

- Browser cancels underlying request
- Promise rejects with `AbortError`

💡 This is the **real cancellation**, not just ignoring

---

## 🔥 Tricky Example (Interview Favorite)

```js
let canceled = false;

const promise = new Promise((resolve) => {
  setTimeout(() => resolve("Done"), 1000);
});

promise.then((res) => {
  if (!canceled) {
    console.log(res);
  }
});

canceled = true;
```

👉 Output: ❌ Nothing

💡 WHY:

- Promise still runs
- Result is ignored

### 🧠 Race Condition Handling

```js

function fetchData() {
  if (controller) controller.abort();

  controller = new AbortController();

  return fetch("/api", { signal: controller.signal });
}
```
