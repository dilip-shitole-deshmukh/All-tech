## 🧠 Hoisting (JavaScript)

---

## 🔹 Definition

Hoisting is JavaScript’s behavior where **variable and function declarations are moved to the top of their scope during the compilation phase (before execution)**.

👉 In simple terms:

> “You can use some variables/functions before they are declared because JS internally moves declarations up”

💡 Important:

- Only **declarations are hoisted**, not initializations.

---

## 🔹 Core Explanation

---

### ⚙️ 1. How Hoisting Works Internally

JavaScript execution happens in **2 phases**:

```text
1. Memory Creation Phase (Hoisting happens here)
2. Execution Phase
```

🧠 During memory phase:

- Variables → allocated memory
- Functions → fully stored in memory

👉 Then execution phase runs line by line.

---

### 🟢 2. Hoisting with `var`

```js
console.log(a); // undefined
var a = 10;
```

🧠 What actually happens:

```js
var a; // hoisted
console.log(a); // undefined
a = 10;
```

👉 WHY:

- `var` is hoisted and initialized with `undefined`

---

### 🔵 3. Hoisting with `let` and `const` (TDZ 🔥)

```js
console.log(a); // ❌ ReferenceError
let a = 10;
```

🧠 WHY:

- Hoisted but NOT initialized
- Exists in **Temporal Dead Zone (TDZ)**

👉 TDZ = time between hoisting and initialization

---

### 🟡 4. Function Hoisting

#### ✅ Function Declaration

```js
sayHello();

function sayHello() {
  console.log("Hello");
}
```

👉 Works because:

- Entire function is hoisted

---

#### ❌ Function Expression

```js
sayHi(); // ❌ TypeError

var sayHi = function () {
  console.log("Hi");
};
```

🧠 WHY:

- `var sayHi` → undefined
- Not a function yet

---

### 🔁 Summary Table

| Type                 | Hoisted            | Initialized |
| -------------------- | ------------------ | ----------- |
| var                  | ✅ Yes             | undefined   |
| let                  | ✅ Yes             | ❌ No (TDZ) |
| const                | ✅ Yes             | ❌ No (TDZ) |
| function declaration | ✅ Yes             | ✅ Yes      |
| function expression  | ❌ (only var part) | ❌          |

## 🔹 Example(s) with Code

---

### ✅ Example 1: var Hoisting

```js
console.log(x); // undefined
var x = 5;
```

👉 Output:

```text
undefined
```

---

### ✅ Example 2: let TDZ

```js
console.log(y); // ReferenceError
let y = 10;
```

👉 WHY:

- Accessing before initialization

---

### ✅ Example 3: Function Hoisting

```js
greet();

function greet() {
  console.log("Hello");
}
```

👉 Works fine

---

### ❌ Example 4: Tricky Case 🔥

```js
var x = 1;

function test() {
  console.log(x);
  var x = 2;
}

test();
```

🧠 Output:

```text
undefined
```

👉 Internally:

```js
function test() {
  var x;
  console.log(x); // undefined
  x = 2;
}
```

## 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Thinking variables move physically

👉 Reality:

- Only **memory allocation happens**, not actual code movement

---

### ❌ Mistake 2: Confusing undefined vs ReferenceError

```js
var a → undefined
let a → ReferenceError
```

---

### ❌ Mistake 3: Ignoring TDZ

👉 Causes runtime errors

---

### ❌ Mistake 4: Function expression confusion

👉 Not hoisted like declarations

## 🔹 Interview Q&A

---

### ❓1. What is hoisting?

JS behavior where declarations are moved to top of scope.

---

### ❓2. Are variables hoisted?

✅ Yes (var, let, const)

---

### ❓3. Difference between var and let hoisting?

- var → initialized with undefined
- let → TDZ (not initialized)

---

### ❓4. What is TDZ?

Time between declaration and initialization where variable cannot be accessed.

---

### ❓5. Are functions hoisted?

- Function declarations → yes
- Function expressions → no

---

### ❓6. Why does undefined occur?

Because variable is hoisted but not assigned

---

### ❓7. Why let gives error?

Because it’s in TDZ

---

### ❓8. Best practice?

Declare variables before use

---

## 🔹 Advantages / Pitfalls

---

### ✅ Advantages

- Flexible execution
- Allows function calls before definition

---

### ❌ Pitfalls

- Confusing behavior
- Bugs due to undefined
- TDZ errors

---

## 🔹 Best Practices

---

✔ Always declare variables at top
✔ Prefer `let` and `const` over `var`
✔ Avoid relying on hoisting
✔ Use clear code structure
✔ Keep functions defined before usage
