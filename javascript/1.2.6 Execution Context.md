## 👉 Execution Context — Deep-Dive (Interview Ready)

This is a **🟡 Conceptual / Intermediate Topic** → very important for interviews.
Focus on **HOW JavaScript runs code internally**.

---

# 🔹 Definition

- **Execution Context** is the **environment in which JavaScript code is executed**.
- It contains information about **variables, functions, and the value of `this`**.

👉 Think:
**“Execution Context = Box where JS runs your code.”**

---

# 🔹 Types of Execution Context

---

## 🔸 1. Global Execution Context (GEC)

### ✅ Core Explanation

- Created when your JS program starts.
- There is **only one global execution context**.

It does two main things:

- Creates **global object** (`window` in browser)
- Sets `this` → points to global object

---

## 🔸 2. Function Execution Context (FEC)

### ✅ Core Explanation

- Created **every time a function is invoked**.
- Each function gets its **own execution context**.

👉 WHY:
To maintain separate variable environments for each function call.

---

## 🔸 3. Eval Execution Context (Rare)

- Created when using `eval()` (not recommended).
- Mostly ignored in modern development/interviews.

---

# 🔹 Phases of Execution Context (VERY IMPORTANT)

Every execution context has **2 phases**:

---

## 🔸 1. Creation Phase (Memory Phase)

### ✅ What happens here?

- Memory is allocated for variables and functions.
- Variables → initialized as `undefined`
- Functions → stored completely in memory

👉 This is where **hoisting** happens.

---

## 🔸 2. Execution Phase

### ✅ What happens here?

- Code runs line by line.
- Variables get actual values.
- Functions are executed.

---

# 🔹 Example (Step-by-Step Execution)

### 💻 Code

```js
var x = 10;

function test() {
  var y = 20;
  console.log(x + y);
}

test();
```

---

### 🔍 Step 1: Global Execution Context (Creation Phase)

Memory:

```
x → undefined
test → function definition
```

---

### 🔍 Step 2: Global Execution Context (Execution Phase)

```
x = 10
test() → function call
```

👉 New **Function Execution Context** is created.

---

### 🔍 Step 3: Function Execution Context (Creation Phase)

Memory:

```
y → undefined
```

---

### 🔍 Step 4: Function Execution Context (Execution Phase)

```
y = 20
console.log(10 + 20) → 30
```

---

# 🔹 Call Stack (Execution Order)

### ✅ Core Explanation

- JS uses a **Call Stack** to manage execution contexts.
- It follows **LIFO (Last In First Out)**.

👉 Think: Stack of plates 🍽️

---

### 💻 Example

```js
function a() {
  b();
}
function b() {
  console.log("B");
}
a();
```

### 🔍 Flow

```
Global → a() → b()
```

Stack:

```
[b]
[a]
[Global]
```

Then popped in reverse:

```
b → a → Global
```

# 🔹 Key Concepts Inside Execution Context

---

## 🔸 1. Variable Environment

- Stores variables and function declarations.
- Separate for each execution context.

---

## 🔸 2. Scope Chain

- Used to resolve variables.
- If not found locally → looks in outer scope.

👉 Related to **lexical scope**.

---

## 🔸 3. `this` Binding

- Value of `this` depends on how function is called.
- In global → `window` (browser)

---

# 🔹 Tricky / Edge Cases

---

## ⚠️ Case 1: Hoisting Behavior

```js
console.log(a);
var a = 10;
```

👉 Output: `undefined`

WHY:

- `var a` is hoisted → initialized as `undefined`

---

## ⚠️ Case 2: Function vs Variable Hoisting

```js
foo();

function foo() {
  console.log("Hello");
}
```

👉 Works fine because function is fully hoisted.

---

## ⚠️ Case 3: Function Inside Function

```js
function outer() {
  var a = 10;

  function inner() {
    console.log(a);
  }

  inner();
}
outer();
```

👉 Uses scope chain to access `a`.

# 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Thinking code runs line-by-line only

👉 Actually, JS first does **memory allocation (creation phase)**

---

### ❌ Mistake 2: Confusing hoisting with execution

👉 Hoisting = memory allocation, not execution

---

### ❌ Mistake 3: Ignoring call stack

👉 Leads to confusion in nested function calls

# 🔹 Interview Q&A

---

### 1. What is execution context?

- It’s the environment where JS code runs.
- Contains variables, functions, and `this`.

---

### 2. What are phases of execution context?

- Creation phase → memory allocation
- Execution phase → code execution

---

### 3. What is call stack?

- Data structure managing execution contexts.
- Follows LIFO order.

---

### 4. What is hoisting?

- Variables/functions moved to top during creation phase.
- Variables initialized as `undefined`.

---

### 5. Difference between GEC and FEC?

- GEC → created once for program
- FEC → created for every function call

---

### 6. What is scope chain?

- Mechanism to resolve variables.
- Searches from local → outer scope.

---

### 7. What is variable environment?

- Stores variables and functions inside execution context.

---

### 8. What is `this` in execution context?

- Refers to object calling the function.
- Depends on invocation.
