## 🧠 Optional Chaining (`?.`) & Nullish Coalescing (`??`)

---

## 🔹 Definition

👉 **Optional Chaining (`?.`)**
Safely access nested properties **without throwing errors** if something is `null` or `undefined`.

👉 **Nullish Coalescing (`??`)**
Provides a **default value ONLY when value is `null` or `undefined`** (not for falsy values like `0`, `""`, `false`).

💡 Together, they solve **common runtime errors + incorrect default handling**

---

## 🔹 Core Explanation

---

## 🟢 1. Optional Chaining (`?.`) → Safe Access

```js
const user = { name: "Dilip" };

console.log(user.address?.city); // undefined ✅ (no crash)
```

🧠 How it works:

- Stops evaluation if left side is `null`/`undefined`
- Returns `undefined` instead of throwing error

👉 WHY:

- Prevents:

```js
user.address.city; // ❌ TypeError
```

---

### 🔁 Equivalent Old Way

```js
user && user.address && user.address.city;
```

👉 `?.` is cleaner and readable

---

### ✅ Works with Different Cases

#### 1. Object properties

```js
user?.name;
```

#### 2. Array access

```js
arr?.[0];
```

#### 3. Function calls

```js
user.getName?.();
```

👉 Prevents calling undefined functions

---

## 🔵 2. Nullish Coalescing (`??`) → Default Values

```js
const value = null ?? "Default";
console.log(value); // "Default"
```

🧠 How it works:

- Returns right side ONLY if left side is:
  - `null`
  - `undefined`

---

### ⚠️ Difference from `||` (Important 🔥)

```js
console.log(0 || 10); // 10 ❌
console.log(0 ?? 10); // 0 ✅
```

👉 WHY:

- `||` treats all falsy values as false
- `??` only checks null/undefined

---

## 🟡 3. Combining Both (Real Power 🔥)

```js
const user = {};

const city = user.address?.city ?? "Unknown";

console.log(city); // "Unknown"
```

🧠 Flow:

1. `user.address` → undefined
2. `?.city` → undefined
3. `??` → fallback used

## 🔹 Example(s) with Code

---

### ✅ Example 1: Deep Nested Access

```js
const data = {
  user: {
    profile: {
      name: "Dilip",
    },
  },
};

console.log(data.user?.profile?.name); // Dilip
```

👉 Safe even if any level missing

---

### ✅ Example 2: API Response Handling

```js
const response = {};

const name = response.data?.user?.name ?? "Guest";
```

👉 Prevents crashes in UI

---

### ⚠️ Example 3: Tricky Case

```js
const count = 0;

console.log(count || 5); // 5 ❌
console.log(count ?? 5); // 0 ✅
```

👉 Important interview question

## 🔹 When to Use / When NOT to Use

---

### ✅ Use Optional Chaining

- Accessing nested data
- API responses
- Optional functions

---

### ✅ Use Nullish Coalescing

- Default values
- When `0`, `false`, `""` are valid

---

### ❌ Avoid

- Overusing deeply chained expressions
- Using `??` when `||` is intended

---

## 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Using `||` instead of `??`

👉 Leads to wrong defaults

---

### ❌ Mistake 2: Overusing optional chaining

```js
user?.address?.city?.length?.toString();
```

👉 Hard to read

---

### ❌ Mistake 3: Assuming `?.` handles everything

```js
(user?.name).toUpperCase(); // ❌ may crash
```

👉 `?.` only applies to that access

---

### ❌ Mistake 4: Mixing `??` and `||` incorrectly

```js
a ?? b || c // ❌ syntax error (needs parentheses)
```

## 🔹 Interview Q&A

---

### ❓1. What is optional chaining?

Safe property access operator

---

### ❓2. What problem does it solve?

Prevents "Cannot read property of undefined"

---

### ❓3. What is nullish coalescing?

Default value operator for null/undefined

---

### ❓4. Difference between `||` and `??`?

- `||` → falsy
- `??` → null/undefined only

---

### ❓5. Can optional chaining be used with functions?

✅ Yes (`fn?.()`)

---

### ❓6. Does `?.` prevent all errors?

❌ No (only null/undefined access)

---

### ❓7. Can we chain multiple `?.`?

✅ Yes

---

### ❓8. Why is `??` preferred for defaults?

Avoids overriding valid falsy values

---

## 🔹 Advantages / Pitfalls

---

### ✅ Advantages

- Prevent runtime crashes
- Cleaner syntax
- Better readability

---

### ❌ Pitfalls

- Overuse reduces readability
- Misunderstanding `??` vs `||`
- Partial safety (not full protection)

---

## 🔹 Best Practices

---

✔ Use `?.` for safe access
✔ Use `??` for defaults (instead of `||`)
✔ Avoid deep chaining
✔ Combine both smartly
✔ Keep expressions readable

---
