## 🧠 Expression vs Statement (JavaScript Deep Dive)

This is a **🟢 Basic but IMPORTANT Topic** — interviewers expect **clear distinction + tricky cases (function, arrow, IIFE, JSX, etc.)**.

---

# 🔹 Definition

👉 **Expression**

- A piece of code that **produces a value**

👉 **Statement**

- A piece of code that **performs an action** (does something)

💡 Simple interview line:

> “Expressions return values, while statements perform actions.”

---

# 🔹 Core Difference (Must Remember)

| Feature        | Expression 🧮 | Statement 🧾 |
| -------------- | ------------- | ------------ |
| Returns value  | ✅ Yes        | ❌ No        |
| Can assign     | ✅ Yes        | ❌ No        |
| Can use in JSX | ✅ Yes        | ❌ No        |

---

# 🔹 Core Explanation

---

## 🧩 1. Expression (Produces Value)

👉 Anything that evaluates to a value

---

### 🔧 Examples

```js id="exp1"
5 + 10; // 15
("Hello"); // string
true && false; // false
```

---

👉 Can be assigned:

```js id="exp2"
let x = 5 + 10;
```

---

💡 WHY:

- Because it returns a value

---

## 🧾 2. Statement (Performs Action)

👉 Executes instructions but doesn’t return value

---

### 🔧 Examples

```js id="stmt1"
if (true) {
  console.log("Hello");
}
```

```js id="stmt2"
for (let i = 0; i < 5; i++) {}
```

---

💡 WHY:

- Controls flow, not value

---

# 🔹 Tricky & Important Cases (Interview Favorite)

---

## ⚠️ 1. Function Declaration vs Expression

---

### ❌ Function Declaration (Statement)

```js id="fn1"
function greet() {
  return "Hi";
}
```

👉 Statement → defines function

---

### ✅ Function Expression

```js id="fn2"
const greet = function () {
  return "Hi";
};
```

👉 Expression → assigned to variable

---

---

## ⚠️ 2. Arrow Functions

```js id="fn3"
const add = (a, b) => a + b;
```

👉 Always an **expression**

---

---

## ⚠️ 3. IIFE (Immediately Invoked Function)

```js id="fn4"
(function () {
  console.log("Run");
})();
```

👉 Expression (wrapped in parentheses)

---

💡 WHY:

- JS expects expression, not statement

---

---

## ⚠️ 4. if Statement vs Ternary Expression

---

### ❌ Statement

```js id="if1"
if (isLoggedIn) {
  showDashboard();
}
```

---

### ✅ Expression

```js id="if2"
isLoggedIn ? showDashboard() : showLogin();
```

---

💡 Key difference:

- Ternary returns value → expression

---

---

## ⚠️ 5. JSX (React Interview Trap)

```jsx id="jsx1"
{
  isLoggedIn ? <Dashboard /> : <Login />;
}
```

👉 Works because:

- JSX expects **expressions only**

---

❌ Not allowed:

```jsx id="jsx2"
if (isLoggedIn) { ... } ❌
```

# 🔹 Real-world Use Cases

---

## ⚛️ React Development

- JSX only accepts expressions

---

## 🧮 Functional Programming

- Expressions preferred (pure functions)

---

## 🧩 Clean Code

- Expressions make code concise

---

# 🔹 When to Use / NOT Use

---

### ✅ Use Expressions when:

- Need value
- Writing functional/clean code
- JSX rendering

---

### ❌ Avoid Expressions when:

- Complex logic becomes unreadable

---

### ✅ Use Statements when:

- Control flow needed
- Complex branching

---

# 🔹 Common Mistakes / Traps

---

## ❌ “Everything is expression”

👉 Wrong

- JS has both

---

## ❌ Using statements inside JSX

👉 Causes errors

---

## ❌ Confusing function declaration vs expression

👉 Important in hoisting

---

## ❌ Overusing ternary

```js id="ternary1"
a ? b : c ? d : e ? f : g ❌
```

👉 Hard to read

---

# 🔹 Advantages & Pitfalls

---

## 🧮 Expressions

### ✅ Advantages

- Concise
- Composable
- Functional style

### ⚠️ Pitfalls

- Hard to read if complex

---

## 🧾 Statements

### ✅ Advantages

- Clear logic flow
- Easier debugging

### ⚠️ Pitfalls

- More verbose

---

# 🔹 Best Practices

✔ Prefer expressions for simple logic
✔ Use statements for complex control flow
✔ Avoid nested ternaries
✔ Use meaningful variable names
✔ Keep code readable

---

# 🔹 Senior-Level Insights 🧠

---

## ⚡ 1. Expression-based Programming

👉 Modern JS prefers expressions:

```js id="exprmodern"
const result = condition && doSomething();
```

---

## 🔄 2. Immutability & Expressions

- Expressions align with:
  - Functional programming
  - Pure functions

---

## 🧠 3. Hoisting Difference

- Function declaration → hoisted
- Function expression → not hoisted

---

## ⚙️ 4. Compiler Perspective

- JS engine treats:
  - Statements → execution flow
  - Expressions → value computation

# 🔹 Interview Q&A 🎯

---

### 1. What is expression?

Code that evaluates to a value.

---

### 2. What is statement?

Code that performs an action.

---

### 3. Key difference?

Expression returns value, statement does not.

---

### 4. Is function declaration expression?

No, it is a statement.

---

### 5. Is arrow function expression?

Yes.

---

### 6. Why JSX allows expressions only?

Because it needs values to render UI.

---

### 7. Example of expression?

`5 + 3`

---

### 8. Example of statement?

`if`, `for`, `while`

---

### 9. What is ternary operator?

An expression that returns a value.

---

### 10. Why avoid nested ternary?

Reduces readability.

---

# ✅ Final Summary (Interview Answer)

👉 “Expressions are pieces of code that return values, while statements perform actions. Expressions can be assigned to variables and used in places like JSX, whereas statements control program flow. Understanding the difference is important for writing clean and predictable JavaScript.”
