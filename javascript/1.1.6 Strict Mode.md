## 👉 Strict Mode (`"use strict"`)

---

## 🔹 Definition

Strict Mode is a way to **opt into a stricter version of JavaScript** by adding `"use strict"` at the top of a file or function.

👉 It helps:

- Catch silent errors
- Prevent unsafe actions
- Make code more predictable and maintainable

---

## 🔹 Core Explanation

### 🟡 1. How to Enable Strict Mode

```javascript
"use strict";
```

- Can be applied:
  - Globally (entire file)
  - Locally (inside a function)

👉 Important:

- In modern JS (ES Modules, classes), strict mode is **enabled by default**

---

### 🟡 2. Prevents Accidental Globals

```javascript
"use strict";

x = 10; // ❌ ReferenceError
```

👉 Without strict mode:

- JS silently creates a global variable → dangerous

👉 With strict mode:

- Throws error → prevents bugs and memory leaks

---

### 🟡 3. `this` Behavior Changes

```javascript
"use strict";

function test() {
  console.log(this);
}
test(); // undefined
```

👉 Without strict mode:

- `this` → global object (`window`)

👉 With strict mode:

- `this` → `undefined`

💡 Why:

- Prevents accidental access to global scope

---

### 🟡 4. Disallows Duplicate Parameters

```javascript
"use strict";

function sum(a, a) {
  // ❌ Error
  return a + a;
}
```

👉 Why:

- Avoids confusion and unexpected overwriting

---

### 🟡 5. Makes Assignments Safer

```javascript
"use strict";

let obj = {};
Object.defineProperty(obj, "x", { value: 10, writable: false });

obj.x = 20; // ❌ TypeError
```

👉 Without strict mode:

- Fails silently

👉 With strict mode:

- Throws error → easier debugging

---

### 🟡 6. Restricts Deleting Variables

```javascript
"use strict";

let x = 10;
delete x; // ❌ Error
```

👉 Why:

- Prevents breaking variable bindings

---

## 🔹 Example(s) with Code

### ⚠️ Example 1: Silent Error vs Strict Mode

```javascript
// Without strict mode
x = 5;
console.log(x); // 5 (global variable created)
```

```javascript
"use strict";
x = 5; // ❌ ReferenceError
```

👉 Explanation:

- Strict mode stops accidental global pollution

---

### ⚠️ Example 2: `this` Behavior

```javascript
function show() {
  console.log(this);
}
show(); // window (non-strict)
```

```javascript
"use strict";
function show() {
  console.log(this);
}
show(); // undefined
```

👉 Why:

- Forces safer function execution context

---

### ⚠️ Example 3: Reserved Keywords

```javascript
"use strict";

let public = 10; // ❌ Error
```

👉 Why:

- Prevents using future reserved keywords

---

## 🔹 Real-world Use Cases

- 🔹 Prevent bugs in large codebases (especially React/Angular apps)
- 🔹 Avoid accidental global variables (memory leaks)
- 🔹 Safer refactoring and debugging
- 🔹 Used automatically in modern bundlers (Vite, Webpack, ES modules)

---

## 🔹 When to use / When NOT to use

### ✅ Use:

- Always use strict mode in legacy scripts
- Modern projects → already enabled (ES modules)

### ❌ Avoid:

- Mixing strict and non-strict code inconsistently
- Relying on non-strict behaviors (like implicit globals)

---

## 🔹 Common Mistakes / Traps

### ❌ Mistake 1: Thinking strict mode is optional in modern JS

👉 Reality:

- ES Modules (`import/export`) already use strict mode

---

### ❌ Mistake 2: Confusion with `this`

```javascript
"use strict";
function test() {
  console.log(this);
}
```

👉 Developers expect `window`, but get `undefined`

---

### ❌ Mistake 3: Silent failures assumption

👉 Developers assume code will "just fail silently"

👉 Reality:

- Strict mode throws errors → breaks execution (good for debugging)

## 🔹 Interview Q&A

### ❓ 1. What is Strict Mode?

- A restricted version of JS enabled using `"use strict"`
- Helps catch errors and enforce safer coding

---

### ❓ 2. Is strict mode default in modern JS?

- Yes, in ES modules and classes
- No need to explicitly add in modern setups

---

### ❓ 3. What happens if you assign undeclared variable?

- Non-strict → becomes global
- Strict → throws ReferenceError

---

### ❓ 4. How does `this` behave in strict mode?

- In functions → `undefined`
- Prevents accidental global access

---

### ❓ 5. Can you use duplicate parameters?

- No, strict mode throws error

---

### ❓ 6. Why is strict mode useful?

- Prevents bugs
- Makes debugging easier
- Enforces cleaner code

---

### ❓ 7. Can strict mode improve performance?

- Indirectly yes
- Engines can optimize better due to predictable behavior

---

## 🔹 Advantages / Pitfalls

### ✅ Advantages

- Catches errors early
- Prevents unsafe practices
- Makes code more predictable
- Helps JS engines optimize

### ❌ Pitfalls

- Can break old code relying on non-strict behavior
- Requires understanding differences (`this`, globals)

---

## 🔹 Best Practices

✔ Use ES modules (strict mode by default)
✔ Avoid relying on implicit globals
✔ Always declare variables (`let`, `const`)
✔ Understand `this` behavior changes
✔ Use strict mode for legacy scripts

---

## 🔹 Final Summary (Interview Ready)

- `"use strict"` → enables stricter JS rules
- Prevents silent errors (globals, assignments)
- Changes behavior of `this`, parameters, deletion
- Default in modern JS (ES modules)

💡 **Golden Insight:**
👉 “Strict mode doesn’t add new features — it removes dangerous ones to make JavaScript safer and more predictable.”
