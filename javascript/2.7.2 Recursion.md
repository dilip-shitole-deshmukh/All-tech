## 👉 Recursion (JavaScript)

---

## 🔹 Definition

👉 **Recursion** is a technique where a function **calls itself** to solve a problem.

📌 Simple:

> A function keeps calling itself until a **base condition** is met.

---

## 🔹 Core Explanation

### 🧠 1. Two Key Parts of Recursion

Every recursive function must have:

1. **Base Case (Stopping Condition)**
   - Prevents infinite calls
   - When this condition is met → recursion stops

2. **Recursive Case (Self-call)**
   - Function calls itself with a smaller/simpler input

💡 Without base case → **infinite recursion → stack overflow**

---

### 🔄 2. How Recursion Works Internally

- Each function call is pushed into the **call stack**
- Execution pauses until deeper calls return
- Once base case is reached → stack **unwinds (LIFO)**

📦 Think of it like:

> Stacking plates → remove from top in reverse order

---

### ⚠️ 3. Stack Behavior (Important for Interviews)

- Each recursive call creates a **new execution context**
- Memory increases with depth
- Too deep recursion → `RangeError: Maximum call stack size exceeded`

---

## 🔹 Example(s) with Code

### ✅ Example 1: Factorial

```js id="m0rz2f"
function factorial(n) {
  if (n === 0) return 1; // base case
  return n * factorial(n - 1); // recursive call
}

console.log(factorial(5)); // 120
```

🧩 **Execution Flow:**

```
factorial(5)
= 5 * factorial(4)
= 5 * 4 * factorial(3)
= 5 * 4 * 3 * factorial(2)
= 5 * 4 * 3 * 2 * factorial(1)
= 5 * 4 * 3 * 2 * 1
= 120
```

💡 Stack grows → then resolves backward

---

### ⚠️ Example 2: Missing Base Case

```js id="gyrkp4"
function infinite(n) {
  return infinite(n + 1);
}
```

👉 ❌ No base case → infinite recursion → crash

---

### 🧩 Example 3: Tree Traversal (Real-world)

```js id="gd6azp"
const tree = {
  value: 1,
  children: [
    { value: 2, children: [] },
    { value: 3, children: [] },
  ],
};

function traverse(node) {
  console.log(node.value);
  node.children.forEach((child) => traverse(child));
}

traverse(tree);
```

💡 WHY recursion:

- Data is **nested/recursive in nature**

## 🔹 Real-world Use Cases

### 🌳 1. Working with Nested Data (JSON)

- API responses often deeply nested
- Recursion helps traverse unknown depth

---

### 🌐 2. DOM Traversal

- Traversing child nodes in DOM tree
- Similar structure → perfect for recursion

---

### 🔍 3. Search Algorithms

- DFS (Depth First Search)
- Used in trees/graphs

---

### ⚛️ 4. React Patterns

- Rendering nested components (menus, comments)
- Recursive component rendering

---

## 🔹 When to Use / When NOT to Use

### ✅ Use Recursion When:

- Problem has **repeating substructure**
- Data is **tree-like or nested**
- Solution can be divided into smaller subproblems

---

### ❌ Avoid When:

- Deep recursion (risk of stack overflow)
- Iterative solution is simpler and more efficient
- Performance is critical

---

## 🔹 Common Mistakes / Traps

### ❌ Mistake 1: Missing Base Case

👉 Leads to infinite recursion and crash

---

### ❌ Mistake 2: Incorrect Base Condition

```js id="nzpmt1"
if (n === 1) return 1; // ❌ what about n=0?
```

👉 Edge cases ignored

---

### ❌ Mistake 3: Not Reducing Problem Size

```js id="l5r86v"
return fn(n); // ❌ no progress toward base case
```

👉 Recursion must move toward termination

---

### ❌ Mistake 4: Ignoring Stack Limits

- JS does NOT optimize tail recursion reliably
- Deep recursion can break in production

## 🔹 Interview Q&A

### ❓1. What is recursion?

👉 A function calling itself until a base condition is met.

---

### ❓2. Why do we need base case?

👉 To stop recursion; otherwise it runs infinitely and crashes.

---

### ❓3. What is call stack in recursion?

👉 Each function call is stored in stack memory and resolved in reverse order.

---

### ❓4. Recursion vs Iteration?

👉 Recursion is cleaner for tree problems; iteration is more memory-efficient.

---

### ❓5. What is stack overflow?

👉 When too many recursive calls exceed call stack limit.

---

### ❓6. Can recursion replace loops?

👉 Yes, but not always efficient.

---

### ❓7. What is tail recursion?

👉 When recursive call is last operation (JS has limited optimization support).

---

### ❓8. When should you avoid recursion?

👉 When depth is very large or iterative solution is simpler.

---

## 🔹 Advantages / Pitfalls

### ✅ Advantages

- Elegant and clean code
- Ideal for tree/recursive structures
- Reduces complex logic into smaller parts

---

### ⚠️ Pitfalls

- Stack overflow risk
- Higher memory usage
- Harder to debug for beginners

---

## 🔹 Best Practices

✔ Always define a clear base case
✔ Ensure each call reduces problem size
✔ Handle edge cases (0, null, empty)
✔ Prefer iteration for large inputs
✔ Use memoization for optimization

---

## 🔹 Senior-Level Insights

### ⚡ 1. Performance Optimization (Memoization)

```js id="o6wqsg"
const memo = {};

function fib(n) {
  if (n <= 1) return n;
  if (memo[n]) return memo[n];

  memo[n] = fib(n - 1) + fib(n - 2);
  return memo[n];
}
```

💡 Avoids repeated calculations → improves from O(2ⁿ) to O(n)

---

### ⚡ 2. Recursion vs Iteration Trade-off

| Aspect      | Recursion     | Iteration |
| ----------- | ------------- | --------- |
| Readability | High (clean)  | Medium    |
| Performance | Lower (stack) | Better    |
| Memory      | Higher        | Lower     |

---

### ⚡ 3. Tail Call Optimization (TCO)

- Some languages optimize recursion
- JavaScript **does NOT reliably support TCO**
- So deep recursion is risky
