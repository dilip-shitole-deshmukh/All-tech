## 📦 JSON & Data Serialization (Frontend Deep Dive)

This is a **🟡 Conceptual + Practical Topic**, but interviewers often extend into **API communication, edge cases, and performance**, so we’ll cover **HOW + WHY + pitfalls**.

---

# 🔹 Definition

👉 **JSON (JavaScript Object Notation)**

- A lightweight data format used to **store and exchange data**
- Based on JavaScript object syntax, but language-independent

👉 **Serialization**

- Converting data (object) → **string format** (e.g., JSON)

👉 **Deserialization**

- Converting string → **usable object**

💡 Simple interview line:

> “Serialization converts objects into transferable format (JSON), and deserialization converts them back into usable data.”

---

# 🔹 Core Explanation

---

## 🧩 1. What is JSON Structure

```json
{
  "name": "Dilip",
  "age": 25,
  "isActive": true
}
```

---

### 🧠 Rules:

- Keys must be **strings (double quotes)**
- No functions, undefined, or comments
- Supports:
  - string
  - number
  - boolean
  - null
  - array
  - object

---

💡 WHY JSON is popular:

- Lightweight
- Easy to parse
- Language-independent

---

## 🔄 2. Serialization (Object → JSON)

👉 Using `JSON.stringify()`

```js id="json1"
const user = { name: "Dilip", age: 25 };

const json = JSON.stringify(user);

console.log(json);
// '{"name":"Dilip","age":25}'
```

---

## 🧠 Execution

- Object converted into string
- Ready for:
  - Network transfer
  - Storage

---

## 🔁 3. Deserialization (JSON → Object)

👉 Using `JSON.parse()`

```js id="json2"
const json = '{"name":"Dilip","age":25}';

const obj = JSON.parse(json);

console.log(obj.name); // Dilip
```

---

## 🧠 Execution

- String parsed into JS object
- Can now be used in code

---

# 🔹 Tricky Cases (Interview Favorite)

---

## ⚠️ 1. Functions are Ignored

```js id="json3"
const obj = {
  name: "Dilip",
  greet: () => "Hi",
};

JSON.stringify(obj);
```

👉 Output:

```json
{ "name": "Dilip" }
```

---

💡 WHY:

- JSON doesn’t support functions

---

## ⚠️ 2. Undefined is Removed

```js id="json4"
const obj = { a: undefined };

JSON.stringify(obj); // '{}'
```

---

---

## ⚠️ 3. Date Becomes String

```js id="json5"
const obj = { date: new Date() };

JSON.stringify(obj);
```

👉 Converts to ISO string

---

---

## ⚠️ 4. Circular Reference Error

```js id="json6"
const obj = {};
obj.self = obj;

JSON.stringify(obj); ❌
```

👉 Error: Converting circular structure

---

---

## ⚠️ 5. NaN / Infinity

```js id="json7"
JSON.stringify({ value: NaN });
```

👉 Output:

```json
{ "value": null }
```

---

# 🔹 Advanced Features

---

## ⚙️ 1. Replacer (Customize Serialization)

```js id="json8"
JSON.stringify(obj, (key, value) => {
  if (key === "password") return undefined;
  return value;
});
```

👉 Used to filter data

---

## ⚙️ 2. Reviver (Customize Parsing)

```js id="json9"
JSON.parse(json, (key, value) => {
  if (key === "date") return new Date(value);
  return value;
});
```

# 🔹 When to Use / NOT Use

---

### ✅ Use JSON when:

- Sending data over network
- Storing structured data

---

### ❌ Avoid JSON when:

- Need functions or methods
- Complex object graphs (circular refs)

---

# 🔹 Common Mistakes / Traps

---

## ❌ “JSON is JavaScript object”

👉 Wrong

- JSON is string format

---

## ❌ Forgetting stringify

```js id="json11"

```

---

## ❌ Not handling parse errors

```js id="json12"

```

👉 Throws error

---

## ❌ Expecting functions in JSON

👉 Not supported

# 🔹 Advantages & Pitfalls

---

## ✅ Advantages

- Lightweight
- Easy to read
- Cross-language support

---

## ⚠️ Pitfalls

- No functions
- No circular references
- Limited data types

---

# 🔹 Best Practices

✔ Always validate JSON before parsing
✔ Use try/catch with JSON.parse
✔ Avoid storing sensitive data
✔ Use replacer to filter data
✔ Convert dates manually if needed

---

# 🔹 Senior-Level Insights 🧠

---

## ⚡ 1. Serialization Cost (Performance)

- Large objects → slow stringify/parse
  👉 Optimize:
- Send minimal data
- Use pagination

---

## 🔄 2. JSON vs Other Formats

| Format   | Use Case         |
| -------- | ---------------- |
| JSON     | Standard APIs    |
| XML      | Legacy systems   |
| ProtoBuf | High performance |

---

## 📊 3. Data Normalization

- Avoid deeply nested JSON
  👉 Improves performance and maintainability

---

## 🧠 4. Security Consideration

- Never trust JSON from external sources
  👉 Validate input

---

## ⚙️ 5. Streaming JSON (Advanced)

- Large data → process in chunks
- Avoid full memory load
