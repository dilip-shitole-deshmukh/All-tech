## 🧠 State Management (Redux Toolkit) — Deep Dive

This is a **🔴 Advanced + Architecture Topic** — interviewers expect **internals, flow, performance, and why Redux Toolkit exists** (not just syntax).

---

# 🔹 Definition

👉 **State Management** is how an application manages and shares data across components.

👉 **Redux Toolkit (RTK)** is the official, modern way to use Redux that:

- Reduces boilerplate
- Simplifies logic
- Provides best practices by default

💡 Simple interview line:

> “Redux Toolkit is a modern abstraction over Redux that simplifies global state management using slices, reducers, and built-in utilities.”

---

# 🔹 Core Redux Concepts (Foundation)

---

## 🧩 1. Store (Single Source of Truth)

👉 Central place where all application state lives

```js id="rtk1"
const store = configureStore({
  reducer: rootReducer,
});
```

---

💡 WHY:

- Ensures predictable state
- Easy debugging

---

## 🔄 2. Actions

👉 Plain objects describing **what happened**

```js id="rtk2"
{
  type: "counter/increment";
}
```

---

💡 Think:

> “Action = event”

---

## ⚙️ 3. Reducers

👉 Functions that update state based on action

```js id="rtk3"
(state, action) => newState;
```

---

💡 Rule:

- Must be **pure functions**
- No side effects

---

## 🔁 4. Flow (Important)

```id="flow1"
Component → dispatch(action)
        → reducer updates state
        → store updates
        → UI re-renders
```

---

# 🔹 Redux Toolkit (What it Improves)

---

## ❌ Old Redux Problems

- Too much boilerplate
- Manual immutability handling
- Complex setup

---

## ✅ RTK Solutions

- `createSlice()` → combines actions + reducers
- `configureStore()` → simplified setup
- Uses **Immer** → allows "mutating" syntax safely

---

# 🔹 Example (Redux Toolkit)

---

## 🧩 Slice

```js id="rtk4"
import { createSlice } from "@reduxjs/toolkit";

const counterSlice = createSlice({
  name: "counter",
  initialState: { value: 0 },
  reducers: {
    increment: (state) => {
      state.value += 1; // safe (Immer)
    },
    decrement: (state) => {
      state.value -= 1;
    },
  },
});

export const { increment, decrement } = counterSlice.actions;
export default counterSlice.reducer;
```

---

## 🏗️ Store

```js id="rtk5"
import { configureStore } from "@reduxjs/toolkit";
import counterReducer from "./counterSlice";

const store = configureStore({
  reducer: {
    counter: counterReducer,
  },
});
```

---

## ⚛️ Usage in React

```js id="rtk6"
import { useSelector, useDispatch } from "react-redux";

function Counter() {
  const count = useSelector((state) => state.counter.value);
  const dispatch = useDispatch();

  return (
    <>
      <span>{count}</span>
      <button onClick={() => dispatch(increment())}>+</button>
    </>
  );
}
```

---

## 🧠 Execution Flow

1. Button click → dispatch action
2. Reducer updates state
3. Store updates
4. Component re-renders

# 🔹 Async Handling (Very Important)

---

## ⚡ createAsyncThunk

```js id="rtk7"
export const fetchData = createAsyncThunk("data/fetch", async () => {
  const res = await fetch("/api/data");
  return res.json();
});
```

---

## 🧠 WHY:

- Handles:
  - pending
  - fulfilled
  - rejected

👉 No need for manual async logic

# 🔹 When to Use / NOT Use

---

### ✅ Use Redux Toolkit when:

- Complex state
- Shared across many components
- Predictable state needed

---

### ❌ Avoid when:

- Small app
- Simple local state

- `useState`
- `useContext`

✔ Use selectors for derived data
✔ Avoid unnecessary global state

# 🔹 Senior-Level Insights 🧠

---

## ⚡ 1. Normalized State

👉 Store data like DB:

```js id="norm1"
{
  users: {
    byId: { 1: {...}, 2: {...} },
    allIds: [1, 2]
  }
}
```

💡 Improves performance

---

## 🔄 2. Selector Optimization

👉 Use memoized selectors (Reselect)

- Prevent unnecessary re-renders

---

## 📊 3. Performance Consideration

- Too many updates → re-renders
  👉 Solution:
- Split slices
- Use selectors

---

## ⚙️ 4. RTK Query (Modern Approach)

👉 Built-in data fetching solution

- Caching
- Auto refetch
- Simplifies API handling

---

## 🧠 5. Alternative State Tools

- Context API → simple cases
- Zustand → lightweight
- React Query → server state
