## 🧾 `sessionStorage` (JavaScript Deep Dive)

This is a **🟡 Conceptual + Practical Topic** — very similar to `localStorage`, but interviewers check if you clearly understand **lifetime, tab scope, and differences**.

---

# 🔹 Definition

👉 `sessionStorage` is a **Web Storage API** that stores data as **key–value pairs for a single browser session**.

- Data persists **only while the tab is open**
- Each tab has its **own isolated storage**

💡 Simple interview line:

> “`sessionStorage` stores data per tab session and is cleared when the tab or browser is closed.”

---

# 🔹 Core Explanation

---

## 🧠 1. Basic API Methods

```js id="ss1"
sessionStorage.setItem("name", "Dilip");
sessionStorage.getItem("name");
sessionStorage.removeItem("name");
sessionStorage.clear();
```

---

### 🔍 Behavior:

- Same API as `localStorage`
- Works synchronously
- Stores only **strings**

---

---

## 🧩 2. Data Storage Format

```js id="ss2"
sessionStorage.setItem("age", 25);
```

👉 Stored as:

```id="ss2o"
"25"
```

---

👉 For objects:

```js id="ss3"
sessionStorage.setItem("user", JSON.stringify({ name: "Dilip" }));
```

---

👉 Retrieve:

```js id="ss4"
const user = JSON.parse(sessionStorage.getItem("user"));
```

---

💡 Same JSON rules apply

---

---

## ⚙️ 3. Session Scope (KEY DIFFERENCE)

👉 Data exists only for **that tab session**

- Refresh page → data persists ✅
- Close tab → data removed ❌

---

💡 Important:

> Each tab gets its own sessionStorage

---

---

## 🧠 4. Tab Isolation Behavior

👉 Example:

- Open same website in 2 tabs
- Each tab has **different sessionStorage**

---

💡 WHY:

> sessionStorage is tied to the **window/tab context**, not just origin

---

---

## 🧩 5. Same-Origin Policy

👉 Like `localStorage`, it follows:

- Same domain + protocol
- No cross-origin access

---

---

# 🔹 Tricky Behavior (Interview Focus)

---

## ⚠️ 1. Data Lost on Tab Close

```js id="ss5"
sessionStorage.setItem("temp", "data");
```

👉 Close tab → data gone

---

💡 Unlike localStorage

---

---

## ⚠️ 2. Not Shared Across Tabs

👉 Even same URL:

```js id="ss6"
sessionStorage.getItem("key");
```

👉 Different values per tab

---

---

## ⚠️ 3. Everything is String

```js id="ss7"
sessionStorage.setItem("isLoggedIn", true);
```

👉 Output:

```id="ss7o"
"true"
```

---

---

## ⚠️ 4. Synchronous API

👉 Blocks main thread

```js id="ss8"
sessionStorage.setItem("bigData", data);
```

---

💡 Avoid heavy operations

---

# 🔹 Example (End-to-End)

---

```js id="ss9"
const user = { name: "Dilip" };

// Store
sessionStorage.setItem("user", JSON.stringify(user));

// Retrieve
const data = JSON.parse(sessionStorage.getItem("user"));

console.log(data.name); // Dilip
```

# 🔹 When to Use / NOT Use

---

### ✅ Use sessionStorage when:

- Data is temporary
- Tab-specific behavior needed
- Session-based state

---

### ❌ Avoid when:

- Need persistence after tab close
- Need sharing across tabs
- Storing sensitive data

---

# 🔹 Common Mistakes / Traps

---

## ❌ Confusing with localStorage

👉 sessionStorage is temporary

---

## ❌ Expecting cross-tab sharing

👉 Not supported

---

## ❌ Storing objects directly

👉 Must stringify

---

## ❌ Storing sensitive data

👉 Security risk

---

# 🔹 Advantages & Pitfalls

---

## ✅ Advantages

- Automatic cleanup (on tab close)
- Tab-specific isolation
- Simple API

---

## ⚠️ Pitfalls

- Data loss on tab close
- Only strings supported
- Synchronous API
- Limited size (~5MB)

---

# 🔹 Best Practices

✔ Use JSON.stringify/parse
✔ Use for temporary data only
✔ Avoid storing sensitive info
✔ Keep data small
✔ Use meaningful keys

---

# 🔹 Senior-Level Insights 🧠

---

## ⚡ 1. UX Optimization

👉 sessionStorage is great for:

- Preventing form loss

---

## 🔄 2. localStorage vs sessionStorage Strategy

| Feature  | localStorage | sessionStorage  |
| -------- | ------------ | --------------- |
| Lifetime | Persistent   | Session only    |
| Scope    | Shared       | Per tab         |
| Use case | Preferences  | Temporary state |

---

## 🔐 3. Security Consideration

- Vulnerable to XSS
  👉 Avoid storing:
- Tokens
- Sensitive user data

---

## 📊 4. Performance Consideration

- Avoid frequent writes
- Avoid large data

---

## 🧠 5. State Management Integration

- Used for:
  - temporary persistence
  - page reload recovery

# 🔹 Interview Q&A 🎯

---

### 1. What is sessionStorage?

Browser storage for session-based data.

---

### 2. When does it expire?

When tab/browser is closed.

---

### 3. Difference from localStorage?

localStorage persists, sessionStorage does not.

---

### 4. Is it shared across tabs?

No.

---

### 5. What type of data can it store?

Only strings.

---

### 6. How to store objects?

Using JSON.stringify.

---

### 7. Is it synchronous?

Yes.

---

### 8. Storage limit?

~5MB.

---

### 9. Is it secure?

No, vulnerable to XSS.

---

### 10. When to use it?

Temporary session data.

---

# ✅ Final Summary (Interview Answer)

👉 “`sessionStorage` is a browser storage API that stores data per tab session. It persists across page reloads but is cleared when the tab is closed. It is useful for temporary state management but should not be used for sensitive or long-term data.”
