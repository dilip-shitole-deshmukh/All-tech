# 🧠 Global vs Function Execution Context (JavaScript)

---

## 🔹 Definition

👉 **Simple Definition:**

- **Global Execution Context (GEC)** is created when JS starts executing the file.
- **Function Execution Context (FEC)** is created every time a function is invoked.

👉 **Slightly Deeper:**

- GEC acts as the **root environment**, holding global variables and functions.
- FEC is a **temporary execution environment**, created per function call, with its own variables, scope, and `this`.

---

# 🔹 Deep Explanation (Core Section)

---

## 1️⃣ Global Execution Context (GEC)

### 🧠 What it is

- The **default execution context** created once when the JS engine starts.
- There is **only one GEC per program**.

### ⚙️ Internal Working

- During creation phase:
  - Creates **global object** (`window` in browser, `global` in Node)
  - Sets `this = global object`
  - Allocates memory for:
    - Variables (`var` → attached to global object)
    - Functions (fully hoisted)

- Also creates **scope chain root**

### 💡 Why it behaves this way

- JS needs a **starting point** to execute code.
- Acts as the **base of scope chain** for all nested contexts.

### ⚠️ Edge Cases

- `let/const` are NOT attached to global object (they live in separate environment)
- Global variables can cause **name collisions**

---

## 2️⃣ Function Execution Context (FEC)

### 🧠 What it is

- Created every time a function is called.
- Each call gets its **own isolated context**.

### ⚙️ Internal Working

- Creation phase:
  - Creates:
    - Variable Environment (local vars)
    - Arguments object
    - `this` binding (depends on call-site)

  - Links to **outer lexical environment**

- Execution phase:
  - Runs code line-by-line
  - Resolves variables via scope chain

### 💡 Why it behaves this way

- Functions need **independent memory space**
- Enables:
  - Recursion
  - Closures
  - Encapsulation

### ⚠️ Edge Cases

- Multiple calls → multiple contexts (important in recursion)
- Arrow functions → don’t have their own `this`

---

## 3️⃣ Key Differences (GEC vs FEC)

| Feature   | Global Execution Context | Function Execution Context |
| --------- | ------------------------ | -------------------------- |
| Created   | Once                     | Every function call        |
| `this`    | Global object            | Depends on call            |
| Memory    | Shared/global            | Isolated per function      |
| Variables | Global scope             | Local scope                |
| Lifetime  | Entire program           | Until function finishes    |

---

## 4️⃣ Call Stack Interaction 🔥

### ⚙️ How it works

- GEC is pushed first into stack
- Each function call → new FEC pushed
- When function completes → popped

### 💡 Why important

- Determines execution order
- Helps debug stack overflow, recursion

---

## 5️⃣ `this` Behavior (Critical Interview Topic)

### 🧠 In GEC:

```js id="0s8e7n"
console.log(this);
```

👉 `window` (browser)

---

### 🧠 In FEC:

```js id="g4v5c9"
function test() {
  console.log(this);
}
test();
```

👉 Non-strict → `window`
👉 Strict → `undefined`

💡 WHY:
`this` depends on **how function is called**, not where defined.

---

## 6️⃣ Hoisting Difference

### 🧠 In GEC:

- Variables hoisted globally
- `var` → attached to global object

### 🧠 In FEC:

- Variables hoisted locally
- Not accessible outside function

💡 Key Insight:
Hoisting happens **per execution context**

# 🔹 Example(s) with Code

---

## ✅ Example 1: GEC vs FEC Basic

```js id="h8w0rt"
var a = 10;

function foo() {
  var b = 20;
  console.log(a + b);
}

foo();
```

### 🔍 Execution:

1. GEC created:
   - `a = undefined`
   - `foo = function`

2. Execution:
   - `a = 10`

3. `foo()` → new FEC:
   - `b = undefined`

4. Execution:
   - `b = 20`
   - `a` found via scope chain

👉 Output: **30**

💡 WHY:
FEC accesses GEC via scope chain.

---

## ⚡ Example 2: Isolation of FEC

```js id="n5g1c9"
function test() {
  var x = 10;
}
test();

console.log(x);
```

👉 Output:

```id="0xtn3v"
ReferenceError
```

### 💡 WHY:

`x` exists only inside FEC → not in GEC.

---

## 🔥 Example 3: Tricky `this` Case

```js id="x6n9tp"
var name = "global";

function show() {
  console.log(this.name);
}

const obj = {
  name: "object",
  show: show,
};

show(); // ?
obj.show(); // ?
```

### 🔍 Execution:

1. `show()`:
   - Called globally → `this = window`
   - Output → "global"

2. `obj.show()`:
   - Called as method → `this = obj`
   - Output → "object"

👉 Output:

```id="6hl9hn"
global
object
```

💡 WHY:
FEC `this` depends on call-site.

---

## 🔥 Example 4: Multiple FEC (Recursion)

```js id="y9k4zc"
function count(n) {
  if (n === 0) return;
  console.log(n);
  count(n - 1);
}

count(3);
```

### 🔍 Execution:

- Each call creates new FEC:
  - count(3)
  - count(2)
  - count(1)

👉 Output:

```id="cw0g0f"
3
2
1
```

💡 WHY:
Each recursive call has separate execution context.

# 🔹 Real-world Use Cases

---

### 🌐 1. React Functional Components

- Each render = function execution context
- State/props exist in that FEC

---

### 🔁 2. API Calls / Async Functions

- Each callback creates new FEC
- Prevents variable conflicts across calls

---

### 📦 3. Utility Functions

- Encapsulate logic → avoid global pollution

---

### 🔐 4. Module Scope (ES Modules)

- Each module behaves like its own global context

---

# 🔹 When to use? (Why, Where, How)

---

### ✅ Use FEC for isolation

- Avoids global variable conflicts
- Keeps logic modular

---

### ✅ Use GEC carefully

- Only for truly global configs/constants

---

### ✅ Use understanding for debugging

- Helps trace variable lookup and call stack

---

# 🔹 When NOT to use

---

### ❌ Avoid too many globals (GEC abuse)

- Leads to collisions and bugs

---

### ❌ Avoid heavy recursion

- Too many FEC → stack overflow

---

# 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Thinking all variables are global

✅ Actually: Function creates separate context
💡 Because: Each FEC has its own memory

---

### ❌ Mistake 2: Misunderstanding `this`

✅ Actually: Depends on call-site
💡 Because: FEC determines binding

---

### ❌ Mistake 3: Ignoring scope chain

✅ Actually: FEC can access GEC
💡 Because: Lexical linking

---

### ❌ Mistake 4: Expecting variables to persist

✅ Actually: FEC destroyed after execution
💡 Because: Memory cleanup

# ✅ Advantages

---

### ✔️ Isolation

- FEC prevents variable conflicts → safer code.

---

### ✔️ Structured execution

- GEC + FEC organize program flow.

---

### ✔️ Enables advanced patterns

- Closures, recursion, modular design.

---

# ⚡ Pitfalls

---

### ⚠️ Global pollution

- Too many globals → unpredictable bugs.

---

### ⚠️ Stack overflow

- Too many nested FECs (recursion).

---

### ⚠️ `this` confusion

- Wrong binding → incorrect behavior.

---

# 🔹 Best Practices

---

✅ Minimize global variables
→ Keep GEC clean

✅ Use functions for modularity
→ Leverage FEC isolation

✅ Prefer arrow functions when needed
→ Predictable `this`

✅ Use strict mode
→ Avoid accidental globals

---

# 🔹 Senior-Level Insights

---

### 🧠 Performance

- Creating FEC has cost → excessive function calls impact performance.

---

### 🧠 Memory Behavior

- FEC removed after execution unless referenced (closures).

---

### 🧠 Scalability

- Clean separation (GEC vs FEC) → maintainable architecture.

---

### 🧠 Trade-offs

- More functions = better modularity BUT more contexts
- Globals = faster access BUT risky
