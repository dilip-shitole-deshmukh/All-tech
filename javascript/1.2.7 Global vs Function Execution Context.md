## 👉 Global vs Function Execution Context — Deep-Dive

This is a **🟡 Conceptual / Intermediate Topic** → interviewers expect **clear comparison + flow understanding (HOW it works internally)**.

---

# 🔹 Definition

- **Execution Context** is the environment where JavaScript code runs.
- There are mainly **two important types**:
  - 🌍 **Global Execution Context (GEC)**
  - ⚙️ **Function Execution Context (FEC)**

👉 Think:

- GEC = **Main entry point**
- FEC = **New environment for each function call**

---

# 🔹 Global Execution Context (GEC)

### ✅ Core Explanation

- Created **once when JS program starts**.
- It represents the **global scope** of your application.

### 🔑 Key Properties

- Creates **global object** (`window` in browser, `global` in Node)
- `this` → points to global object
- Stores all global variables & functions

👉 WHY:

- JS needs a base environment to start execution.

---

# 🔹 Function Execution Context (FEC)

### ✅ Core Explanation

- Created **every time a function is invoked**.
- Each function call gets its **own separate execution context**.

### 🔑 Key Properties

- Has its own:
  - Variables
  - Arguments
  - `this` value

- Gets destroyed after function execution completes

👉 WHY:

- Ensures **isolation between function calls** (no variable conflicts)

---

# 🔹 Key Differences (Most Important for Interviews)

| Feature  | 🌍 Global Execution Context | ⚙️ Function Execution Context     |
| -------- | --------------------------- | --------------------------------- |
| Creation | Created once                | Created on every function call    |
| Count    | Only one                    | Multiple (per function call)      |
| Scope    | Global scope                | Local (function scope)            |
| `this`   | Global object               | Depends on how function is called |
| Lifetime | Till program ends           | Till function finishes            |
| Memory   | Shared globally             | Isolated per call                 |

---

# 🔹 How They Work Together (Execution Flow)

### 💻 Example

```js
var x = 10;

function add() {
  var y = 20;
  console.log(x + y);
}

add();
```

---

## 🔍 Step-by-Step Flow

### 1️⃣ Global Execution Context (Creation Phase)

```js
x → undefined
add → function
```

---

### 2️⃣ Global Execution Context (Execution Phase)

```js
x = 10
add() → triggers Function Execution Context
```

---

### 3️⃣ Function Execution Context (Creation Phase)

```js
y → undefined
```

---

### 4️⃣ Function Execution Context (Execution Phase)

```js
y = 20
console.log(10 + 20) → 30
```

---

### 🔁 Call Stack Flow

```
[Global]
   ↓
[add()]
   ↓
(pop add after execution)
   ↓
[Global]
```

👉 FEC is pushed → executed → popped.

---

# 🔹 Important Concept: Scope Chain Connection

### ✅ Core Explanation

- FEC can access variables from GEC using **scope chain**.
- If variable not found locally → JS looks in outer (global) scope.

👉 WHY:

- Enables **lexical scoping + closures**

---

### 💻 Example

```js
var a = 10;

function test() {
  console.log(a);
}

test(); // 10
```

👉 `test` uses GEC variable via scope chain.

# 🔹 Tricky / Edge Cases

---

## ⚠️ Case 1: Multiple Function Calls = Multiple Contexts

```js
function test() {
  var x = 1;
  console.log(x);
}

test();
test();
```

👉 Each call creates **separate FEC**
👉 No shared memory between calls

---

## ⚠️ Case 2: `this` Behavior Difference

```js
function test() {
  console.log(this);
}

test(); // window (in browser)
```

👉 In FEC:

- `this` depends on **how function is called**, not where defined

---

## ⚠️ Case 3: Nested Functions

```js
function outer() {
  var a = 10;

  function inner() {
    console.log(a);
  }

  inner();
}

outer();
```

👉 `inner` FEC accesses `outer` FEC → via scope chain

# 🔹 Interview Q&A

---

### 1. What is Global Execution Context?

- It is the default execution context created when JS starts.
- It contains global variables, functions, and `this`.

---

### 2. What is Function Execution Context?

- Created whenever a function is invoked.
- Has its own variables, arguments, and `this`.

---

### 3. How many GECs can exist?

- Only one per program.
- It acts as the root of execution.

---

### 4. Can multiple FECs exist?

- Yes, each function call creates a new FEC.
- They are managed using the call stack.

---

### 5. What happens after function execution?

- Its execution context is removed from call stack.
- Memory is eligible for garbage collection.

---

### 6. How does FEC access global variables?

- Through scope chain (lexical environment).
- JS searches outer scopes if not found locally.

---

### 7. Difference between GEC and FEC?

- GEC is global and single.
- FEC is local and created per function call.

---

### 8. What is role of call stack?

- Manages execution contexts.
- Ensures proper execution order (LIFO).

---

# 🔹 Advantages

- ✔ Isolated execution → avoids variable conflicts
- ✔ Predictable execution flow
- ✔ Enables closures and modular code

---

# 🔹 Best Practices

- ✅ Minimize global variables (avoid GEC pollution)
- ✅ Use functions to isolate logic (FEC advantage)
- ✅ Prefer `let/const` over `var`
- ✅ Understand `this` binding clearly

---

# 🔥 Senior-Level Insight

- Excessive creation of FEC (deep recursion) → can cause **stack overflow**
- Closures retain FEC in memory → can lead to **memory leaks if not handled properly**
- Reducing dependency on GEC improves:
  - Maintainability
  - Testability
  - Scalability
