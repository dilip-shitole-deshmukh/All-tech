## 🧠 Promises (JavaScript)

> ⚠️ This is a **🟡 Conceptual / Core Async topic** → focus on **state, chaining, event loop behavior**

---

## 🔹 Definition

A **Promise** is an object that represents the **eventual completion (or failure) of an asynchronous operation**.

👉 In simple terms:

> “A promise is a placeholder for a value that will be available in the future”

💡 It solves problems of callbacks like:

- Callback hell
- Inversion of control

---

## 🔹 Core Explanation

---

## 🟢 1. Promise States (Very Important 🔥)

A Promise has **3 states**:

```text
Pending → Fulfilled (Resolved)
        → Rejected
```

🧠 Meaning:

- **Pending** → initial state
- **Fulfilled** → success
- **Rejected** → error

👉 Once settled → **state cannot change**

---

## 🔵 2. Creating a Promise

```js id="b9xrlx"
const promise = new Promise((resolve, reject) => {
  const success = true;

  if (success) {
    resolve("Data received");
  } else {
    reject("Error occurred");
  }
});
```

🧠 How it works:

- `resolve()` → success
- `reject()` → failure

---

## 🟡 3. Consuming a Promise (`then`, `catch`, `finally`)

```js id="0r6e76"
promise
  .then((data) => console.log(data))
  .catch((err) => console.log(err))
  .finally(() => console.log("Done"));
```

🧠 Flow:

1. `.then()` → runs on success
2. `.catch()` → runs on error
3. `.finally()` → always runs

---

## 🔁 4. Promise Chaining (Key Concept 🔥)

```js id="vc0ol6"
fetchData()
  .then((data) => process(data))
  .then((result) => console.log(result))
  .catch((err) => console.log(err));
```

🧠 WHY:

- Each `.then()` returns a new Promise
- Enables chaining instead of nesting

👉 Fixes callback hell

---

## 🔥 5. Async Nature (Event Loop Insight)

```js id="apjbmd"
console.log("Start");

Promise.resolve().then(() => {
  console.log("Promise");
});

console.log("End");
```

🧠 Output:

```text
Start
End
Promise
```

👉 WHY:

- Promise callbacks go to **Microtask Queue**
- Executed after current call stack

💡 Important interview point

## 🔹 Example(s) with Code

---

### ✅ Example 1: Basic Promise

```js id="f2wwqs"
const p = new Promise((resolve) => {
  setTimeout(() => resolve("Done"), 1000);
});

p.then((res) => console.log(res));
```

---

### ✅ Example 2: Chaining

```js id="18am8m"
Promise.resolve(2)
  .then((x) => x * 2)
  .then((x) => x + 1)
  .then(console.log); // 5
```

---

### ⚠️ Example 3: Error Handling

```js id="u1gjay"
Promise.reject("Error")
  .then(() => console.log("Success"))
  .catch((err) => console.log(err));
```

👉 Skips `.then()` → goes to `.catch()`

### ❌ Avoid

## 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Not returning Promise in chain

```js id="vy0b54"
.then(() => {
  fetchData(); // ❌ not returned
})
```

👉 Breaks chaining

---

### ❌ Mistake 2: Missing catch

👉 Unhandled promise rejection

---

### ❌ Mistake 3: Nested promises

👉 Same problem as callback hell

---

### ❌ Mistake 4: Assuming synchronous behavior

👉 Promises are async

## 🔹 Senior-Level Insights 🚀

---

### ⚡ Microtask Queue Priority

👉 Execution order:

```text
Call Stack → Microtasks (Promises) → Macrotasks (setTimeout)
```

👉 Promise runs before setTimeout

---

### 🧠 Promise Utilities

```js id="f8dm7l"
Promise.all([]);
Promise.race([]);
Promise.allSettled([]);
```

👉 Used for parallel async handling

---

### 🔄 Evolution

```text
Callbacks → Promises → Async/Await
```

👉 Modern code prefers async/await

---

### ⚖️ Trade-offs

| Feature     | Pros       | Cons                    |
| ----------- | ---------- | ----------------------- |
| Promise     | Structured | Chain complexity        |
| Async/Await | Readable   | Hidden promise behavior |
