## 🧠 Executing Tasks in Parallel (JavaScript)

> ⚠️ This is a **🟡 Conceptual + Performance-critical topic**
> 👉 Frequently asked to test **async optimization + Promise APIs + execution flow**

---

## 🔹 Definition

👉 Executing tasks in parallel means:

> **Running multiple async operations at the same time without waiting for each other**

💡 In simple terms:

```text
Start A, B, C together → wait for all results
```

---

## 🔹 Core Explanation

---

## 🟢 1. Parallel vs Sequential

---

### 🔹 Sequential (Slow ⏳)

```js
await task1();
await task2();
await task3();
```

👉 Each waits for previous → total time = sum of all

---

### 🔹 Parallel (Fast ⚡)

```js
await Promise.all([task1(), task2(), task3()]);
```

👉 All start together → total time = longest task

---

## 🟡 2. Why Parallel Execution Matters

👉 Improves:

- Performance 🚀
- User experience
- Resource utilization

💡 Example:

```text
Fetch user + posts + comments → run together
```

---

## 🔥 3. How Parallel Execution Works

👉 Key idea:

- Start all promises first
- Then wait for results

```js
const p1 = task1();
const p2 = task2();

await p1;
await p2;
```

👉 Both started in parallel

---

## 🚀 4. Methods for Parallel Execution

---

## ✅ Method 1: `Promise.all()` (Most Common ⭐)

```js
const results = await Promise.all([task1(), task2(), task3()]);

console.log(results);
```

### 🧠 Behavior:

- Runs all promises in parallel
- Resolves when all succeed
- Fails fast if any fails ❗

---

## ✅ Method 2: `Promise.allSettled()`

```js
const results = await Promise.allSettled([task1(), task2(), task3()]);
```

### 🧠 Behavior:

- Waits for all
- Returns success + failure info

---

## ✅ Method 3: `Promise.race()`

```js
await Promise.race([task1(), task2()]);
```

👉 Returns first completed (success/failure)

---

## ✅ Method 4: `Promise.any()`

```js
await Promise.any([task1(), task2()]);
```

👉 Returns first successful result

---

## 🔹 Example(s) with Code

---

### ✅ Example 1: Parallel API Calls

```js
async function fetchData() {
  const [user, posts] = await Promise.all([
    fetch("/user").then((res) => res.json()),
    fetch("/posts").then((res) => res.json()),
  ]);

  console.log(user, posts);
}
```

### 🧠 WHY parallel:

- Both requests start together
- Faster than sequential

---

### ⚠️ Tricky Example (Interview Favorite)

```js
async function wrong() {
  const a = await task1();
  const b = await task2();
}
```

👉 ❌ This is sequential

---

### ✅ Correct Parallel Version

```js
async function correct() {
  const p1 = task1();
  const p2 = task2();

  const a = await p1;
  const b = await p2;
}
```

👉 Both start at same time

## 🔹 When to Use / When NOT to Use

---

### ✅ Use Parallel

- Independent tasks
- No dependency between operations

---

### ❌ Avoid Parallel

- Tasks depend on each other

```text
Login → Token → Data
```

👉 Must be sequential

---

## 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Using `await` too early

```js
await task1(); // ❌ blocks
await task2();
```

---

### ❌ Mistake 2: Forgetting error handling

👉 `Promise.all` fails entirely if one fails

---

### ❌ Mistake 3: Overloading system

👉 Too many parallel calls

---

### ❌ Mistake 4: Misunderstanding parallel vs concurrent

👉 JS is single-threaded → uses concurrency, not true parallel CPU execution

---

## 🔹 Interview Q&A

---

### ❓1. How to execute tasks in parallel?

Using `Promise.all`

---

### ❓2. Why faster than sequential?

Tasks run simultaneously

---

### ❓3. When not to use parallel?

When tasks depend on each other

---

### ❓4. What happens if one promise fails in Promise.all?

Entire promise rejects

---

### ❓5. Difference: all vs allSettled?

all → fails fast
allSettled → waits for all

---

### ❓6. How to start promises in parallel manually?

Store promises before awaiting

---

### ❓7. Is JS truly parallel?

No, it's concurrent (single-threaded)

## 🔹 Advantages / Pitfalls

---

### ✅ Advantages

- Better UX

---

### ❌ Pitfalls

- Error handling complexity

## 🔹 Best Practices

---

✔ Use `Promise.all` for independent tasks
✔ Use `allSettled` for partial failures
✔ Avoid unnecessary sequential `await`
✔ Limit parallelism if needed

---

## 🔹 Senior-Level Insights 🚀

---

### ⚡ Controlled Parallelism (Important)

👉 Avoid:

```js
Promise.all(1000 requests) // ❌ overload
```

👉 Use batching:

```text
Run 5 at a time → next 5
```

---

### 🧠 Concurrency vs Parallelism

| Concept     | JS Behavior           |
| ----------- | --------------------- |
| Parallel    | Multi-core execution  |
| Concurrency | Event loop scheduling |

👉 JS uses concurrency

---

### ⚖️ Trade-offs

| Approach   | Pros        | Cons         |
| ---------- | ----------- | ------------ |
| Sequential | Predictable | Slow         |
| Parallel   | Fast        | Complex      |
| Batched    | Balanced    | Slight delay |

---
