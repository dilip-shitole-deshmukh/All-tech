## 🧠 Execute Promises in Sequence

> ⚠️ This is a **🟡 Conceptual / Practical Async topic**
> 👉 Frequently asked to test **async flow control + understanding of promises**

---

## 🔹 Definition

Executing promises **in sequence** means:
👉 Each promise starts **only after the previous one is resolved**

💡 In simple terms:

> “Wait for Task A → then run Task B → then Task C”

---

## 🔹 Core Explanation

---

## 🟢 1. Sequential vs Parallel Execution

### 🔹 Sequential

```text
Task A → Task B → Task C
```

👉 Next task waits for previous
👉 Slower but ordered

---

### 🔹 Parallel

```text
Task A
Task B   → run together
Task C
```

👉 Faster but no strict order

---

## 🟡 2. Why Sequential Execution is Needed

👉 Required when:

- Output of one task is input for next
- Order matters (e.g., API chaining)
- Avoid race conditions

💡 Example:

```text
Login → Get Token → Fetch User Data
```

---

## 🔥 3. How to Execute Promises in Sequence

---

## ✅ Method 1: Using `then()` chaining

```js
function task1() {
  return Promise.resolve("Task 1");
}

function task2() {
  return Promise.resolve("Task 2");
}

function task3() {
  return Promise.resolve("Task 3");
}

task1()
  .then((res1) => {
    console.log(res1);
    return task2();
  })
  .then((res2) => {
    console.log(res2);
    return task3();
  })
  .then((res3) => {
    console.log(res3);
  });
```

### 🧠 Execution Flow:

1. task1 resolves
2. task2 starts only after task1
3. task3 starts after task2

👉 Ensures strict order

---

## ✅ Method 2: Using `async/await` (Preferred ⭐)

```js
async function runTasks() {
  const res1 = await task1();
  console.log(res1);

  const res2 = await task2();
  console.log(res2);

  const res3 = await task3();
  console.log(res3);
}

runTasks();
```

### 🧠 WHY this works:

- `await` pauses execution until promise resolves
- Code looks synchronous but runs asynchronously

💡 Clean and readable → best practice

---

## ✅ Method 3: Using `for...of` (for dynamic arrays)

```js
const tasks = [task1, task2, task3];

async function runSequential() {
  for (const task of tasks) {
    const result = await task();
    console.log(result);
  }
}

runSequential();
```

### 🧠 Why important:

- Works for dynamic list of promises
- Avoids complex chaining

---

## ⚠️ Tricky Example (Interview Favorite)

```js
const tasks = [task1, task2, task3];

tasks.forEach(async (task) => {
  const result = await task();
  console.log(result);
});
```

### ❌ Output Issue:

👉 Runs in parallel, NOT sequential

💡 WHY:

- `forEach` doesn’t wait for async functions

---

## 🔹 When to Use / When NOT to Use

---

### ✅ Use Sequential

- Dependent tasks
- Order matters
- Data transformation pipelines

---

### ❌ Avoid Sequential

- Independent tasks

👉 Use:

```js
await Promise.all([task1(), task2()]);
```

---

## 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Using `forEach` with async

👉 Doesn’t wait → breaks sequence

---

### ❌ Mistake 2: Not returning promise in `.then()`

```js
.then(() => task2()) // ✅ correct
.then(() => { task2(); }) // ❌ wrong
```

---

### ❌ Mistake 3: Overusing sequential

👉 Causes performance issues

---

### ❌ Mistake 4: Mixing async patterns incorrectly

👉 Leads to confusing flow

---

## 🔹 Interview Q&A

---

### ❓1. How to run promises sequentially?

Using `.then()` chaining or `async/await`

---

### ❓2. Which is better?

`async/await` → cleaner and readable

---

### ❓3. Why not use `forEach`?

It doesn’t wait for async operations

---

### ❓4. Sequential vs parallel?

Sequential = ordered, slower
Parallel = faster, unordered

---

### ❓5. When to use Promise.all?

When tasks are independent

---

### ❓6. What does `await` do?

Pauses execution until promise resolves

---

### ❓7. Can async/await run in parallel?

Yes (if not awaited sequentially)

---

## 🔹 Advantages / Pitfalls

---

### ✅ Advantages

- Predictable execution
- Easier debugging
- Maintains order

---

### ❌ Pitfalls

- Slower performance
- Blocking logical flow unnecessarily

---

## 🔹 Best Practices

---

✔ Prefer `async/await`
✔ Use `for...of` for loops
✔ Use `Promise.all` when possible
✔ Always handle errors (`try/catch`)

---

## 🔹 Senior-Level Insights 🚀

---

### ⚡ Performance Optimization

👉 Bad (Sequential unnecessarily):

```js
await task1();
await task2();
```

👉 Good (Parallel):

```js
await Promise.all([task1(), task2()]);
```

---

### 🧠 Controlled Concurrency (Advanced)

👉 Sometimes you need:

- Not fully sequential
- Not fully parallel

💡 Use batching:

```text
Run 3 at a time → then next 3
```

---

### ⚖️ Trade-off Thinking

| Approach   | Use Case              |
| ---------- | --------------------- |
| Sequential | Dependent tasks       |
| Parallel   | Independent tasks     |
| Hybrid     | Large data processing |

---
