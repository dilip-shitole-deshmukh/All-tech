## 🧠 Template Literals (JavaScript)

---

## 🔹 Definition

Template Literals are **string literals enclosed in backticks (`)** that allow:

- Embedded expressions (`${}`)
- Multi-line strings
- Advanced string formatting

👉 In simple terms:

> “A modern and powerful way to write dynamic strings”

---

## 🔹 Core Explanation

---

## 🟢 1. Basic Syntax

```js
const name = "Dilip";

const msg = `Hello ${name}`;
```

🧠 Output:

```text
Hello Dilip
```

👉 WHY:

- `${}` evaluates JavaScript expressions inside string

---

## 🔵 2. Expression Interpolation

```js
const a = 5;
const b = 10;

console.log(`Sum is ${a + b}`);
```

🧠 Output:

```text
Sum is 15
```

👉 Inside `${}`:

- Any JS expression works
- Functions, calculations, conditions

---

## 🟡 3. Multi-line Strings (Big Advantage 🔥)

```js
const text = `Line 1
Line 2
Line 3`;
```

👉 No need for `\n`

💡 Old way:

```js
"Line1\nLine2";
```

---

## 🧠 4. Function Calls Inside Template

```js
function greet(name) {
  return `Hi ${name}`;
}

console.log(`Message: ${greet("JS")}`);
```

👉 Output:

```text
Message: Hi JS
```

---

## 🔁 5. Nested Templates

```js
const user = "Dilip";

const msg = `Hello ${`Mr. ${user}`}`;
```

👉 Output:

```text
Hello Mr. Dilip
```

---

## 🔥 6. Tagged Template Literals (Advanced)

```js
function tag(strings, value) {
  return strings[0] + value.toUpperCase();
}

const name = "dilip";

console.log(tag`Hello ${name}`);
```

🧠 Output:

```text
Hello DILIP
```

👉 WHY:

- Template is passed as:
  - array of strings
  - values separately

💡 Used for:

- Sanitization
- Styling (e.g., styled-components)

---

## 🔹 Example(s) with Code

---

### ✅ Example 1: String Formatting

```js
const user = "Dilip";
const age = 25;

console.log(`Name: ${user}, Age: ${age}`);
```

---

### ✅ Example 2: Conditional Logic

```js
const isAdmin = true;

console.log(`Role: ${isAdmin ? "Admin" : "User"}`);
```

---

### ✅ Example 3: HTML Template (Frontend 🔥)

```js
const name = "Dilip";

const html = `
  <div>
    <h1>${name}</h1>
  </div>
`;
```

👉 Used heavily in UI rendering

## 🔹 When to Use / When NOT to Use

---

### ✅ Use Template Literals

- Dynamic strings
- Multi-line content
- Readable formatting

---

### ❌ Avoid

- Over-nesting templates
- Complex logic inside `${}`

---

## 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Using quotes instead of backticks

```js
"Hello ${name}" ❌
```

👉 Won’t interpolate

---

### ❌ Mistake 2: Overloading expressions

```js
`${a + b + c + d}` ❌ (hard to read)
```

---

### ❌ Mistake 3: HTML injection risk

👉 User input inside template → security issue

✅ Yes

## 🔹 Advantages / Pitfalls

---

### ✅ Advantages

- Cleaner syntax
- Easy dynamic strings
- Multi-line support

---

### ❌ Pitfalls

- Can reduce readability if overused
- Security risks (XSS)
- Debugging complex templates

---

## 🔹 Best Practices

---

✔ Use backticks for dynamic strings
✔ Keep expressions simple
✔ Avoid nesting too much
✔ Sanitize user input
✔ Use tagged templates when needed
