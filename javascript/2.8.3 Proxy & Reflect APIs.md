## 👉 Proxy & Reflect APIs (JavaScript)

---

## 🔹 Definition

### 🕵️ Proxy

👉 A **Proxy** is an object that wraps another object and lets you **intercept and customize operations** like:

- property access (`get`)
- assignment (`set`)
- function calls, etc.

📌 Simple:

> “Proxy = middleman that controls how an object is accessed.”

---

### 🪞 Reflect

👉 **Reflect** is a built-in object that provides **default behavior for object operations** (get, set, delete, etc.).

📌 Simple:

> “Reflect = safe, standard way to perform object operations (often used inside Proxy).”

---

## 🔹 Core Explanation

### 🧠 1. Why Proxy Exists

- Normally, JS objects behave directly (no interception).
- Proxy allows you to **hook into internal operations**.

💡 Use cases:

- Validation
- Logging
- Reactivity (Vue 3 uses Proxy internally)

---

### ⚙️ 2. Basic Proxy Syntax

```js id="proxy-basic"
const proxy = new Proxy(target, handler);
```

- **target** → original object
- **handler** → object with traps (interceptors)

---

### 🔍 3. Common Proxy Traps

| Trap             | Purpose         |
| ---------------- | --------------- |
| `get`            | Access property |
| `set`            | Assign value    |
| `has`            | `in` operator   |
| `deleteProperty` | Delete property |
| `apply`          | Function calls  |

---

### 🧩 4. Example: Intercepting `get`

```js id="proxy-get"
const user = { name: "Dilip" };

const proxy = new Proxy(user, {
  get(target, prop) {
    console.log(`Accessing ${prop}`);
    return target[prop];
  },
});

console.log(proxy.name);
```

🧩 Output:

- Logs: `"Accessing name"`
- Returns `"Dilip"`

💡 Proxy intercepts before actual access

---

### 🛠️ 5. Example: Intercepting `set`

```js id="proxy-set"
const proxy = new Proxy(
  {},
  {
    set(target, prop, value) {
      if (typeof value !== "number") {
        throw new Error("Only numbers allowed");
      }
      target[prop] = value;
      return true;
    },
  },
);

proxy.age = 25; // ✅
proxy.age = "25"; // ❌ error
```

💡 Useful for validation

---

## 🔹 Reflect API (Very Important with Proxy)

### 🪞 6. Why Reflect is Used

- Provides **default behavior** inside Proxy
- Avoids breaking standard JS behavior

---

### 🔄 Example: Proxy + Reflect

```js id="proxy-reflect"
const user = { name: "Dilip" };

const proxy = new Proxy(user, {
  get(target, prop, receiver) {
    console.log(`Getting ${prop}`);
    return Reflect.get(target, prop, receiver);
  },
});
```

💡 WHY use Reflect:

- Ensures correct behavior (especially with inheritance, getters)

---

### ⚠️ Without Reflect (Problem)

```js id="no-reflect"
get(target, prop) {
  return target[prop]; // ❌ may break `this` binding
}
```

👉 Reflect handles edge cases properly

---

## 🔹 Example(s) with Code

### ✅ Example 1: Default Value Handler

```js id="default-value"
const proxy = new Proxy(
  {},
  {
    get(target, prop) {
      return prop in target ? target[prop] : "Not Found";
    },
  },
);

console.log(proxy.name); // "Not Found"
```

---

### ⚠️ Example 2: Logging + Reflect

```js id="logging-proxy"
const obj = { a: 10 };

const proxy = new Proxy(obj, {
  get(target, prop) {
    console.log(`Reading ${prop}`);
    return Reflect.get(target, prop);
  },
  set(target, prop, value) {
    console.log(`Setting ${prop}`);
    return Reflect.set(target, prop, value);
  },
});

proxy.a;
proxy.a = 20;
```

---

### 🧩 Example 3: Function Proxy

```js id="function-proxy"
function sum(a, b) {
  return a + b;
}

const proxy = new Proxy(sum, {
  apply(target, thisArg, args) {
    console.log("Function called");
    return Reflect.apply(target, thisArg, args);
  },
});

proxy(2, 3); // logs + result
```

### ✅ Use When:

- Building frameworks/libraries

### ❌ Avoid When:

- Simple use case (overkill)

## 🔹 Common Mistakes / Traps

### ❌ Mistake 1: Not returning `true` in set

```js id="set-error"
set(target, prop, value) {
  target[prop] = value;
  // ❌ missing return true
}
```

👉 Causes TypeError in strict mode

---

### ❌ Mistake 2: Ignoring Reflect

👉 Leads to broken behavior (especially with getters/setters)

---

### ❌ Mistake 3: Proxying deeply nested objects

👉 Proxy is shallow by default

---

### ❌ Mistake 4: Performance misuse

👉 Proxy adds overhead → avoid in hot paths

## 🔹 Interview Q&A

### ❓1. What is Proxy?

👉 An object that intercepts operations on another object.

---

### ❓2. What is Reflect?

👉 A built-in API to perform object operations safely and consistently.

---

### ❓3. Why use Reflect with Proxy?

👉 To maintain default behavior and handle edge cases correctly.

---

### ❓4. What are traps?

👉 Methods inside handler that intercept operations (`get`, `set`, etc.).

---

### ❓5. Is Proxy deep or shallow?

👉 Shallow — nested objects are not automatically proxied.

---

### ❓6. Can Proxy intercept function calls?

👉 Yes, using `apply` trap.

---

### ❓7. Real-world example?

👉 Vue 3 reactivity system.

---

### ❓8. Performance impact?

👉 Slight overhead — avoid excessive usage in tight loops.

## 🔹 Advantages / Pitfalls

### ✅ Advantages

- Powerful abstraction
- Enables reactivity
- Custom behavior control
- Useful in frameworks

---

### ⚠️ Pitfalls

- Debugging complexity
- Performance overhead
- Not supported in very old browsers

---

## 🔹 Best Practices

✔ Use Reflect inside Proxy
✔ Keep handlers simple
✔ Avoid deep nesting without control
✔ Use only where necessary
✔ Test edge cases thoroughly

---

## 🔹 Senior-Level Insights

### ⚡ 1. Proxy in Framework Design

- Vue 3 uses Proxy for reactivity instead of `Object.defineProperty`
- Enables better tracking of dynamic properties

---

### ⚡ 2. Performance Trade-off

- Proxy introduces overhead per operation
- Avoid using in large loops or critical rendering paths

---

### ⚡ 3. Deep Proxy Strategy

```js id="deep-proxy"
function deepProxy(obj) {
  return new Proxy(obj, {
    get(target, prop) {
      const value = target[prop];
      return typeof value === "object" && value !== null
        ? deepProxy(value)
        : value;
    },
  });
}
```

💡 Needed for nested reactivity

---

### ⚡ 4. Security / Sandbox Use

- Proxy can restrict or monitor object usage
- Useful in sandboxed environments

---

👉 **Proxy** = intercept object operations

✔ Used for validation, logging, reactivity

💡 Golden Rule:

> “Use Proxy to control behavior, Reflect to preserve it.”
