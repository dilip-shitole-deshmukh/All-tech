## 👉 `this`, `call`, `apply`, `bind` — Deep-Dive (Interview Ready)

This is a **🟡 Conceptual / Intermediate Topic** → interviewers expect **clear rules of `this` + how to control it using call/apply/bind + tricky cases**.

---

# 🔹 Definition

- **`this`** → refers to the object that is executing the function (decided at call-time).
- **`call`, `apply`, `bind`** → methods used to **explicitly control the value of `this`**.

👉 Simple interview line:
**“`this` depends on how a function is called, and call/apply/bind allow us to manually control it.”**

---

# 🔹 Core Understanding of `this`

---

## 🔸 Key Rule (Golden Rule)

👉 **Call-site decides `this`**

- `obj.method()` → `this = obj`
- `fn()` → `this = window/undefined`
- `new Fn()` → `this = new object`
- Arrow → inherits `this`

---

# 🔹 `call`, `apply`, `bind` — Core Idea

👉 All three are used to **set `this` manually**

---

## 🔸 1. `call()`

### ✅ Explanation

- Invokes function **immediately**
- Arguments are passed **individually**

### 💻 Example

```js id="d7m6l9"
function greet(city) {
  console.log(this.name, city);
}

const user = { name: "Dilip" };

greet.call(user, "Pune"); // Dilip Pune
```

---

## 🔸 2. `apply()`

### ✅ Explanation

- Same as `call`, but arguments are passed as an **array**

### 💻 Example

```js id="x4m4ko"
greet.apply(user, ["Mumbai"]); // Dilip Mumbai
```

👉 Difference from `call` = argument format

---

## 🔸 3. `bind()`

### ✅ Explanation

- Does NOT execute immediately
- Returns a **new function with bound `this`**

### 💻 Example

```js id="tppv9k"
const fn = greet.bind(user, "Delhi");
fn(); // Dilip Delhi
```

👉 Useful for callbacks

---

# 🔹 Quick Comparison (Important Table)

| Feature   | call       | apply     | bind         |
| --------- | ---------- | --------- | ------------ |
| Execution | Immediate  | Immediate | Delayed      |
| Arguments | Individual | Array     | Individual   |
| Return    | Result     | Result    | New function |

---

# 🔹 Deep Understanding (WHY Needed)

👉 Problem:

```js id="3e0q84"
const obj = {
  name: "Dilip",
  getName() {
    console.log(this.name);
  },
};

const fn = obj.getName;
fn(); // undefined ❌
```

👉 WHY?

- Function lost its context → `this` is no longer `obj`

---

### ✅ Fix using `bind`

```js id="q9qgqc"
const fn = obj.getName.bind(obj);
fn(); // Dilip ✅
```

---

# 🔹 Tricky / Edge Cases

---

## ⚠️ Case 1: Arrow Function + bind

```js id="ixf4y8"
const obj = {
  name: "Dilip",
  getName: () => {
    console.log(this.name);
  },
};

obj.getName.call(obj); // undefined ❌
```

👉 WHY?

- Arrow function ignores call/apply/bind
- Uses lexical `this`

---

## ⚠️ Case 2: Partial Application (bind)

```js id="pf7v4n"
function multiply(a, b) {
  return a * b;
}

const double = multiply.bind(null, 2);
console.log(double(5)); // 10
```

👉 `bind` can preset arguments

---

## ⚠️ Case 3: Borrowing Methods

```js id="bb8l0q"
const user1 = { name: "A" };
const user2 = { name: "B" };

function greet() {
  console.log(this.name);
}

greet.call(user1); // A
greet.call(user2); // B
```

👉 Same function reused with different objects

---

## ⚠️ Case 4: setTimeout Problem

```js id="lcm3nr"
const obj = {
  name: "Dilip",
  getName() {
    setTimeout(function () {
      console.log(this.name);
    }, 1000);
  },
};

obj.getName(); // undefined ❌
```

👉 Fix:

```js id="bz8tvt"
setTimeout(() => console.log(this.name), 1000);
```

# 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Confusing call vs bind

👉 `call` executes immediately
👉 `bind` returns function

---

### ❌ Mistake 2: Using arrow functions incorrectly

👉 Arrow ignores `call/apply/bind`

---

### ❌ Mistake 3: Losing `this` in callbacks

👉 Happens frequently in async code

# 🔹 Interview Q&A

---

### 1. What is `this`?

- Refers to object executing function.
- Determined by call-site.

---

### 2. Difference between call and apply?

- Both execute immediately.
- call → arguments individually
- apply → arguments as array

---

### 3. What is bind?

- Returns new function with fixed `this`.
- Does not execute immediately.

---

### 4. When to use bind?

- When passing functions as callbacks.
- To preserve context.

---

### 5. Can arrow function use bind?

- ❌ No
- Arrow functions ignore binding methods.

---

### 6. What is method borrowing?

- Using call/apply to reuse functions across objects.

---

### 7. Why `this` is undefined in callbacks?

- Function loses calling object.
- Needs binding or arrow function.

---

### 8. Which is faster: call or apply?

- Almost same.
- Modern JS engines optimize both.

---

# 🔹 Advantages

- ✔ Flexible function reuse
- ✔ Explicit control over execution context
- ✔ Helps avoid bugs with `this`

---

# 🔹 Best Practices

- ✅ Use `bind` for callbacks
- ✅ Use arrow functions for simpler `this` handling
- ✅ Prefer `call` over `apply` (more common)
- ❌ Avoid unnecessary binding

---

# 🔥 Senior-Level Insight

- Overusing `bind` can:
  - Create extra functions → memory overhead
  - Reduce readability

👉 Modern approach:

- Prefer arrow functions
- Avoid dynamic `this` when possible
