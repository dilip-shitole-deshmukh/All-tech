## 🧠 Retry a Promise N Times on Failure

> ⚠️ This is a **🟡 Conceptual + Real-world Async pattern**
> 👉 Very common in interviews → tests **error handling + resilience + async control**

---

## 🔹 Definition

👉 Retrying a promise means:

> **If a promise fails, try executing it again up to N times before giving up**

💡 In simple terms:

```text
Try → Fail → Retry → Fail → Retry → Success (or final failure)
```

---

## 🔹 Core Explanation

---

## 🟢 1. Why Retry is Needed

👉 Real-world systems are unreliable:

- Network failures
- Temporary server issues
- Timeout errors

💡 Instead of failing immediately:

> Retry improves success chances

---

## 🟡 2. Key Concepts Behind Retry

---

### 🔹 Controlled Attempts

- Limit retries (avoid infinite loops)

---

### 🔹 Delay Between Retries (optional)

- Prevent spamming server

---

### 🔹 Error Handling

- Stop retrying on certain errors (e.g., 400 vs 500)

---

## 🔥 3. Basic Retry Implementation (Recursive)

```js
function retryPromise(fn, retries) {
  return fn().catch((err) => {
    if (retries === 0) {
      throw err;
    }
    console.log("Retrying...", retries);
    return retryPromise(fn, retries - 1);
  });
}
```

### 🧠 How it works:

1. Call function `fn()`
2. If success → return result
3. If fail → retry until retries = 0

---

## ✅ Example Usage

```js
let attempt = 0;

function unstableAPI() {
  return new Promise((resolve, reject) => {
    attempt++;
    if (attempt < 3) {
      reject("Failed attempt " + attempt);
    } else {
      resolve("Success on attempt " + attempt);
    }
  });
}

retryPromise(unstableAPI, 3).then(console.log).catch(console.error);
```

### 🧠 Execution Flow:

```text
Attempt 1 → Fail
Attempt 2 → Fail
Attempt 3 → Success ✅
```

---

## 🚀 4. Retry Using Async/Await (Cleaner ⭐)

```js
async function retry(fn, retries) {
  for (let i = 0; i <= retries; i++) {
    try {
      return await fn();
    } catch (err) {
      if (i === retries) throw err;
      console.log(`Retry ${i + 1}`);
    }
  }
}
```

👉 More readable and interview-friendly

---

## ⚡ 5. Retry with Delay (Real-world)

```js
function wait(ms) {
  return new Promise((res) => setTimeout(res, ms));
}

async function retryWithDelay(fn, retries, delay) {
  for (let i = 0; i <= retries; i++) {
    try {
      return await fn();
    } catch (err) {
      if (i === retries) throw err;
      console.log(`Retry after ${delay}ms`);
      await wait(delay);
    }
  }
}
```

## 🔥 Tricky Edge Case (Interview Favorite)


💡 Many developers think:
❌ Only 2 attempts
✅ Actually 3 attempts

## 🔹 When to Use / When NOT to Use

---

### ✅ Use Retry

- Temporary failures (5xx errors)
- Network issues

---

### ❌ Avoid Retry

- Client errors (400, 401)
- Validation failures

💡 Retry won't fix logic errors

---

## 🔹 Common Mistakes / Traps

---

### ❌ Mistake 1: Infinite retries

```js
while (true) {} // ❌ dangerous
```

---

### ❌ Mistake 2: Retrying all errors

👉 Some errors should fail immediately

---

### ❌ Mistake 3: No delay between retries

👉 Can overload server

---

### ❌ Mistake 4: Not handling rejection after retries

👉 Leads to silent failures

## 🔹 Senior-Level Insights 🚀

---

### ⚡ Exponential Backoff (Very Important)

```js
const delay = (base * 2) ^ attempt;
```

👉 Example:

```text
1st retry → 1s
2nd retry → 2s
3rd retry → 4s
```

💡 Prevents system overload

---

### 🧠 Idempotency Awareness

👉 Safe to retry:

- GET requests
- Idempotent APIs

👉 Dangerous:

- Payment APIs (duplicate charges)

---

### ⚖️ Trade-offs

| Factor       | Impact            |
| ------------ | ----------------- |
| More retries | Higher success    |
| More retries | Higher latency    |
| Delay        | Less load, slower |

---

### 🚀 Production Pattern

```js
retry(apiCall, 3).catch(showErrorToUser);
```

👉 Always fail gracefully after retries
