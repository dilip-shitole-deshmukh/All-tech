## 👉 New ES6 Methods (Interview Deep-Dive)

This is a **🟢 Basic / Direct Topic**, but slightly broader → so we’ll cover **important ES6 methods across Array, Object, String, and Number** in a **crisp but interview-ready way**.

---

# 🔹 Definition

- ES6 introduced several **built-in methods** to make working with arrays, objects, strings, and numbers **more expressive and less error-prone**.
- These methods reduce manual logic (loops, condition checks) and encourage **functional programming style**.

---

# 🔹 Core ES6 Methods (Most Asked)

---

## 🔸 1. `Array.from()`

### ✅ Core Explanation

- Converts **array-like or iterable objects** into real arrays.
- Useful when working with DOM collections or strings.

### 💻 Example

```js
const str = "hello";
const arr = Array.from(str);
console.log(arr); // ['h','e','l','l','o']
```

👉 WHY: Strings are iterable → converted into array.

---

## 🔸 2. `Array.of()`

### ✅ Core Explanation

- Creates an array from given arguments.
- Avoids confusion of `Array(3)` (which creates empty slots).

### 💻 Example

```js
Array.of(3); // [3]
Array(3); // [empty × 3]
```

👉 Important difference in interviews.

---

## 🔸 3. `find()` vs `findIndex()`

### ✅ Core Explanation

- `find()` → returns first matching element
- `findIndex()` → returns index of first match
- Stops iteration once condition is satisfied (efficient)

### 💻 Example

```js
const arr = [10, 20, 30];
arr.find((x) => x > 15); // 20
arr.findIndex((x) => x > 15); // 1
```

---

## 🔸 4. `includes()`

### ✅ Core Explanation

- Checks if value exists in array (returns true/false).
- Cleaner alternative to `indexOf()`.

### 💻 Example

```js
[1, 2, 3].includes(2); // true
```

👉 WHY better: `indexOf` returns -1 → less readable.

---

## 🔸 5. `Object.assign()`

### ✅ Core Explanation

- Copies properties from one or more objects into target object.
- Used for **shallow cloning and merging**.

### 💻 Example

```js
const obj1 = { a: 1 };
const obj2 = { b: 2 };
const result = Object.assign({}, obj1, obj2);
```

👉 Creates new object → avoids mutation (important in React).

---

## 🔸 6. `Object.keys()`, `Object.values()`, `Object.entries()`

### ✅ Core Explanation

- `keys()` → returns array of keys
- `values()` → returns values
- `entries()` → returns key-value pairs

### 💻 Example

```js
const user = { name: "Dilip", age: 25 };

Object.keys(user); // ['name','age']
Object.values(user); // ['Dilip',25]
Object.entries(user); // [['name','Dilip'],['age',25]]
```

---

## 🔸 7. `String.includes()`, `startsWith()`, `endsWith()`

### ✅ Core Explanation

- Modern string checking methods.
- More readable than older `indexOf`.

### 💻 Example

```js
const str = "JavaScript";

str.includes("Script"); // true
str.startsWith("Java"); // true
str.endsWith("Script"); // true
```

---

## 🔸 8. `Number.isNaN()` & `Number.isFinite()`

### ✅ Core Explanation

- `Number.isNaN()` → checks strictly for NaN (better than global `isNaN`)
- `Number.isFinite()` → checks if value is a finite number

### 💻 Example

```js
Number.isNaN(NaN); // true
Number.isNaN("abc"); // false ❗

isNaN("abc"); // true ❌ (confusing)
```

👉 WHY: global `isNaN` coerces values → unreliable.

---

## 🔸 9. `Math.trunc()`, `Math.sign()`

### ✅ Core Explanation

- `Math.trunc()` → removes decimal part
- `Math.sign()` → returns sign (-1, 0, 1)

### 💻 Example

```js
Math.trunc(4.9); // 4
Math.sign(-10); // -1
```

# 🔹 Real-world Use Cases

- 🔹 `find()` → search items in API response (users, products)
- 🔹 `includes()` → validation (check roles, permissions)
- 🔹 `Object.assign()` / spread → state updates in React
- 🔹 `entries()` → looping objects in UI rendering
- 🔹 `Array.from()` → convert NodeList → array (DOM operations)

# 🔹 Common Mistakes / Traps

### ❌ Mistake 1: Assuming `Object.assign()` does deep copy

```js
const obj = { a: { b: 1 } };
const copy = Object.assign({}, obj);
copy.a.b = 2;
```

👉 Original object also changes → shallow copy only.

---

### ❌ Mistake 2: Confusing `find` vs `filter`

- `find()` → returns single element
- `filter()` → returns array

---

### ❌ Mistake 3: Using `isNaN()` incorrectly

👉 It converts values → leads to bugs.

# 🔹 Interview Q&A

### 1. Difference between `Array.from()` and `Array.of()`?

- `Array.from()` converts iterable/array-like objects into arrays.
- `Array.of()` creates array from given arguments.

---

### 2. Why `includes()` over `indexOf()`?

- `includes()` returns boolean → more readable.
- Avoids checking `!== -1`.

---

### 3. What is difference between `find()` and `filter()`?

- `find()` returns first matching element.
- `filter()` returns all matching elements in array.

---

### 4. Is `Object.assign()` deep copy?

- ❌ No, it performs shallow copy.
- Nested objects still share reference.

---

### 5. Why `Number.isNaN()` is preferred?

- It checks strictly for NaN without type coercion.
- Prevents false positives.

---

### 6. What does `Object.entries()` return?

- Returns array of `[key, value]` pairs.
- Useful for iteration with loops.

---

### 7. Can `Array.from()` work on objects?

- Only on iterable or array-like objects (like NodeList, string).
- Plain objects are not iterable.

# 🔹 Best Practices

- ✅ Prefer `includes()` over `indexOf()`
- ✅ Use `find()` for single match, `filter()` for multiple
- ✅ Use `Object.assign()` or spread for immutability
- ✅ Avoid global `isNaN()`
- ✅ Use `Array.from()` for DOM collections
